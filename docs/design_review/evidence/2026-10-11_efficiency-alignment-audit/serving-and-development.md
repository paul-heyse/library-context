## Material contract clarifications

### Frozen eligibility is more than a positive membership cache

The captured concurrent serving changes require a current-context witness for derived rows and
refuse an old eligible row if its current relation-bearing dependencies do not qualify in the
selected view. Caches introduced by O-F35/O-F36 must key the complete selected view/epoch,
operation, relation-qualified dependency set and relevant context/absence premise. They cannot
carry a successful answer from an earlier selection or infer eligibility from any one selected
node. The overlay is **Implemented/static**, with external acceptance still pending; it is
neither an audit implementation nor fresh Tested evidence. Preserve its behavior in a rewrite.

### Search reorder has a legitimate losing case

Let a shared vector cohort contain many retained releases while the requested pin admits only a
small subset. Today exact scoring follows the subset. A proposal that scores the entire cohort
before filtering trades fewer membership/hydration operations for potentially many more score
operations. This is a structural counterexample, not a latency estimate. Exact scoring order and
eligibility-before-cap can be semantically compatible while total work differs. The plan needs a
route-selection decision or evidence that the workload justifies the trade, not an unconditional
efficiency promise. Preserve the existing per-tier distinct target/context stop rule.

### Sorting needs both equivalence and bounded work state

The existing sorter deliberately has two live heads and bounded transient decoding. Its extra
disk passes are real. Replacing it with unbounded all-runs merge would transfer the problem into
open descriptors and live memory. A finite fan-in chosen from available reservation, row bounds
and descriptor admission retains the intended refusal contract. DataFusion may supply the sort
while a streaming adjacent-key validator supplies this repository's equality/conflict rule;
that composition has to be compared at the adapter boundary rather than dismissed categorically.

### Evidence cannot be moved across time without changing its claim

The test artifact capture intentionally calls its digest an observation at completion, and does
not claim that the runner executed those bytes. Retiring that observation may be sensible, but
hashing a replaced path during a later export is a different observation. Revised O-RC15 must
state which evidence consumers survive and what they can establish. The same distinction applies
to immutable executable identity and mutable pathname identity for the stable service.

## Library evidence and limits

- Context7 was used first for nextest, Cargo and tokenizers documentation on 2026-10-11.
  [Nextest binary metadata](https://nexte.st/rustdoc/nextest_metadata/struct.RustBinaryId.html)
  and [machine-readable list output](https://nexte.st/docs/machine-readable/list) distinguish
  target kinds. The repository already records Cargo `target` metadata in completion evidence;
  no new nextest setup-script or experimental recording feature is assumed.
- [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html) and
  [cargo check](https://doc.rust-lang.org/cargo/commands/cargo-check.html) support the profile
  versus check distinction. These are current documentation, not proof of an exact compiler
  command on this checkout. Effective codegen-unit settings were not executed or asserted.
- Context7's tokenizers results included newer main-branch serialization contracts, which were
  **not transferred**. Exact local registry source for `tokenizers-0.23.2`,
  `src/tokenizer/mod.rs:468–476`, implements `from_file` by reading a string and `from_bytes`
  by deserializing the provided slice. The project already calls the latter in `load`.
- No SurrealDB plan or DataFusion replacement probe was executed here. Server execution strategy,
  actual compile/link cost, peak live memory, fairness, and ranking latency remain unmeasured.

## Source-search interpretation

The missing CLI signal registration is a scoped source result plus a traced call/drain path,
not proof that every possible launcher lacks cancellation. The member-selection predicates are
read directly but do not establish an optimizer plan. Source package closures do not establish
binary size. The historical probe outputs P1–P9 remain owned by the original review, with their
stated host/cache/run limits; the audit did not rerun them.
