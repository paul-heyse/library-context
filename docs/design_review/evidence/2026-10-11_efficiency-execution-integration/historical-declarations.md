## Role and set semantics

Original `Spec/v2` sorted/deduplicated SourceSnapshot identity values before hashing. Nevertheless, Workspace::producer_inputs_async enumerates actual declaration roles; CompletedInputs::ordered_bindings sorts by role; snapshots() emits those roles; ProducerOutput::contribution_spec stores that Vec. BTreeMap backing did not reorder the serialized role vector. The nine normalization stage declarations themselves intentionally sort/dedup relation names; provider declarations preserve their own original order. Converter verifies original set-hash identity independently, then validates actual stored Vec role order/cardinality and maps it role-for-role to the target ordered Spec/v3. Never recover roles from the old set hash or sort every old input Vec uniformly.

Actual sets/maps stay canonical sets: original binding sources are sorted/dedup by input ID; supplier roles are a BTreeMap; declared outputs are a BTreeSet; completed output roots are a BTreeMap. CapturedSources is a set keyed by SourceSnapshot.identity, unlike ordered Spec inputs. Stage input declaration order/cardinality and producer contract role order have separate target identities.
