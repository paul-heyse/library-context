# Agent execution: bounded implementation evidence

**Current consumer, 2026-10-14:** [Catalog coordinator §6](../../../plans/catalog-completion-plan_2026-10-14.md#6-sole-disposition-and-current-checkpoint)
owns T01–T04/P01 and I03 dispositions. This folder contains the source of the bounded inert
containment comparison; run-owned outputs remain in managed storage, not duplicated here.

`containment_probe.py` compares the installed transient user-service mechanism with the required
separate lifetimes. It creates only nonce-named inert units/processes, registers output ownership
before use, authenticates the exact unit before stopping it, and preserves an independently owned
sentinel until its own cleanup. It does not query or alter any native database/shared daemon.
Installed systemd255 is the contract; newer Context7 material is discovery only.

The candidate is eligible only if it preserves nested-session cleanup, separately owned daemons
and slow observer finalization. A common cgroup that kills those lifetimes is evidence against
that candidate, not authorization to add a general containment selector or repair unrelated units.
Actual commands/results and the selected mechanism belong to the coordinator, not a second ledger.

[Independent implementation assessment](independent-review.md) records the unchanged scoped
Accept judgment and its targeted final-source addendum. Native execution evidence is separately
owned by coordinator §6 and the run receipts. The single-group comparison selected explicit
delegated-owner composition; it establishes no production speed comparison.
