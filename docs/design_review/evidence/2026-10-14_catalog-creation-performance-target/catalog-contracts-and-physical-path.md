## Native effects share a write/conflict point

`crates/lctx-native/src/control/authorization.rs:230–278` distinguishes installation, open/frozen/terminal attempt and other effect owners. Open and frozen compiler effects map to the root attempt record. `owner_effect_plan:650–718` writes intent and payload in distinct guarded transactions. Both ordinary authorization and payload fencing touch the owner, select it `FOR UPDATE`, check generation/era/state/epoch and touch the attempt. `control/schema.surql:157–160` realizes `native_touch` as a write to the exact record's predicate revision. `native_incidence:162–168` additionally links relevant rows to their attempt/hold owners.

Consequently, otherwise independent effects in the same attempt share a source-visible write/conflict point. Frontend concurrency does not remove it. This is not an engine observation of lock wait, retry rate or timeout cause. A revised protocol would have to establish whether a narrower producing scope can own ordinary payload effects while global freeze/retirement/certification still fences all producers. Preserve ABA protection, exact generation/era/epoch, expected-object guards, idempotent effect identity, unknown outcome reconciliation and authenticated drainage. Deleting shared guards or simply raising admitted calls is not a complete alternative.

Existing bounded ingress, call registry and asynchronous bridge are strengths. Any recommendation must compose with them rather than adding an unrelated scheduler, writer cap or a second outcome authority.

## Admission and publication: distinguish reuse from independent checking

`crates/lctx-compiler-store/src/artifact.rs:1736–1848` freezes the workspace, obtains facts availability, executes semantic and frontier admission, prepares canonical content, executes graph admission, obtains original inventory, populates the manifest and assembles admitted physical content. `lctx-compiler-store/src/compiler.rs:4215` already retains owner-keyed canonical preparation and its scan lease. The current physical inventory handoff shares actual completed-owner state with client/pool and frozen-parent provenance; cold/data-only paths remain independent. These are existing corrections and preservation constraints, not missing mechanisms.

The meaningful review question is which final semantic properties were genuinely established over the exact same immutable inputs earlier, and which actual native, cross-relation, changed-output or foreign-input properties still require independent certification. A hash or cached Boolean is not sufficient evidence. Frozen admission is a real boundary and cannot simply be omitted.

`crates/lctx-publisher/src/lib.rs:105–138` creates publication, materializes references/search, then seals. `native_publication.rs:241–268` already batches references by 128. Finalization drains ordinary writers and validates final eligibility; an acknowledged publication marker precedes fallible cleanup (`281` onward). This is a true completion barrier.

There is a narrower reuse question in search preparation. `crates/lctx-native/src/derived_search.rs:2342–2357` constructs ordered expected rows, lowers and writes derived search, reconciles actual rows and materializes lexical statistics. That expected preparation is then dropped. `2362–2399` reconstructs it in `reconcile_search_owned`; `control/staging.rs:335` invokes that route during final publication. `Expected:1162–1232` owns seven bounded sorted/ordered row families and compares complete serialized actual rows to exact EOF, detecting missing/extra rows and draining transport. Retaining provenance-bound expected runs for a fresh final actual-state comparison could avoid repeated expectation derivation. It must not avoid that comparison. Cold/foreign input has no same-owner preparation premise and still needs independent derivation.

A revealing failure case mutates derived actual rows after preparation but before sealing: retained expectations must still detect the mutation. A revealing legitimate case changes encoder/projection/recipe or input identity: an old expected run must be ineligible. Any retained state must have a budget, exact dependencies and release after finalization/cancellation; no second durable truth store is proposed.
