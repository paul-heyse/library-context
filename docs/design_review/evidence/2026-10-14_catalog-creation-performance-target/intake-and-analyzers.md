## Contracts worth preserving

The intake distinguishes selected analysis roots from contextual imports. Roots are chosen by the model's admission operation, sorted by path, checked for source size and UTF-8 before Pyrefly receives root handles ([pyrefly_stage.rs](../../../../crates/cpg-extract/src/pyrefly_stage.rs), lines 126–140, 494–517). Configuration disables discovery heuristics, fixes Python/platform/search paths, skips interpreter queries, and binds normalized configuration, environment and lock identity into `AnalysisContext` (lines 347–405). A corpus gets its own root plus its linked frozen library as site-package context. Combining the sessions must preserve these distinct import meanings; equality of Python version is insufficient.

The same transaction provides retained AST/module text, Pysa symbols/calls, parameter answers and types. It starts with dependency `Require::Exports`, runs named roots at `Everything`, and promotes selected dependency modules later in that same transaction (lines 518–533, 637–668, 826–841, 916–1010, 1398–1440). This already avoids subprocess reports and a fresh typing session per query. Fork [Require](https://github.com/paul-heyse/pyrefly/blob/63cda076956013cd0bd1d0d05c785f747fe6adc0/pyrefly/lib/state/require.rs#L24) lines 24–75 explicitly retains AST/answers/answer traces only at `Everything`; simply lowering root requirements would remove evidence consumers need.

Latest Ruff is an independent syntax/context authority. `CanonicalSyntax` verifies captured content/length and parses once for the root's syntax, diagnostics and semantic-context passes ([ruff_context.rs](../../../../crates/cpg-extract/src/ruff_context.rs), lines 44–132). Its AST cannot be substituted by Pyrefly's older Ruff AST merely because ranges resemble each other. Typed `Spans`, source identity, native parameter answers and explicit partial/unavailable coverage preserve the join. Different observations must not become interchangeable just to save parsing. Separate visitors over one AST are not automatically duplicate semantic analysis.

Both profiles request Pyrefly plus latest Ruff, documents and deployment. Only Behavioral requests `ty_flow`; Catalog retains Flow `NotRequested` ([facts contracts](../../../../crates/lctx-model/src/domain/producer_contract/facts.rs), lines 264–277, 324–350, 377–462). Catalog speed must therefore be assessed on its own route; changes solely to ty-flow cannot be claimed as Catalog latency fixes.

Accepted output is bounded and drained. Stage writers flush typed batches, and `StageContext` rejects operations following cancellation/refusal ([bundle.rs](../../../../crates/cpg-extract/src/bundle.rs), lines 250–305, 341–355, 378–420). One `ProducerIngress` owns the cross-relation stream, retains a pending native acknowledgement, and waits for the preceding accepted unit when admitting the next ([workspace.rs](../../../../crates/cpg-core/src/workspace.rs), lines 2076–2158). This prevents an arbitrary unbounded sink backlog. Provider thread joining and accepted-ingress settlement remain independent obligations; a canceled future never licenses abandonment of its analyzer heap or native writes.

## Parallelism: actual structure and candidate changes

The facts driver awaits each scheduled provider's execution and completion before starting the next ([facts.rs](../../../../crates/cpg-core/src/facts.rs), lines 40–93). The provider contracts expose genuine dependencies: documents consumes Python/public-name observations; ty-flow consumes syntax/lexical observations; deployment consumes acquisition records. A dependency-ready schedule could overlap deployment with Python analysis and, after Python completes, documents with Behavioral flow. It must retain exact completed input descriptors, contribution ownership, vocabulary assembly and cancellation of sibling work on failure. Shared contribution kinds are not authority to write into the same mutable producing contribution.

This is an **Interface-checked opportunity**, not by itself a finding that serial scheduling violates A4. Pyrefly already analyzes the named root set through a shared library pool: `State` uses `Inline` for ordered extraction/lazy queries, while `transaction.run` explicitly receives `analysis_pool()` ([pyrefly_stage.rs](../../../../crates/cpg-extract/src/pyrefly_stage.rs), lines 94–100, 518–533, 1420–1427). The exact fork's [ThreadPool](https://github.com/paul-heyse/pyrefly/blob/63cda076956013cd0bd1d0d05c785f747fe6adc0/crates/pyrefly_util/src/thread_pool.rs#L79), lines 79–123, maps `AllThreads` to `available_parallelism().min(64)` and joins the spawned work with a Rayon scope. `NumThreads(NonZeroUsize)` and `Inline` are also available. No arbitrary thread cap or automatic removal of the library's 64-worker bound is recommended. The useful design comparison considers available host capacity, shared pool occupancy, simultaneous stages, memory overlap and the library's dependency work. A second pool per file/session would add workers and retained state without establishing useful overlap.

Within one Pyrefly session, roots are emitted in a sequential loop after the joined analysis (lines 580–615). Expensive range queries can perform lazy work inline; fork [run_step](https://github.com/paul-heyse/pyrefly/blob/63cda076956013cd0bd1d0d05c785f747fe6adc0/pyrefly/lib/state/state.rs#L2122), lines 2137–2164, queues only created/increased-require/dirty modules and avoids a pool handoff when no new tasks exist. Repeated `run` calls are therefore not proof of repeated whole-project checking. Parallel extraction would require checked thread-safe transaction access, separate per-module lowering state, deterministic receipts, output ownership and total working-set analysis. Retain the current simple route until that comparison identifies a material gain.

Release and corpus each construct a new `State` (lines 299–317, 518). This repeats at least session-local preparation; both can encounter the same imported dependency bytes. It is a plausible reuse boundary, but joining them under one constant configuration changes import semantics. Prefer library-owned incremental/session reuse keyed by complete source, configuration, resolver and provider identities over an ad hoc cache of rendered answers. A multi-config State, or sharing only demonstrably context-independent preparation, needs exact fork qualification. The fork's stdlib cache is keyed by `SysInfo` and enforces matching typeshed paths within that identity ([state.rs](https://github.com/paul-heyse/pyrefly/blob/63cda076956013cd0bd1d0d05c785f747fe6adc0/pyrefly/lib/state/state.rs#L2047), lines 2047–2111); that invariant must survive any broader reuse.

## Concrete avoidable work and lifetime concerns

### IA-01: Behavioral flow gathers every module result before lowering the first

**Source diagnosis — Implemented.** `TyFlow::run` reads all admitted root texts into `native_inputs`, calls `cpg_flow::index`, then starts its emitting loop ([ty_flow.rs](../../../../crates/cpg-extract/src/ty_flow.rs), lines 571–629). `index` prepares one virtual filesystem and Program, then sequentially computes every `ModuleFlow` into a `Vec` ([cpg-flow/lib.rs](../../../../crates/cpg-flow/src/lib.rs), lines 405–458). Thus all returned flow graphs coexist before the sink's backpressure can affect their producer. Pipeline input/index charges do not convert these result allocations into incremental output. More or more complex corpus modules amplify retained intermediates even when sink queues stay bounded. This is a concrete FP-07 / DP-10 / DP-20 concern for Behavioral, with no Catalog latency implication.

**Proposed direction.** Keep preparation of the complete virtual import root and Program, then expose a module-result callback/iterator while the same database remains alive. Lower and emit each result before computing the next. Preserve exact original/view hashes, module error independence, scope/place/occurrence correspondence, runtime bindings and unavailable/partial reasons. Avoid a new workflow framework. Parallel module queries using cloned Salsa databases are a separate alternative requiring exact snapshot/thread and memory qualification, not a prerequisite for streaming. A per-file database would lose existing import context and repeat preparation.

**Closure.** Inspection establishes that no full result vector precedes first emission; an independent two-module case with a cross-module import preserves facts and view identities, and a sink refusal prevents subsequent modules from being computed. A larger authorized run would measure peak memory and elapsed time; none is measured here. This correction need not alter the profile-selection rule.

### IA-02: Runtime rewriting builds a throwaway AST for tokens

**Source diagnosis — Implemented.** `rename` calls latest Ruff `parse_unchecked_source`, inspects only `.tokens()`, copies text and replaces identifier tokens named `TYPE_CHECKING`, refusing a pre-existing sentinel ([cpg-flow/lib.rs](../../../../crates/cpg-flow/src/lib.rs), lines 370–400). The rewritten file is subsequently parsed by `ruff_db::parsed_module` for ty (lines 511–515). The preparatory original-source AST is unnecessary to the consumer's stated token operation. This is avoidable full-source parse/allocation work under FP-07 / DP-10, solely on Behavioral.

**Interface-checked alternative, Proposed adoption.** The exact Ruff fork publicly exposes `lexer::lex(source, Mode)` (doc-hidden), `Lexer::next_token` and `Lexer::current_range` ([lexer.rs](https://github.com/paul-heyse/ruff/blob/9080ee7a82a4ec7359ba2ade60839ef1108a2968/crates/ruff_python_parser/src/lexer.rs#L1621), lines 121–142, 1621–1625; [lib.rs](https://github.com/paul-heyse/ruff/blob/9080ee7a82a4ec7359ba2ade60839ef1108a2968/crates/ruff_python_parser/src/lib.rs#L88), lines 88–105). A lexer-only pass is the smallest candidate, with no new dependency. Reusing already retained canonical Ruff tokens is another option but would carry them across the current completed-record boundary; a token transport/cache may cost more than a cheap local lex. Raw textual replacement is unsuitable because it changes strings/comments and misses token semantics.

**Risk and closure.** Lexer recovery and parser-mediated token recovery may differ on malformed f-/t-strings and syntax errors; `Lexer::finish` is crate-private. Do not silently change supported recovery behavior. A small pure parity case should compare old/new transformed bytes, rename count and refusal for ordinary names, strings/comments, f-/t-string replacement fields, non-ASCII/BOM/CRLF, an existing sentinel and malformed interpolated strings. Retain parser fallback for any intentionally supported recovery case that cannot be preserved otherwise. No probe ran.

### IA-03: Cancellation does not reach the native Pyrefly task heap

**Source diagnosis — Implemented.** Dropping a provider future sets `StageContext`'s atomic and cancels the workspace sink, then registers the provider thread for joining ([bundle.rs](../../../../crates/cpg-extract/src/bundle.rs), lines 481–534, 537–549; [workspace.rs](../../../../crates/cpg-core/src/workspace.rs), lines 3004–3038). `guard` observes the atomic only when the adapter performs a context operation. The initial `transaction.run` and later dependency waves receive no cancellation handle or callback (Pyrefly adapter lines 518–533, 1420–1427). A cancellation during a long analyzer run therefore drains safely but can continue computing work that can never be published. This is a failure-path execution concern for both profiles, not proof of corrupt completion.

**Interface-checked alternative, Proposed adoption.** The exact fork exposes `Transaction::get_cancellation_handle` ([state.rs](https://github.com/paul-heyse/pyrefly/blob/63cda076956013cd0bd1d0d05c785f747fe6adc0/pyrefly/lib/state/state.rs#L907), lines 907–915). Its handle is a cloneable atomic signal; `TaskHeap::work` checks it before each queued task and clears remaining queued work ([task_heap.rs](https://github.com/paul-heyse/pyrefly/blob/63cda076956013cd0bd1d0d05c785f747fe6adc0/crates/pyrefly_util/src/task_heap.rs#L22), lines 22–40, 168–219). Active callbacks finish cooperatively; this is not hard preemption or a guaranteed latency bound. `Transaction::run` discards its internal `Cancelled` result (state.rs lines 2319–2325), so the adapter must explicitly reject interrupted execution before querying/emitting a completed view.

**Owning correction and closure.** Let the existing provider-run cancellation owner register a transaction-local callback/handle with a scoped lifetime, synchronize registration against cancellation already signaled, and unregister when the transaction ends. Reuse that owner for failure as appropriate; do not add an unrelated polling thread or reset/reuse a canceled transaction. Continue joining provider/library workers and settling accepted ingress; never turn interrupted answers into empty/partial-complete facts. A deterministic pure cancellation case can cancel queued analyzer work and prove no completion plus joined drainage; interruption of an already-running lazy query remains a separate residual obligation. Exact callback registration and error propagation design remain to be settled by the coordinator.

### IA-04: A prepared root's inherited-field correspondence can be parsed again

**Source diagnosis — Implemented.** The main root path builds canonical syntax and `Spans` once (Pyrefly adapter lines 662–704). `InheritedFieldSpans` has a separate lazy cache; on first inherited-field lookup for a source it reparses verified source and reruns typed syntax into a new `Spans` (lines 2553–2577, 2628–2655). Its existing cache already prevents repetition per descendant class, so this is not a per-field full parse explosion. It can still duplicate canonical preparation of a root already/currently processed. This is a narrower both-profile reuse opportunity, not established timing dominance.

**Proposed direction and risk.** Make one source-only correspondence preparation operation serve main root emission and inherited-field lookup, with exact source/provider/parser/settings/limit identity and separately owned invocation receipts. Seed/reuse only compact indexes actually needed for inheritance; retaining every root AST or all large span indexes can cost more memory than the saved parse. Sources first needed before their main emission require deliberate preparation ownership, not fabricated emitted receipts. Keeping the lazy cache is the simplest alternative when actual overlap is small. Closure is an exact-source multi-class case that observes one preparation per source while preserving occurrence IDs, source-size refusal and ambiguous/unavailable attachment; the existing cache test at lines 3009–3037 covers only cache calls, not main-pass reuse. No new test ran.

## Native heap and transitive work: open premise, not a license to reduce coverage

Root source-size, syntax-node and callback limits do not bound total native analyzer work. `typed_syntax::admit` explicitly notes that an oversized refused root may still be imported and parsed provider-internally, outside the adapter budget ([typed_syntax.rs](../../../../crates/cpg-extract/src/typed_syntax.rs), lines 49–66, 116–127). Session `Require::Exports` reduces dependency retention requirements; it does not mean zero dependency parsing/checking. Selected external symbols and public traces promote dependency modules to `Everything` even in Catalog; Behavioral's model requirements can enlarge that selected closure (Pyrefly adapter lines 1327–1459; [native_context.rs](../../../../crates/cpg-extract/src/native_context.rs), lines 110–123). The visited set prevents repeated module promotion within that pass. Removing imports or replacing them with `Any` changes types, exports, signatures, MROs and uncertainty; it is not a conforming speed improvement for comprehensive creation.

Native Pyrefly AST/answers and ty Salsa/semantic-index heaps remain distinct from typed transfer and adapter allocations. Canonical Ruff reserves a conservative source-based allowance (ruff_context.rs lines 73–101), and ty explicitly separates pipeline-owned charged indexes from native heaps (ty_flow.rs lines 98–99, 132–179). These are truthful allocation domains, not a measured process-memory ceiling. No whole-input capacity conclusion follows from their bounded row writers. For skewed sources/import closures, prefer demand-appropriate library requirements, source/session reuse, incremental lowering and cancellation before inventing additional resource machinery or weakening imports. The missing decision premise is actual peak native heap and import work for the authorized FastMCP workload, with release/corpus and profiles separated. Its measurement belongs to later qualification, not this static report.

Capture closure is verified on opening and again after native providers return ([bundle.rs](../../../../crates/cpg-extract/src/bundle.rs), lines 95–114, 401–406). This repeatedly reads the frozen closure, but establishes a real integrity guarantee around provider work. It is not dismissed as redundant because paths are read-only. Replacing repeated verification with a once-certified immutable capture owner requires stronger enforcement that providers cannot mutate/replace it and exact lifetime/cancellation qualification. Until then, retain the guarantee; no claim is made that hashing dominates latency.
