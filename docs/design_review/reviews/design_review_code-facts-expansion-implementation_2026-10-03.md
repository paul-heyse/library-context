## Library fit, alternatives and transition

The selected native library interfaces supply structured signatures, binders, member/type locations, resolved definitions and flow information that a CLI text/JSON-only authority would flatten or omit. Independent latest Ruff owns canonical syntax; Pyrefly's embedded Ruff remains private to its adapter, and ty attachment has explicit correspondence. This increases adapter/pin maintenance but makes source identity and native typing evidence inspectable. The review used pinned interfaces/source and the offline analyzer skill for these claims; it did not rely on library names as evidence of fit.

Keeping only raw native outputs would be a simpler acquisition design but would leave every consumer to decide role, completeness, closure and qualification. A universal provider registry would add machinery without removing those semantic decisions. Reimplementing a Python type checker or general interpreter would increase both semantic and maintenance scope. The bounded model operations are justified because they decide product questions the linked libraries do not own; they do not replace the libraries' type authority. Existing DataFusion/Arrow, finite BDD and graph foundations remain appropriate to relational computation, condition operations and declared projections. No new library adoption or license restriction is needed for these corrections.

The simplest viable corrections are the ones implemented: reuse Types coverage, directed CorpusLibrary membership and shared ScopeIndex ownership. Per-callable completeness, universal document association or Input-scope rewriting would respectively introduce a new authority, weaken association or erase the native qualification. The selected fixes avoid those costs. A future requirement for per-callable negative precision, additional corpus association or effective runtime terminal behavior must revisit the owning contract; it cannot be obtained by loosening a renderer.

This is a hard declared-model/schema migration. Append-only codebooks, required-nullable wire fields and generated Rust-owned contracts replace the prior shape; no compatibility reader or defaulted missing premise is introduced. Rust remains the wire/semantic owner and Python validates the generated contract. Rebuilt fixture generations and final matching artifacts are acceptance work; operator reconstruction and activation are separately stopped. No additional architectural authority change is required by this review: the corrections realize existing owners. Current disposition belongs to coordinator §5, not to a rewritten historical review.
