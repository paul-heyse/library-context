# Catalog collection efficiency: integrated design review

**Reviewed 2026-10-17 · Design tier · Target purpose · Decision: Accept scoped**

The assembled collection changes substantially improve the physical route for producing attributed
code facts. Canonical correspondence is indexed, compatible Pyrefly preparation is shared, dependency
function payloads are selected before expensive expansion, and flow collection consumes admitted
complete groups instead of retaining a complete expanded module. Native ingress reuses stable writer
preparation while retaining fresh authorization, expectations, outcomes and recovery for each window.

Independent review found three residual problems: diagnostic cancellation could start another complete
traversal; capture/call lowering repeatedly searched immutable inventories; accepted ingress could lose
its executor during sibling cancellation. The source corrections have been independently inspected.
The repaired actual-native refusal control passed its unchanged finality assertions; the reviewer
independently inspected both source and the selected closure evidence.

This bounded review covers PA00–PA05, TF00–TF03 and NI00–NI03. It does not certify full Catalog runs,
complete native concurrency/recovery matrices, publication/restore, serving, operator adoption or
measured performance. The [collection coordinator §6](../../plans/catalog-collection-efficiency-plan_2026-10-17.md#6-sole-disposition-and-current-checkpoint)
alone owns current finding disposition.

## 3. Composition, library fit and execution fit

`Spans`, `SyntaxIndex`, `TypeIndex`, `ClassBindingIndex` and lexical preparation remove repeated
correspondence searches while preserving their duplicate policies. One compatible root
`PysaResolver`/`ModuleAnswersContext` and captured-variable preparation feed specialized collectors.
Definitions-only dependency processing does not construct call graphs.

Early heavy-payload selection uses complete borrowed function-base/class inventories and exact
selected names/keys/enclosing closure. Full capture eligibility, classes/globals and required ancestry
remain. Replacing capture eligibility with selected retained definitions would lose reference-only
facts. Lower requirements or earlier collection need finality/epoch guarantees not established by the
inspected alternatives. The IC:F02 live index preserves those full-base consumers without repeated
session-global scans.

Type reuse is intentionally limited to display text from the current Other/Truncated encounter.
Recursive construction, first registration, chosen/candidate distinctions, depth and cumulative work
remain encounter-sensitive. Final term identity alone is an incomplete memoization key.

One guarded canonical read feeds both charged row inventory and the model attacher. Native flow
prepares the full transformed virtual universe before queries, then consumes owning source inputs in
callback order. Releasing original text after callbacks preserves virtual context for lazy cross-file
queries. Complete use/capture/reaching groups remain producer-owned and admitted through callback
return. Shared condition backing and retained ordinal correspondence have explicit lifetimes.
Private consumer-stop signalling preserves the original callback error, stops subsequent top-level
queries and leaves unrelated panics to unwind.

Serial top-level collection preserves callback-before-next-query refusal. Retained native ASTs avoid
reconstruction by later wildcard/import queries. Speculative parallelism or eviction would add work
and error/resource ownership without an established benefit. Opaque analyzer heaps, VFS, BDD/model
internals remain outside the adapter-owned allocation guarantee. A single parser/diagnostic traversal
and native cycle region can defer cooperative cancellation; no fixed latency guarantee follows.

Native scalar indexes use tagged table/String/i64/UUID keys, original positions and full equality;
compound/unkeyed values keep ordered fallback. Generic Value hashing would not establish the required
cross-representation numeric equality. Supplied guards are not recaptured. Packet-local deferred flags
precede request hashing. Native `array::find` retains first-match/NONE without materializing all matches.

Ingress writer reuse retains only compatible issuance and fixed control sizing. Every window still
prepares expectations, request identity, authorization, outcome and recovery. Standalone and post-freeze
owners remain independent. The attempt registered read is meaningful optimistic commit protection on
the pinned RocksDB realization; it is not an exclusive waiting PostgreSQL row lock. Removing it would
lose stale-owner protection without an established concurrency benefit. Complete cuts remain necessary.

These mechanisms remove identified amplification without a global cache, scheduler or backend. Their
qualitative value is credible for growth, skew and cycles, provided accepted work retains its executor
through cancellation. No benchmark campaign is needed to establish that structural judgment.

| Analysis question | Universe and method | Meaning/limit |
|---|---|---|
| Canonical/native correspondence | Exact source/span/kind/role candidate views | Model attachment remains authority; ambiguity explicit |
| Dependency payload demand | Full native bases/classes plus selected closure | Changes construction demand, not capture eligibility |
| Runtime reaching candidates | Complete ty source universe and qualified groups | Conservative within declared model; unsupported/approximation retained |
| Native commit eligibility | Fresh expectations under original owner/era/cut | Exact equality/rollback; acceptance and finality independent |

## 5. Findings and corrective contracts

<a id="F01"></a>

### IC:F01 — Diagnostic cancellation could start another abandoned traversal

**Moderate · FP-07, DP-20, A4 · Baseline Implemented / Interface-checked.**

`diagnostic_records::ruff` ran complete Noqa-enabled and disabled `check_path` computations without
an operation check between them. `pyrefly_stage` could also enter preparation without a fresh check.
Context observer checkpoints do not interrupt ordinary diagnostic traversal. Cancellation during
the first channel therefore allowed a second whole-source traversal with no remaining consumer.
No false completed output was demonstrated.

Thread the existing operation check into prepared diagnostics; check before preparation and before/after
each channel. Preserve both complete suppression-sensitive computations while live, original error
identity, and the explicit indivisible traversal limit. The independently inspected repair does this.
Run `20261017T080437.747Z-5725c4` passed the new boundary-refusal and existing two-channel parity controls
(2 passed, exit0, host cleanup confirmed). This is focused-Tested behavior, not general cancellation latency.

<a id="F02"></a>

### IC:F02 — Capture and call lowering bypassed prepared correspondence

**Moderate · FP-07, DP-10, DP-16, A4 · Baseline Implemented / Interface-checked.**

`capture_records::symbol` scanned session-global native symbols for every full base function and outer
capture origin. `call_records::symbol` repeated it for graph owners; each native site also searched the
retained canonical call vector. Sparse selected output did not prevent repeated unrelated examination.

The existing interner must maintain one charged module/native-key candidate view. Preserve lowest-ID
first selection for calls, unique/ambiguous selection for captures, identical reinterning, payload
collision refusal and reference-only eligibility. Dynamic target insertion updates that view. Native
symbols cannot be mutated around the owner. Keep an admitted local first-retained canonical site view
with the original missing-site fallback. Retained definitions do not own capture eligibility.

The independently inspected correction implements those contracts, admits growth before mutation,
and retains backing charges through owned maps. Run `20261017T080922.477Z-9cb259` passed5 DB-free controls:
live/module-scoped/idempotent keys; lowest-ID/defensive ambiguity; refusal with unchanged inventories;
canonical duplicate/fallback; and actual Pyrefly full-base/reference-only capture parity with missing
outer refusal. These are focused-Tested local semantics, not native database qualification.

<a id="F03"></a>

### IC:F03 — Accepted ingress could outlive its submitting executor

**High · FP-03/05/06, DP-19/20, A1/A3/A4, G5 · Actual baseline failure; correction focused-Tested.**

`NativeBridge` owns a private Tokio runtime and exits on shared cancellation after draining its request
JoinSet. Baseline `NativeCalls::submit` and `NativeCompilerStore::ingress` used ambient `tokio::spawn`.
An accepted ingress driver could outlive its submitting request while still executing on the bridge
runtime. Retaining its JoinHandle did not keep that runtime executing. Merely reversing Workspace
drain awaits would not prevent the actor's independent cancellation shutdown.

Actual `typed_flow::native_flow_group_resource_refusal_drains_without_completed_observation` in
`20261017T080121.505Z-d50c9d` failed cleanup at143s. The original `Resource(flow_use_group)` and empty
completed tables were preserved. Sibling completion lost an accepted ingress acknowledgement;
driver join reported `JoinError::Cancelled`, with Unknown acknowledgement/write/driver/pin-close
finality. This is not a demonstrated payload collision or false completed-fact result.

Use the existing store construction runtime for registered native calls and accepted ingress,
matching retained readers/preparation. The store's actual executor must remain alive through drainage;
a Handle alone does not own a Runtime. Preserve existing scopes, retries, request recovery, mutation
leases, charges, acknowledgements, joins and truthful Unknown handling. Do not swallow JoinError,
demote Unknown, abort accepted tasks or equate host exit with native finality.

The root's three-file runtime-placement correction has been independently source-accepted. Run
`20261017T080922.894Z-3fd8bc` passed2 DB-free controls that destroy the submitting runtime before
ingress acknowledgement or call release, with exit0 and confirmed host cleanup.
**Focused-Tested closure,2026-10-17:** `20261017T081134.928Z-2bda8e` passed the actual-native Resource
refusal, Catalog context, Behavioral context and qualified runtime-flow controls:4passed, exit0,
host cleanup confirmed. The refusal reached its unchanged Resource, completed-visibility, cleanup
and zero-reservation assertions. Together with the two executor-lifetime controls and independently
inspected source, this establishes the selected correction. Original `d50c9d` failure/Unknown ownership
remain protected; a new pass does not relabel them or establish the wider recovery matrix.

## 7. Alternatives, rule impacts and validation boundary

Diagnostic fusion would conflate suppression and observer stopping/completeness; shared preparation
plus boundary cancellation preserves both. Broad term caching lacks encounter/context effects.
Earlier/lower-requirement Pyrefly collection lacks established rich-fact epoch guarantees. Parallel
top-level flow work would violate stop ordering and add resource/error owners. Generic Value hashing
lacks exact equality fit. Larger windows or writer fan-out do not remove repeated preparation.
IC:F03 needs no new executor framework or shutdown protocol: use the existing retained-work executor.

**Required rule changes: none.** These repairs realize existing cancellation, lookup and finality
contracts. No complete-cut, receiving, diagnostic, candidate, concurrency or Unknown-protection rule
is weakened. They are bounded implementation corrections; no binding decision pivot is selected.

## 8. Decision

**Accept scoped.** IC:F01–F03's inspected corrections preserve semantic authority, candidate
completeness, exact equality, independent admission and truthful failure handling. A1–A4 are satisfied
for the examined scenarios, supported by focused diagnostic, lookup and accepted-executor controls.
No new rule changes or material review findings remain. The fresh independent reviewer inspected the
final correction and actual refusal evidence before this closure.

This accepts the bounded collection/integration design at its stated strength. Analysis/retrieval
assertions retain their own outcomes and limits. Full Catalog, selected-complete, assembled, wider
recovery/publication/serving qualification and measured performance remain outside this acceptance.
The coordinator owns current dispositions; this review is the dated judgment, not another progress ledger.
