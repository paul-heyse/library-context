## 2. Governing owners and corrected behavior

| Owner / consumer | Source-supported contract |
|---|---|
| Native selection → serving discovery/hydration | Package, release, input, member and derivation nomination use exact native selected access, including contributor-held aliases. Nominal copies elsewhere cannot satisfy eligibility. Nested module lookup uses the selected reader. |
| Native audit → installation/completion/recovery | Ordered membership observation reaches physical terminal completion and full output digests. Backing, guard, hold and endpoint correspondence use bounded sets/windows; a late failure cannot become successful empty observation. |
| Held audit → compiler preparation | `InstallationAudit` owns a real reader pin and memoizes only independently completed observations. Root inventories, aliases, layouts, ranges and final checked installation remain independently earned. |
| Compiler dependency mapping → caller budget | Contributor decoding is charged while temporary, pending descriptors through processing, stack capacity through traversal, and returned mappings through their actual consumer. Tree-to-vector conversion retains overlapping charges. |
| Native request → original completion | The original transaction persists `applied` or `premise_changed`. The caller reads that exact result while retaining its outcome reference. Only the conclusive no-op authorizes same-incarnation recapture. Missing outcomes, retirement, ABA and uncertain requests do not. |
| Model/native diagnostic → host observer | Bounded typed causes preserve known identity/issuance and absent opaque identities. Current producer and reader migrate together. Diagnostics confer no release authority or native finality. |
| Native schema → beta development worker | Derived assets preserve one authority, complete file inventory and ordered module closure. Direct Any sessions and tester-private sessions have different ownership boundaries. |
| Existing service/run/storage → campaign disposal | Exact prelaunch target/consumer records survive missing beta reports. Current executor authentication is independent of resume checkpoints. Whole-target disposal preserves original native uncertainty and retires only its owned runtime state. |

The governing model keeps execution, retention, completeness, semantic admission, publication,
selected visibility and recovery separate. No universal lifecycle registry or new scheduler is
introduced. Whole-service containment is justified because beta's public tester does not accept
injected clients. It is a development boundary, not an alternative product installation authority.

For a completed blob, equal replay can advance guard revision without changing bytes. The
reviewer inspected immutable writers, blob declarations, expectations and retirement. Completed
piece writers admit only exact existing equality; header replay preserves the completed declaration.
A real retained blob pin prevents its retirement, and verified outgoing holds prevent independent
piece retirement. Therefore exact completed declaration and the same active positive incarnation
are sufficient operation-local reuse premises after full inventory/bytes/hold validation. Check
them before/after initial observation and on reuse. This reasoning does not weaken revision-sensitive
pre-completion finalization, permit incomplete memoization or establish a portable witness.

## 4. Execution fit and scenario reasoning

The new audit originally ordered by `relation,semantic_key,id` despite a unique
`(contribution,relation,semantic_key)` index. The redundant `id` was removed. Exact pinned source
advertises ordering after the equality prefix; the actual campaign's fixed plain EXPLAIN shows
`IndexScan contribution_rows` Forward under SelectProject, without Sort. This supports the chosen
physical route, without executing or timing a large workload. Client window charging alone would
not have settled possible server-side full sorting.

Runtime investigation also exposed a missing leading derivation equality in incoming operation
and evidence nominations. The corrected queries bind the exact selected reader's derivation after
caller bindings and supply the `incoming(derivation,out,field,in)` index prefix. Independent
focused reinspection accepts this correction: publication uses that same realization, and exact
native selected membership/contributor aliases still govern payload eligibility. The evidence
control places a foreign contributor's nomination in the same realization, so namespace narrowing
cannot stand in for selected hydration. Actual EXPLAIN and behavior outcomes are recorded
separately in coordinator §6; source reinspection does not imply they passed.

Adding evidence remains a model/declaration and selected-hydration change, not a new lifecycle job
for each family. Equal concurrent compiles preserve original request outcomes while recapturing
only allowed changed premises. Overlapping roots share physical observations under a retained
owner without sharing admission. A beta failure before reporting remains covered by prepublished
whole-target ownership. A failed native drain remains failed even when authenticated executor
shutdown/discard settles the target. An already inactive daemon yields honest `not_run` inventory,
with exact unit authentication and descendant checks before disposal.

These routes address material FP-07/A4 amplification through indexed sets, bounded transfer,
held reuse and one campaign daemon reused across suites. No numerical speed, capacity or
efficiency measurement is asserted. C01–C11 supported substitution decisions remain in the
integrations companion; on-demand plans/indexes/parsing are the adopted current tooling route.
