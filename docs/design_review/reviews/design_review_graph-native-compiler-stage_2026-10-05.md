graph cycles are distinguished from cyclic proof dependencies.

The controlled compiler trust premise does not require automatic replay of every producer or
blanket invocation of every historical workspace invariant. Removing repeated replay must
preserve each genuinely necessary local/closure/totality check; a digest proves content
preservation, not unrestricted Python truth.

### F01 — Embedding winners are stage-local and effects are scalar

**Priority: high within selected embeddings. Implemented diagnosis, Proposed correction.**
`analytic_embedding.rs:82–90` and `retrieval.rs:97–106` open separate
`embedding_realization::Session` objects. Each begins with an empty `values` index. `realize`
requests one cache key, counts one text and calls the bulk `Embedder::embed` API with one text
(`embedding_realization.rs:117–196`). CLI compilation supplies no persistent cache
(`lctx/src/compile.rs:35–36`). Retrieval loads earlier analytic uses for byte-equality checks,
but never adopts their winners before requesting vectors (`retrieval/consumption.rs:204–212`).

A legitimate catalog with the same complete spec/request text in both consumers can therefore
invoke the service twice. Two valid responses with differing exact bytes are refused by
`embedding::consumption::Winners::replay`, although the first admitted winner could have satisfied
both uses. Even byte-identical responses perform redundant effects. Distinct texts are processed
through scalar service crossings rather than bounded batches. This defeats DP-09's one reuse
owner, DP-10, FP-03/07 and A3/A4; G6 fails for this composition.

Give the attempt one actual winning-value owner, independent of persistent cache deployment.
It consumes complete spec/text requests, admits tokens before embedding, batches eligible distinct
requests within the existing budget, and returns immutable winning receipts. Preserve separate
analytic and retrieval use identities, service-unavailable/token-limit outcomes and exact consumed
bytes. Different specs/templates must never coalesce. Adopting already completed analytic receipts
for E0 is a small viable first correction; a shared attempt owner plus bounded batching gives the
coherent full route. A cache alone leaves cache-disabled compilation and scalar misses exposed.

Closure: a focused optional-embedding catalog control demonstrates one winner across both
consumers, different-spec separation and preserved unavailable/token-limit behavior; inspection
shows bounded bulk miss realization. Current execution disposition belongs to the coordinator §7.

### F02 — Retrieval construction immediately replays its own producer

**Priority: medium. Implemented diagnosis, Proposed correction.**
`retrieval_preparation::mandatory` builds and returns `(Data, Output)`; `retrieval::produce:51–52`
immediately drops that Output. After loading optional S0 inputs, `retrieval.rs:91` builds the whole
retrieval output again. `ConsumptionData::verify` then calls
`self.output.matches(&build::build(&self.render, b)?)` (`retrieval/consumption.rs:192`), rebuilding
the same final output once more while the original remains live. `retrieval/build.rs:355–678`
renders mandatory source/API/document/deployment units and appends optional brief units.

Optional synthesis can legitimately add rows; it does not justify rebuilding unchanged mandatory
units. The final self-comparison supplies no independent algorithm oracle. As corpus size grows,
production repeats full rendering/fragmentation and retains duplicate result representations under
the same budget. This is concrete avoidable amplification under FP-07/A4 and DP-10/23, independent
of whether small fixtures pass.

Retain the mandatory result and extend only the optional synthesis contribution, or split loading
from construction so production builds once. Preserve original anchors, exact contextual membership,
byte equality, outcome/key completeness and value receipt checks with narrowly scoped completion
validation. Keep full producer-equivalence replay available in independent focused controls/debugging
where it challenges corruption; do not simply remove a necessary closure guarantee. A valid
brief-enabled catalog must retain all mandatory units and its additional brief units. Closure is
the traced single-construction route plus those existing semantic controls. Disposition: coordinator §7.
