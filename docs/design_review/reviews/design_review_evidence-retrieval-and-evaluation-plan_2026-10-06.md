# Evidence/retrieval and evaluation plan — revised target review

**Decision: Accept at Proposed architectural strength for the reviewed plan set.** The revised design incorporates the predecessor review's three material corrections and approved rule changes. It defines how independent programmatic judgments improve retrieval and delivered information, how grounded outer feedback changes either the system or the evaluator without silently changing a comparison, and how full4096 winning values supply one deliberate normalized1024 representation shared by initial search and E1 analytics.

The production design has a credible physical route: bounded construction from attributed roots, exact primary bindings instead of blanket parent membership, shared encoder values, scoped native discovery, batched compatible expansion, late hydration and context-closed delivery. The private evaluator starts with finite relations and independently enumerated cases; optional solvers, neural scoring and larger numerical campaigns do not delay its first useful capability. The long-lived batched evaluation worker and bounded immutable ranked-result retention address actual consumers without introducing an orchestration service or permanent history.

This is acceptance of the specified target, not of its implementation. Current source retains the format2/1024 baseline and the attribution/candidate-loss paths the plans intend to replace. No runtime acceptance, live checkpoint quality, comparative superiority, performance claim, heldout campaign or resumption of paused graph-native remediation follows. The predecessor review's original **Revise** verdict and profile1.4 evidence remain intact. Its findings retain their source-qualified IDs and implementation disposition at the extension coordinator.

## 2. Responsibilities, dependencies and fact fidelity

The design separates authorities by meaning, rather than creating a service for every concept. Source/catalog owners establish attributed evidence. Retrieval construction defines applicability and interpretation closure. The embedding owner defines actual values and consumer projections. Native realization lowers those meanings into access paths. Serving selects and exposes information. A private evaluator judges it against independent expectations; experiment/feedback operations govern changes to the yardstick.

| Embedding model/effects | Actual encoder/input, immutable winners, query recipes and declared projections/consumption | Cache and clients supply exact winners; E0/E1 use owned representation policies |

## 3. Contracts and isolated verification boundaries

The coordinator §2 and supporting plans define construction, projection, nomination, selection and observation verbs with explicit outcomes. Source unavailable/native cases remain qualified instead of guessing a body. Oversized indivisible evidence remains original-addressable with explicit lexical-only/partial-vector availability; headers, mandatory context and special tokens count toward complete encoder input. Synthetic/render/token/source coordinates are distinct.

Pure contract and numerical cases require no native database or model. Actual native/transport claims require their real disposable persistent realization and final SDK/MCP bytes. Independence requires separate expected logic, hand-derived cases and a simpler exhaustive reference; sharing authoritative production validators remains useful admission protection but is not oracle truth.

## 4. Composition, dependencies and execution fit

| Stage/question | Universe/relations and method | Accuracy, limits and lineage |
|---|---|---|
| What is searchable? | Attributed root, primary/context parts and exact binding; semantic partition/local tokenizer | Deterministic policy with source maps; oversized omissions explicit; no invented applicability |
| Where might useful evidence be? | Eligible exact identifier, lexical and1024 ANN contextual nominations; initial RRF K60/equal family ranks | Exact match eligibility versus heuristic score; widening128/256/512/1024 is finite experimental policy, not complete top-k or absence proof |
| What context completes it? | Named qualified relations and batched frontier restrictions | Partial degree/byte/frontier outcomes explicit; physical adjacency is not support |
| How order/pack it? | Retained candidate full4096 rescore; context-closed bundle selection using final cost | Rescore cannot recover missing candidates; greedy selection heuristic; original references distinct from immediate delivery |
| What does E1 compute? | Shared normalized1024 projection, explicit vector universe/method/settings/consumption | Exact analytical neighbor contracts remain separate from ANN; full4096 analytics requires new policy/results |
| Is delivered information sufficient? | Private task/context witnesses and supported finite worlds over exact visible observations | Model-relative judgment; unsupported/inconsistent/budget-infeasible/execution-failed strata preserved |
| Where was numerical information lost? | Same eligible admitted population, blocked full4096 and1024 scoring, then native ANN and later stages | Declared precision/ties/backend; exhaustive is not exact real arithmetic or semantic relevance |

The physical design removes the baseline fragment × parent member × anchor inference and vector-per-occurrence risk. Distinct projection/release/family cohorts deliberately copy only1024 search arrays, buying scalar-index eligibility at a bounded cohort write/index burden. Canonical full/projection bytes remain shared. This is more work than one global vector row, but has a concrete selective-access consumer and avoids per-target/window/anchor replication.

Locked SurrealDB3.3 source `exec/operators/scan/knn.rs:40–133,433–565,767–850` distinguishes bitmap allow-list triage, exact small sets and residual filtering. This corroborates a credible operation route; it does not prove a particular application query uses it. The realization plan §7.3 correctly leaves representative composed EXPLAIN inspection to implementation, permits native exact eligible-set scoring for small authoritative selections, and refuses to treat a correlated binding predicate or hint as prefilter proof. There is no required application counting/planning service or second vector store.

Stable tokenizer assets/preparation, batched construction/native expansion, late full-value hydration, inference outside transactions and blocked offline references fit the local workload qualitatively. Ranked-result state is justified by pagination: at most16 entries/8MiB per session,10-minute expiry and explicit refusal. It does not persist historical query state. Campaign reuse/batching avoids multiplying subprocess and inventory work by generated case count. These are credible work shapes, not measured capacity claims.

Dependencies are substantive rather than broad barriers. EV1 requires ER1 semantic design, not production ER1 or external comparison parity. EV2 challenges that kernel. EV3 uses whichever actual pure/renderer/native lanes exist; integrated packet claims require ER3/ER4. EV4 comparison governance is available before tuning and does not depend on paid outer studies. ER2 requires actual encoder-input/shared declarations; ER3 vector work requires its value seam, while lexical/NotRequested paths do not wait for live inference. ER4 requires maps/bindings and native reads. Relevant native repairs are prerequisites where consumed, while the paused entire remediation suite and Q1 are not universal gates. Shared editing surfaces are coordinator-owned independently of logical parallelism.

## 9. Alternatives and interacting remedies

The implemented all-purpose1024/member-fragment baseline is simpler to retain, but its actual source paths use the access-module artifact (`retrieval/build.rs:1101`, `retrieval_preparation.rs:346`), omit option/release source branches (`retrieval_preparation.rs:365–369`), and multiply fragments by parent membership/anchors (`lctx-publisher/src/search.rs:315–367`). Native search discards BM25-zero matches and limits raw documents before target grouping (`lctx-serving/src/search.rs:61–65`). These observed paths justify the proposed migration without claiming that every task currently fails.

Using full4096 automatically for all analytics would remove a projection choice but change E1 scores/results and arithmetic/live payload incidentally. The selected explicit shared1024 policy provides a narrower, honest initial cut; full4096 analytical experiments remain possible with fresh identities. Global vector sharing with relational residual scope is physically smaller, but cohort copies have a named selective-access purpose. Exact native eligible-set scoring remains the simpler route for small authoritative populations.

A solver-first evaluator adds deployment/encoding/status obligations for cases finite sets already answer; an agent-only expected-answer engine loses reproducible independent semantics. The selected finite-primary/grounded-outer arrangement avoids both while retaining richer theory and usability evidence when needed. Merely counting delivered IDs is simpler but fails legitimate condition/default/context tasks; actual bytes and independent map checks are necessary.

The remedies fit together: exact bindings and observable delivery permit meaningful diagnosis, but never define expected witnesses; precise value identities permit interpretable numerical ablations, but do not establish relevance; evaluator revision governance preserves the meaning of improvement while allowing outer feedback to change that meaning explicitly. No remedy requires compatibility readers or archival runtimes.
