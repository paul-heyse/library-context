# Catalog compilation execution fit

**2026-10-07 · DESIGN / TARGET · Decision: Revise.**

The catalog has useful semantic foundations: pinned acquisition, attributed observations, explicit unresolved states, Rust-owned operations, programmatic assertions, immutable completed inputs and separately published native realizations. Its compilation route nevertheless turns many small semantic operations into repeated large physical operations. Scoped kernels select correct premises, but their row access scans complete IPC relations; shared contributions repeatedly sort and copy the accumulated relation; admission reconstructs properties of unchanged lower inputs; disabled analytics prepare rich execution inputs. Native publication additionally retains scalar writes for external targets inside an otherwise bulk loader.

These are architectural defects under FP-07/A4. Static source evidence establishes the unnecessary work; it does not establish which defect dominated the stopped run or how much faster a correction will be. The recommended architecture is operation-shaped compilation: shared immutable row access and bulk columnar computation, compact indexed kernels where their semantics fit, demand-driven preparation, and validity carried through controlled immutable state. Native SurrealDB remains a credible selected query and publication realization. Its indexed access and graph execution are candidates for particular compiler operations too; the store-free boundary has been assessed as a choice, not treated as an acceptance constraint.

## 3. Contracts that corrections must preserve

Completed inputs bind attempt, profile, model policy, producer/content and the exact shared publication view. Later contributions cannot widen an earlier producer's premises: [workspace](../../../crates/cpg-core/src/workspace.rs), lines 1231–1292. A closure must follow actual owner memberships and forward dependencies, not arbitrary incoming references. Missing requested premises are errors; known complete-empty and `NotRequested` have distinct meanings. Nominal type, context, direction, multiplicity, isolates and unresolved endpoints must survive every physical lowering.

The compiler's read-only [SQL entry point](../../../crates/cpg-core/src/sql.rs) forbids DDL/DML/statements. Pure domain kernels can be tested from explicit inputs without a database. Selected embeddings are declared effects: [retrieval](../../../crates/cpg-core/src/retrieval.rs), lines 165–202, opens a service only when requested; [embedding realization](../../../crates/cpg-core/src/embedding_realization.rs), lines 130–201, checks configuration and canonical winners and uses compact spool offsets rather than retaining all vectors.

Admission establishes actual semantic/reference/outcome properties. A digest or a schema-valid row alone is insufficient. External artifact import and native storage are genuine new exposures; their validation cannot be removed merely because the producer once validated an earlier representation. Conversely, moving controlled immutable premises between internal consumers need not discard their established validity.

Native publication creates a private database, writes endpoints before enforced relationships, checks terminal responses, reconciles stored content and query-visible mappings, fingerprints executable definitions, then exposes a complete marker. Selection remains separate. [Publisher](../../../crates/lctx-publisher/src/lib.rs), lines 9–23, 79–135 and 137–203, has no transaction covering extraction, CPU work or inference. This private/seal/visibility separation is worth preserving under either compiler placement alternative.

### F01 — Selected semantic grains lose their selectivity at physical row access

**Consequence priority: high. FP-07, DP-08/10/14, CI-07/08 · A4 violated. Diagnosis: Implemented/static-inspected. Remedy: Proposed.**

[Normalization](../../../crates/cpg-core/src/normalize/mod.rs), lines 81–147, 204–222 and 501–547, repeatedly sends filtered rich-row reads and missing-ID batches to completed IPC inputs. [CompletedInputs::session](../../../crates/cpg-core/src/workspace.rs), lines 1779–1793, registers only schema and path, despite known completed row counts. [PreparedClosure::select](../../../crates/cpg-core/src/consumed_rows.rs), lines 884–894, joins per-grain keys to a complete rich source. [C0](../../../crates/cpg-core/src/catalog_core.rs), lines 154–232, and [C1](../../../crates/cpg-core/src/catalog_evidence.rs), lines 191–259, repeat that hydration for bounded roots; C2/S0/E0 use the same mechanism.

DataFusion 55.1.0 Arrow IPC `infer_stats` returns unknown statistics; listing pushdown only gives exact partition pruning, and these relations have no ID partition layout. Arrow projection pushdown is available, but this path provides no ID-addressed row lookup. Its physical join-selection rule compares bytes/rows and retains order when those values are unavailable. Thus small logical output and bounded rich decoding coexist with repeated large physical scans and weaker join placement information. This is an integration defect, not evidence that DataFusion itself has a broken optimizer.

The existing nominal adjacency is genuinely indexed: `EdgeSource::matching_batches` and `EdgeCursor::targets`, lines 582–585 and 705–730, binary-search complete nominal keys. Preserve it where useful. The defect is the following rich source access and repeated root seeds, not an assertion that every closure scans all edges.

Preparation also repeats equivalent physical demand. [Callable scopes](../../../crates/cpg-core/src/normalize/callable_scope.rs), lines 78–140, first follow all nominal fields, then request ownership for overlapping fields. `NominalClosure::own`, lines 233–247, adds the same forward follow plus its genuinely required inverse membership. Preparation sorts staged edges without deduplicating these duplicate requests; the full-key visited set preserves semantic traversal, but it does not remove the duplicate edge query/staging cost. Normalize the physical edge request set while retaining both ownership directions.

[E0 ranges](../../../crates/lctx-model/src/domain/retrieval/source.rs), lines 144–166, correctly distinguish exact `(artifact,start,end)` provenance. [Retrieval preparation](../../../crates/cpg-core/src/retrieval_preparation.rs), lines 449–481, fetches physical ordinal chunks separately per range. Overlapping ranges can fetch/decode the same chunk repeatedly before row deduplication. Union or deduplicate physical `(artifact,ordinal)` demand, then associate the fetched bytes with every original range. Distinct range identity is not a reason to duplicate source access.

[S0](../../../crates/cpg-core/src/synthesis.rs), lines 674–735 and 839–869, hydrates/builds documentary findings once to derive global requests and emitter selection, releases the rich data, and repeats documentary hydration/build for emitters. This is a visible memory/recomputation tradeoff, not proof of a redundant semantic pass: the first pass learns information needed by the second. Compare retaining only compact completed documentary output/support versus rebuilding it through indexed input. Retaining every rich graph to avoid recomputation would defeat the intended lifetime boundary. The repeated source-scan defect applies to both passes; removal of the second build itself remains Proposed, conditional on a smaller total preparation/retention route.

**Correction owner:** workspace/source access and compiler adapters. Prepare row/block locators once for a completed immutable view, or process sets through shared projected scans with native optimizer-visible statistics, then hydrate only required rows/fields. Keep complete nominal identity, missing-premise errors, precise publication-view selection and bounded block lifetimes. Reuse generic source locators across semantic scopes; semantic owner membership/direction still selects the closure. Native indexed records/one-hop adjacency are an alternative where a complete native ingestion route earns its cost. A bespoke universal query/provider framework is unnecessary.

**Closure:** source inspection must show selected IDs reach selected blocks/partitions or one shared scan, known source statistics reach the planner, and unrelated content no longer forces repeated full rich scans. Close the duplicate forward-edge staging and overlapping physical-chunk demand obligations while preserving inverse ownership and distinct contextual ranges; record the S0 compact-output versus recomputation/lifetime choice. Challenge reconvergence, shared owners, missing/foreign IDs, high-degree nodes and cross-module required premises with existing focused controls where changed semantics need protection. No latency target is asserted; representative end-to-end timing is required only for a speed claim.

### F02 — Stream completion repeatedly rebuilds accumulated shared content and packs it row by row

**Consequence priority: high. FP-07, DP-10/14/16/19 · A4 violated, G8 fail for scalar gather. Diagnosis: Implemented/static-inspected. Remedy: Proposed.**

[Workspace::order](../../../crates/cpg-core/src/workspace.rs), lines 1362–1389, includes the previous completed relation whenever a contribution is appended. [ordered_stream](../../../crates/cpg-core/src/ordered_stream.rs), lines 310–354, reconstructs all source coordinates and globally sorts them, then lines 215–263 construct one copied RecordBatch per selected row and concatenate those batches. Previous rich content is copied and hashed again. Producer completion and semantic publication boundaries determine this work even when consumers require only an exact immutable union.

The scalar copy has a real rationale: release the large original IPC backing block. That rationale does not require one allocation/copy operator per row per column. Arrow 59.3.0 supplies batched `take` and `interleave_record_batch`; group selected positions while retaining only a bounded active source-block window, then assemble the bounded output. Keeping every original block alive for one giant interleave would defeat the intended protection and is not the remedy.

**Correction owner:** workspace ordered-source completion. Sort a new contribution as needed, merge compatible already ordered runs, and represent immutable selected contribution closures without physically rewriting each prefix unless a consumer requires a contiguous stream. Perform conflict/dedup checks under full nominal keys and preserve old selected views. The current canonical full-row prefix hash is a design choice: if its eager calculation still forces whole-prefix work, separate internal closed-source identity from the final canonical graph content identity rather than hiding that cost behind segmented storage. Final canonical identity, deterministic output and conflict semantics remain deliberate requirements.

**Closure:** inspect removal of repeated coordinate re-sorting/rich prefix rewrites and singleton gather; retain exact same-key conflict detection across files/windows, identical-payload dedup, deterministic ordering and immutable earlier views. Close both the repeated-prefix and packing obligations. Segment maintenance that merely shifts the same rebuilding into another wrapper does not close this finding.

### F03 — Stable semantic validity is discarded at internal boundaries, causing repeated reconstruction

**Consequence priority: high. FP-07, DP-03/09/10/19 · A4 violated. Diagnosis: Implemented/static-inspected. Remedy: Proposed.**

[Compilation](../../../crates/cpg-core/src/compilation.rs), lines 610–615, calls whole `admit_semantics` after normalization; [artifact admission](../../../crates/cpg-core/src/artifact.rs), lines 1255–1260, calls it again after upper stages. [validate_scope](../../../crates/cpg-core/src/workspace.rs), lines 340–384, reconstructs global references and chooses all applicable admission checks; it has no reuse of previously established lower checks by unchanged exact premise set. Global reference construction, lines 978–1144, reads every completed relation to emit target/reference IPC and joins those files. Scoped owner checks prepare their own dependencies again.

The upper artifact contains new records, references, outcomes and shared vocabulary contributions; final admission is necessary. Some premises have changed and must be rechecked. But stable lower scopes are not automatically invalid merely because unrelated upper records exist. The current route repeats their checks without identifying a new exposure. The ordinary CLI also exports its just-admitted object then invokes portable `verify_export`; detached import reconstructs and re-admits semantic rows before publication. External `publish-artifact` genuinely needs this protection; an owned in-process publication path need not pretend its own immutable artifact is an uncontrolled import.

**Correction owner:** workspace/artifact admission and publisher boundary. Carry established validity under the existing attempt/profile/policy/exact selected descriptors; retain a check only while its complete premise set is unchanged. At upper completion enforce newly applicable or affected invariants and all new reference membership, using a reusable compact target/reference view where it removes work. Let ordinary publication consume an owned admitted graph through the same semantic contract; retain independent portable import verification for external exports and stored realization reconciliation after native writes. Do not introduce a certificate system, independent ledger, mandatory replay or new generic validation engine.

**Revealing case:** an upper contribution extends shared vocabulary or changes a context-dependent membership that a lower check consumes. It must invalidate that check; comparing only relation names or latest content would silently bind another view. A check over the exact frozen lower prefix can remain valid while a new check certifies new records. This preservation obligation precedes any skipped check.

**Closure:** name the failure exposures of retained admission/import/storage checks and inspect exact dependency/lifetime reuse for unchanged internal checks. Meaningful changed-premise, detached tamper, missing-reference and native-corruption controls must continue to reject; complete-empty/unrequested cannot substitute for missing requested roots. Do not close this finding merely by deleting final checks.

### F04 — Unrequested A1 analytics prepare and hydrate their execution inputs

**Consequence priority: medium. FP-03/07, DP-10/16, CI-07 · A3/A4 violation in demand composition. Diagnosis: Implemented/static-inspected. Remedy: Proposed.**

[Analytics adapter](../../../crates/cpg-core/src/analytic.rs), lines 39–67, captures expected inputs for all methods; lines 81–111 prepares FrameScopes and reads all declared decoder inputs for each frame. Only later does the model's [analytics build](../../../crates/lctx-model/src/domain/analytics/build.rs), lines 21–37 and method branches, use technique selection. Techniques default to disabled in `analysis/settings.rs`, lines 9–19. Total explicit `NotRequested` outcomes are valuable; their existence does not require full rich kernel preparation.

Do not overstate the graph component: A0 itself requires call and definition topology, so graph hydration is not demonstrably attributable solely to disabled A1. `compilation::graph_needs` is settings-insensitive, and any future graph-only optional route must also make demand effective, but the decisive defect here is disabled A1's own scope construction and rich hydration.

**Correction owner:** analytics model/build selection and adapter. Resolve requested method dependencies before physical preparation. For no selected A1 methods, emit total owned outcomes and required finite frame/domain provenance from the smallest valid inputs. ## 9. Corrective synthesis and tradeoffs

F01 is the central access defect. F02 concerns the construction and lifetime of the very completed inputs that F01 reads. Their remedies should compose: a sorted immutable contribution closure can supply one nominal row/block locator and truthful statistics; a consumer sees its exact view without forcing another full rich stream. F03 then carries validity under those same exact descriptors. This is one coherent ownership direction, not three competing caches or stores.

F04 can remove unused work independently, but its selected branches still need F01's improved access. F05 is an independent native boundary improvement; it does not diagnose compiler-stage delay. Shared semantic provenance/unknown states and exact earlier-view selection are preservation constraints across all corrections.

A database migration alone cannot settle these findings. Native indexed access could solve F01 while introducing per-root network calls, duplicated native/canonical payloads, eager index construction and wider recovery state. Conversely, preserving store-free compilation while adding a generic table/provider/cache framework could add more machinery than a direct immutable locator requires. Select the smallest complete realization per operation; do not mechanically make every semantic kind a file, table, index, task or transaction.

For the chosen in-process compiler direction, publication remains a separate effect because coherent external visibility and read-only pinning are genuine consumers of that boundary. A later native-first choice must state which private compilation operations actually benefit from native adjacency/index execution, how pure owner tests remain isolated, and which IPC/admission/serialization paths disappear. Maintaining both full compiler implementations or a legacy reader is outside the functional need and would undermine the hard pivot.
