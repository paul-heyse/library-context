## 3. Readiness and finite preparation

Direct, invariant and assembly dependencies remain distinct. Runtime binding obtains exact
completed contributor selections. Consumers need not wait for unrelated publication members;
publication prefixes still require complete declared membership. Adding a producer or invariant
changes its declaration and genuine consumers, rather than adding a global barrier.

Upper-stage preparation follows actual demand. Launched tasks own their selected preparation;
coordinator retirement accounts for all uncompleted stages, including running tasks.
[Charged shared slots](../../../crates/cpg-core/src/analysis_graphs.rs) can leave the coordinator map
without invalidating borrowers.

Finite algorithms preserve their contracts:

- [Structural controls](../../../crates/lctx-model/src/domain/structural/controls.rs) use FIFO and
  predecessor arenas, emitting existing flat witnesses; root scratch and output have distinct lifetimes.
- [Delegation](../../../crates/lctx-model/src/domain/analysis/delegation.rs) retains per-seed BFS,
  sharing immutable roles, adjacency and boundaries without collapsing typed evidence.
- [Summary](../../../crates/lctx-model/src/domain/execution/summary_production.rs) prepares exact
  call/frame correspondence on demand while preserving Disjoint, Subsumed, Refused and Proven,
  worklist residuals and independent proofs. Catalog exits explicitly NotRequested before demanding
  Behavioral application/Local/SCC authority; requested Behavioral Summary still requires it.

Shared correspondence avoids repeated reconstruction and scratch has a useful narrower lifetime.
Per-seed traversal and required flat output remain genuine work. No capacity or speed claim follows;
runtime acceptance of the actual bounds is still required.

## 4. Scoped validity

CN01 premises bind model/profile, invariant identity/revision, executable factory, complete ordered
roles, requested/resolved boundaries, exact views/source snapshots and full contributing descriptors.
Native store, calls, cancellation, borrowed execution owner and pool are separate actual identities.
Companion inputs and unregistered factories decline this reuse route.

The model's `scoped_uniform_independent` defaults false. Checks affected by compact owners execute
afresh unless explicitly independent; the six inspected normalization/fidelity opt-ins use the
no-effect compact-owner contract. Row identity alone therefore does not imply complete applicability.

Private success is constructed only after actual scoped execution or complete-empty applicability
EOF. Pending successes commit after whole-prefix native/cancellation checks. Failure or abandonment
invalidates reuse. Exact native-qualified reference sessions are retained where available; external
planner metadata cannot manufacture success. See [admission](../../../crates/lctx-compiler-store/src/admission.rs).

Final freeze compares complete selector mappings and freshly revalidates original capabilities through
the guarded native route. Final artifact evidence retains charged borrowers independently of memo
membership. [Workspace drainage](../../../crates/cpg-core/src/workspace.rs) closes scoped reuse after
native-call drainage and before store drainage. Weak operation links avoid an owner/memo/evidence cycle.

The cost is retained per-check premises/source capabilities and fresh current-owner observations.
That fits avoiding repeated semantic kernels while preserving physical assurance. This is operation-local
reuse; cold admission remains independent execution. Source review does not prove that every late-stream
failure, corruption or cold composition has been exercised by current tests.

## 5. Publication expectations

CN02 extends Publication's existing lifetime. Seven search and four lexical families retain existing
memory/spill-backed PreparedRows. Final comparison and inventory use independent complete cursors;
an exhausted earlier cursor cannot impersonate complete-empty expectations.

PreparedSearch binds actual Loader nonce, publication/source clients, source pin, staging owner, pool,
realization and exact scope. Equal descriptors on another Loader grant no borrowing. The publisher
retains fresh executable definition-epoch verification. The direct native retained route also checks
actual analyzer metadata against the compiled declaration, before lowering, after materialization and
before reuse. See [lexical statistics](../../../crates/lctx-native/src/lexical_stats.rs) and
[publication](../../../crates/lctx-publisher/src/native_publication.rs).

[Staging](../../../crates/lctx-native/src/control/staging.rs) still reads fresh actual rows through
EOF/drainage, reconciles complete root child inventory and performs the final guarded revision/context
effect. Expected runs remove repeated lowering, not these independent observations. Cold reconciliation
retains its reconstruction route.

The comparison synchronously reserves/owns expected backing before admitting the actual stream factory.
The existing owned native driver retains it through transport drainage and receiver loss. Refusal thus
cannot launch an actual read whose cleanup depends on dropped preparation. Acknowledged publication
remains distinct from later cleanup failure: marker identity is recorded before fallible finalizers.

Independent implementation review found two material gaps before repair: the direct retained route
lacked actual analyzer verification, and reservation refusal could await drainage without retaining
expected backing. Both are closed **by source inspection** in the reviewed tree. Actual metadata
compatibility, exhaustion/cancellation controls and owned-campaign mutation tests remain runtime obligations.

## 6. Retirement

[ADR-0170](../../adr/0170-retirement-frontier-and-lineage.md) keeps pending/retiring head pages separate
from retained singleton progress. Candidates are freshly checked. Child nomination clears buffered
hints because new children may sort earlier. Insufficient allowance exits rather than refilling an
unaffordable head. Existing claim/finalize and edge-effect accounting remains.

Required lineage comes from the validated current job after recovery and is carried in page bindings
and their digest. Each effect compares it with the transactionally loaded owner. Constructors and
maintenance successors preserve lineage; child incarnation, exact hold, generation/era/epoch/successor
and root fencing remain. The guarded fresh queue-empty proof alone establishes completion.
See [retirement](../../../crates/lctx-native/src/control/retirement.rs).

This establishes discovery-time pending priority, not atomic exclusion of concurrent nominations.
Paging replaces singleton discovery, but per-candidate refetch remains: it does **not** establish fewer
total database crossings or a speedup. It introduces no second queue authority and preserves recovery
and remote-uncertainty meaning. Native frontier/foreign-lineage/successor controls remain required.

### F01 — Retirement heads scan and sort unrelated job states

**Implemented/source-and-planner assessed,2026-10-14; current disposition at coordinator §6.**
The initial combined `state IN ['pending','retiring'] ORDER BY id LIMIT128` discovery query used
`retirement_queue_v4` only on the job prefix, followed by state filtering and SortTopKByKey. The
declared `(job,state,id)` index did not make that head read bounded by useful candidates. Every
resume's progress query contained the same predicate/order manifestation. The exact progress
projection was not separately probed; its execution-fit diagnosis was inferred from shared predicates
and ordering, then the implementation was removed.

Retirement discovery and progress now share one SQL construct with two exact-state scans, each
limited to full `k=min(remaining demand,128)`, followed by a bounded ordered merge/truncation.
Concurrent pending→retiring duplicates coalesce only with equal job/object/incarnation; current state
remains a freshly checked hint. Moving up to2k payloads avoids a complete queue or cloned rich rows.
Both responses retain native row/byte checks, and returned output retains the native window bound.
The actual patched3.3.0 engine's fixed plans show forward `[job,state]` IndexScan with limit128 and
no Filter/Sort for both selected queries. The source/planner correction was independently accepted;
fresh candidate checks, nomination invalidation, retained cursor, lineage/effect fences and final
transactional empty proof are unchanged. Current-source lower-child/allowance control remains the
runtime closure obligation. No timing or total-query-count conclusion follows.

Planner evidence: managed runs `20261014T173116.127Z-16b979` (original route) and
`20261014T173432.720Z-617508` (exact-state alternatives), retained by the coordinator. These are
read-only fixed EXPLAIN observations on the explicitly owned campaign, not ANALYZE or workload timings.

biodivine-lib-bdd0.6.3 and SurrealDB/parser3.3.0. Selected capability skills supported inquiry;

The composition uses relational streams, model-owned graph/SCC projections, bounded condition kernels,
native indexed discovery/guarded effects and existing spill/lifecycle carriers at their appropriate grain.
Fresh lowering is a simpler baseline but repeats stable work. A generic incremental framework, portable
validation grant or additional query-engine encoding of native Value runs would add ownership, codec
and ordering integration without an established scoped consumer. Specialized private reuse is sufficient.
