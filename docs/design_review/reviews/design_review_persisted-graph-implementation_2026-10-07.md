## 2. Domain and responsibility model

The important distinction is between an enduring nominal row, a producer's completed contribution, an exact immutable view of contributions, final canonical graph content and a published physical realization. Treating all five as one content digest would force repeated prefix work or permit a later contribution to change an earlier reader's meaning. [Model completed contracts](../../../crates/lctx-model/src/domain/completed.rs) separate these explicitly. `ContributionSpec` includes producer/profile/model/implementation/settings and exact input snapshots; `CompletedContribution` adds total outcome and output content; `CompletedView` names the exact contributor set and deduplicated cardinality. Full typed keys retain the relation namespace. Completed-state identity describes retained state, not a reusable execution grant or a claim that an incremental scheduler exists.

| Responsibility | Semantic owner / executing boundary | Consequential contract |
|---|---|---|
| Capture and independent provider facts | Model input/provider contracts; acquisition and native extraction adapters | Pinned captured inputs and constructed provider contexts; typed bounded outputs and total availability, with disagreement/unknowns retained. |
| Nominal identities, graph mapping, roles and invariants | `lctx-model::domain`, generated record/graph registries and shared validators | Meaning is declared before its native/Arrow representation; relationship roles, ordering and qualification remain distinct. |
| Completed products and dependencies | Model completed types; [workspace](../../../crates/cpg-core/src/workspace.rs) and [native compiler](../../../crates/lctx-surrealdb/src/compiler.rs) | Pending writes cannot widen exact completed views; equal duplicate payloads deduplicate, conflicting full-key payloads fail. |
| Native access and bulk computation | [Native provider](../../../crates/lctx-surrealdb/src/compiler_provider.rs), [projected Arrow conversion](../../../crates/lctx-surrealdb/src/projected_arrow.rs), DataFusion and finite model kernels | Selection/projection precede rich transfer; captured provider epochs remain exact; computation does not infer semantic policy from storage. |
| Final semantic admission and publication | [Artifact admission](../../../crates/cpg-core/src/artifact.rs), [publisher](../../../crates/lctx-publisher/src/lib.rs), shared native reconciliation | Required semantic checks, canonical identity and independently regenerated actual-state checks survive direct sealing. Publication and operator selection remain separate. |
| Evidence journeys and evaluation | Serving's pinned reader/packet/delivery owners; independent [MCP observer](../../../crates/lctx-eval/src/mcp_observer.rs) and [experiment identities](../../../crates/lctx-eval/src/experiment.rs) | One realization governs evidence and continuations; independent expectations do not become production inputs. |

The dependency direction is coherent: model meaning is used by both compiler and physical lowerings; native I/O realizes completed state; orchestration composes these capabilities; serving consumes a sealed pin. The lower model does not depend on a server to run finite algorithms. Making compiler acquisition/preparation explicitly native introduces real configuration and lifecycle costs, but does not move Python semantics or evaluation truth into a database schema.

The retained non-graph union has actual consumers rather than speculative persistence: QualityStep preserves private iteration values, ArtifactChunk records refer to the sole original-byte owner, and completed descriptors/bindings support [snapshot inspection](../../../crates/lctx-publisher/src/inspection.rs), transport and audit. There is no second retained raw chunk body. Cross-run scheduling remains outside the implemented capability.

## 3. How the physical route serves the workload

The decisive change is source placement. The former immutable IPC route repeatedly asked an unindexed source for small rich subsets and reconstructed accumulated relations at completion. The native route instead retains typed membership and uses indexed demands over exact views. The schema provides contribution/key membership indexes; scalar nominal reference access derives atomic scope fields from the model registries, rather than a handwritten whitelist that silently misses the next family ([schema](../../../crates/lctx-surrealdb/src/schema.rs)). Native projected builders lower declared columns directly, without a rich canonical encode/decode underneath every selective read.

[Prepared nominal closure](../../../crates/cpg-core/src/consumed_rows.rs) retains captured source providers, deduplicates identical declared forward pairs, batches relation-qualified frontiers and keeps the complete nominal visited key. Native forward and incoming ownership reads project only ID/reference fields. The resulting grain binds sorted distinct per-relation keys to a selected native provider before rich payload reads. A dynamic compact-key/rich-source join remains only for detached finite tables. Compact custom edges still have a bounded spill/gather path where the native atomic field route does not apply. These are complementary realizations of explicit model-owned edges, not competing definitions of closure.

The selected provider retains the key owner charge through its physical plan/stream, pushes safe supported predicates and projection into native reads, and exposes completed cardinality through `NativeExec::partition_statistics`. Selected-key counts are honest upper bounds; filtered/reference selections do not pretend to have exact counts. Known unfiltered rows now reach physical planning, addressing the prior loss of statistics before DataFusion's build-side choice. This establishes availability of the information, not a measured plan/speed result or evidence that DataFusion was previously broken.

Completion processes the current contribution's membership/content once. It computes a new view's row count by indexed anti-membership of those new keys against exact predecessor contributors, rather than fetching/recounting the accumulated union. Immutable contributor sets replace eager prefix sorting/copying/hashing. Final canonical identity still has its required ordered whole-family pass. The latter is a different obligation from repeatedly rewriting a producer prefix.

The remaining upper consumers now fit their demand. [Analytic orchestration](../../../crates/cpg-core/src/analytic.rs) prepares FrameScopes only when a method is requested; all-disabled methods retain complete frames and NotRequested outcomes while A0 stays required. S0 appends documentary products to its compact spool and consumes that completed spool for emitters, replacing the second documentary/hydration construction ([synthesis](../../../crates/cpg-core/src/synthesis.rs)). [Original demands](../../../crates/cpg-core/src/original_demands.rs) union physical chunk IDs for overlapping logical ranges; S0/E0 still retain each original coordinate and support association. Full embedding values, exact winner/spec admission and deliberate 1024 search projection remain separate meanings.

For serving, [Prepared/PacketRows](../../../crates/lctx-serving/src/records.rs) owns one request-local typed family cache and lazy full-key/reference postings. NativePackets/source usage, evidence, characterization, behavior and defaults reuse the shared selected positions instead of rescanning a family for every nested lookup. A selected result may still own copied output rows, and a requested family may decode once; this is bounded request work rather than another cross-request cache or repeated whole-family predicate search. Claims preparation is shared in the same request. The source borrow and charges prevent unqualified reuse under another pin.

The [batch codec](../../../crates/lctx-surrealdb/src/codec.rs) groups actual record types, encodes each bounded type slice once and restores alignment. Loader and independent reconciliation share mechanical conversion but compare actual stored state independently. External endpoint writes deduplicate full keys in bounded batches before ENFORCED edges ([loader](../../../crates/lctx-surrealdb/src/loader.rs)); endpoint/reference second passes remain necessary. [Restore](../../../crates/lctx-publisher/src/backup.rs) uses verified range batches for originals rather than a separate scalar read per 64KiB page.

The final normal/retained service paths finalize delivery and then produce one owned bounded [EncodedJson](../../../crates/lctx-model/src/domain/serving/dispatch.rs). Buffer growth is reserved before allocation and exact final byte caps remain enforced; [service](../../../crates/lctx-serving/src/service.rs) returns that encoding. Raw Rust and MCP envelopes differ and legitimately encode their own final shapes. Delivery stabilization after a changed shape is also necessary; eliminating those passes would weaken the contract.

The analysis meanings are preserved separately from these physical changes:

| Stage / question | Owned projection, method and settings | Accuracy / outcome / evidence contract |
|---|---|---|
| Normalization and C0/C1: which catalog contracts and evidence associations exist? | Typed provider dependencies, source/role qualification, public catalog and exact original/scenario associations; native closure only chooses the required input subset. | Derived under the declared model; provider availability and unresolved/conflicting evidence remain explicit. Completed dependencies and output attribution preserve the basis. |
| A0: what required structural topology supports the frame? | Model-owned call/definition topology, declared connectivity and universe; independent of optional A1 flags. | Retained structural method/abstraction, complete versus limited/unavailable outcomes; no substitution of native reachability for transfer semantics. |
| A1: which selected analytic products help discovery? | Selected PageRank, communities, FCA/RCA and neighbours consume their declared graph/attribute/vector projection and settings. Preparation takes the selected dependency union. | Exact or heuristic meaning stays attached to its named method/parameters/run; total NotRequested is distinct from successful empty output. The pivot does not establish numerical quality. |
| C2/S0: which finite support and programmatic claims can be delivered? | C2 finite predicate/conjunction classification retains its declared completeness domain; S0 uses exact C1 support/original associations and the completed documentary spool. | Model-relative classification and evidence-backed programmatic assertions; support/qualification and original coordinates remain traceable. Spilling and selection cannot silently shorten the semantic universe. |
| E0/search: what exact value and projected ranking input is admitted? | Input recipe/spec/hash and winner policy govern exact value/cache admission; full4096 values and deliberate1024 search projection have distinct consumers. | Exact input/value provenance, heuristic ranking semantics and explicit unavailable outcomes; native read placement does not change the recipe or promote similarity into a semantic fact. |

Budgets and partial-result behavior remain the declared model/operation outcomes and explicit resource refusal; physical batching/spilling is not an approximation policy. This review checks preservation of those contracts rather than reopening each retained algorithm's accuracy qualification.

## 4. Validity, finality and external state

The workspace carries validity only for exact premises: model/invariant/profile and selected immutable views, including reference targets and absence-sensitive inputs. Changed membership or a newly available target changes the premise and rechecks the applicable invariant. Missing requested input cannot certify an empty domain; explicit completed-empty and NotRequested provider declarations can. This removes repeated admission at unchanged internal boundaries while preserving necessary producer/frontier and final graph checks.

Native operation admission closes before final drainage; active writes and streams retain leases until terminal transport completion. Dropped compiler streams drain the SDK transport; errors stay sticky. Contribution publication follows checked statement completion, and uncertain cancellation/cleanup does not become completed state. Owned failures name an unselected orphan if cleanup cannot be confirmed. These properties depend on actual native failure journeys in the acceptance plan; their source mechanisms do not constitute an executed failure receipt.

Ordinary [CLI compilation](../../../crates/lctx/src/compile.rs) checks native readiness before acquisition for both artifact and native targets. Its admitted artifact retains the native authority. `seal_completed` completes endpoint/search realization, reconciles actual graph state, verifies retained-state identity, closes compiler writes and seals that database. The seal checks answer-affecting definitions/index readiness, writes the marker, ends the writable session and reconnects through VIEWER before returning an unselected handle. There is no portable self-export/reimport in the ordinary path. The explicitly requested artifact route exports complete new-format graph/original/retained state and abandons its private native staging after checked completion.

External import and restore remain independent uncertainty boundaries. They load bounded checked content, validate completed descriptor projections, exact memberships/dependencies/cardinality and restored model/frontier outcomes, rebuild serving projections, and reconcile actual persisted state. New-format state is not inferred from the final graph. A private [NativeReader<()>](../../../crates/lctx-surrealdb/src/reader.rs) supplies owner-controlled prepublication reads without manufacturing a `SnapshotHandle`; published readers still check the complete handle against the marker. Production search/restore/reconciliation use this distinction.

The new [F01](#f01) matters here: backing-body validity must precede trusting a membership's claimed content. Its correction belongs to cold import/audit and fixed retained-state representation checks, not a new repeated full-prefix producer-validation stage.

## 7. Finding and scheduled obligation assessment

### F01 — Cold private backing could disagree with completed content identity

**Responsible component:** native compiler retained-state import/audit and fixed backing conversion. **Priority:** correctness/fidelity before performance. **Principles / judgments:** FP-04, DP-01/02/03/09/23, A2, G2/G3/G6. **Current disposition:** the [persisted graph plan](../../plans/persisted-graph-execution-plan_2026-10-07.md) owns scheduled closure; this review owns the diagnosis. This review's F01 is distinct from the catalog-speed review's F01.

At `f385f0c4`, non-graph `compiler_record` rows stored a native body, canonical serialized body and content hash, but `validate_state_row` only checked their table/key envelope. `verify_state` compared membership content with `node.content` and recomputed contributor membership digests; graph reconciliation handled entity/assertion families. None independently reconciled a QualityStep body with its canonical/content fields. A different finite, non-key `QualityStep.value` could therefore remain model-valid while its retained contribution content described the old value. Aggregate transport identity is not that semantic reconciliation: an external exposure can supply a self-consistent outer digest for internally inconsistent projections.

The correction validates the closed QualityStep/ArtifactChunk arms from model nominal fields, rederives the full typed backing identity, checks exact primitive lowering and actual-body canonical bytes/content, and checks original metadata/coverage/digest against the real byte owner at cold exposure. It uses bounded existing verified range reads and direct fixed primitive validation, avoiding a new singleton Arrow roundtrip or routine prefix hash. Ordinary selective views carry their completed validity.

**Source closure:** `ef47b7c2`, with private byte-reader API correction `e73183dd`, implements this correction in [compiler backing validation](../../../crates/lctx-surrealdb/src/compiler.rs) and cold `verify_state`; the reviewer inspected both independently. Meaningful corruption controls cover valid non-key body alteration, false typed key, transport alteration, inconsistent ordinal metadata and coherently altered physical bytes retaining the old logical digest ([compiler views controls](../../../crates/lctx-surrealdb/tests/compiler_views.rs)). **Runtime closure:** the coordinator's three actual persistent compiler-view controls **passed** on 2026-10-07, including the cold body/key/import corruption and coherent original-tamper cases. Their command and bounded scope are recorded in §10; the complete command and enclosing acceptance remained pending. This establishes targeted Tested closure of this correction, not whole-plan acceptance. A future private backing arm or changed native primitive representation reopens the fixed union/validator boundary; no new ledger, gate or permanent probe machinery is required.

## 8. Library fit and complete alternatives

The inspected locked families include DataFusion55.1/Arrow59, SurrealDB SDK3.3, petgraph and the retained finite reasoning/analytics libraries. Native selected tables use the actual adopted indexed record/scope/bulk mechanisms; DataFusion handles columnar joins/projections/global computation; compact Rust full-key structures handle exact visited state and selected positions. A standalone database recursive query is not an automatic semantic replacement. SurrealDB3.3 [`+collect`](https://github.com/surrealdb/surrealdb/blob/v3.3.0/surrealdb/core/src/exec/operators/recursion/collect.rs) tracks hashed values; its array collision test demonstrates generic hash-only merging, not an observed RecordId/pilot collision. This does not establish full-key exact closure equivalence. Native indexed one-hop reads with model-owned visited keys preserve the required guarantee.

Native graph sidecar/inline-edge capabilities are alternatives where suitable adjacency is already persisted. Using them for compiler closure would require early derived-edge writes/maintenance and preservation of declared direction, role and view membership. Current direct scalar reference indexes avoid that extra retained object for this operation. A future adjacency-heavy consumer may justify those built-ins; the current choice is not a claim they are absent or universally unsuitable.

| Complete route | Benefits / burdens | Judgment for this workload |
|---|---|---|
| Persisted native completed state plus Arrow/finite compute | Shares canonical/native serving, inspectable dependencies and complete transport; indexed selective reads, exact immutable views and direct sealing. Pays native writes/index maintenance, RPC conversion and explicit runtime ownership. | Credible implemented composition for the catalog and selected enrichment. Benefits are structural; elapsed speed remains unmeasured. |
| In-process DataFusion over rich immutable IPC | Useful bulk engine and spill capabilities, simple ephemeral processing. Without an appropriate row locator/statistics/selective provider, small grain reads retain repeated rich scans; complete native serving still needs publication/lowering. | Retain DataFusion's appropriate bulk role; the old selective organization is not the preferred complete route. |
| Compact indexed row-address/kernel route plus later native publication | Can suit finite closure and avoid remote crossings. Must also own bounded source-block lifetimes, full nominal keys, deterministic content, complete retained dependency transport and publication conversion. | Credible alternative, not rejected by a benchmark absence. It would add a second compiler/persistence route to the actual shared native consumers without a currently demonstrated need. Revisit on a concrete native crossing/working-set defect. |

Neither choosing native nor retaining DataFusion excuses avoidable preparation or duplicate authority. The assessment follows the composed route and actual consumers, not adoption preference, an invented performance budget or old compiler parity.

## 9. Migration completeness and deferred scope

The inspected production paths migrate ordinary compiler producers/completed reads, analytical/retrieval preparation, artifacts/manifests, publisher/restore/inspection, serving prepared rows, wire delivery, CLI/readiness and evaluation observation. Explicit detached finite MemTables remain semantic test inputs, not a production store-free compiler fallback. Portable graph export and backup remain genuine externally requested operations; their independent checks are preserved. Private prepublication reads and published handles are distinct. There is no requirement to retain retired old-format readers, rollback generations or parallel semantic authorities.

A future cross-run executor must define invalidation/recompute outcomes and absence-sensitive dependencies before using these retained identities as execution reuse. The current foundations have real inspection and transport consumers but do not implement that scheduler. Additional semantic families extend the model and its mechanical lowering; they do not automatically add a runtime stage or per-family framework. High-degree and remote crossing behavior remains a revisit trigger if a supported real workload exposes a new amplification; measurement is needed to claim a speed improvement, not to reopen a static structural defect.
