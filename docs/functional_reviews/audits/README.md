# Functional-review recommendation audits

Companions here record the net changes from a requested
[recommendation audit](../../../.claude/skills/design-review-audit/SKILL.md). The integrated
principal review at its original path is the clean planning input. The
[collection guide](../README.md#recommendation-audits) owns the route and scope.

For `../<subject>_<date>.md`, use `<subject>_<date>_audit.md` here. The filename date identifies
the source review; record the actual audit date inside. Keep one current companion per principal
review and preserve earlier comparisons in Git.

Make the exact input recoverable from Git before replacement and identify its revision, inspected
source state, standard, date and coverage limits. Account for every input recommendation with
Retain, Improve, Correct or adjust, Omit, or Unresolved. Explain consequential changes to value,
scope, enabling mechanisms and the combined recommendation. Include valuable omissions within
the operator's scope. Use flexible Markdown rather than a new registry or scoring system.

Preserve stable opportunity and rule-impact references and map combined, split or replaced
recommendations to the integrated output. Keep critique in this companion; the principal review
presents the resulting proposal directly with a dated attribution and link back here. Preserve
original evidence dates and strength. Neither output approves new scope or changes plan status.

Retain the companion while it supports a current review or downstream decision. Follow the
repository's document lifecycle when its last current consumer is gone. Completion audits
continue to update the same owning plan; they create no report here.
