The [unified plan](../../plans/unified-persistent-surrealdb-plan_2026-10-09.md) develops durable

## §6 Persistence and publication

**Accepted target / implementation in progress, 2026-10-09 (ADR-0145).** One managed service
hosts `main` and `validation`. Explicit maintenance installs compatible schemas and credentials;
ordinary clients only attach. Tests use logical attempts and publications in validation, with no
scratch service or per-test database fallback. Compiler, store, publisher and serving retain their
existing semantic responsibilities. Patched gRPC preserves progressive streaming, cancellation
and checked physical terminality. Optional transports must preserve those contracts.

**Implemented recovery refinement / integrated qualification open, 2026-10-10 (ADR-0146).**
Native upgrades preserve atomic page effects and progress under immutable checked host successor
authority. Schema evolution in §6.3 owns the complete transition and recovery contract;
the persisted coordinator retains actual migration receipts and enclosing acceptance.

> Decision: ADR-0145, ADR-0146

### §6.1 Admitted content and native publication

**Accepted boundary / implementation in progress, 2026-10-11.** `lctx-native` owns shared physical
installation, codec, control, transport and selected semantics. `lctx-compiler-store` owns native
contributions, exact completed views and privately validated admitted/export/restored capabilities;
compilation and independent restore share the actual admission rules. `cpg-core` retains analyzer
orchestration and its completed-input session. Publisher consumes the lower capabilities without
normal analyzer dependencies. Serving preparation/presentation remain above this boundary. Responsible
model/ingestion/codec/derivation source and assets stay in conservative semantic fingerprint closures.
The efficiency coordinator owns implementation and functional acceptance of this split.

**Source integration / functional acceptance open, 2026-10-11.** Physical completion first
checks the exact dependency closures, selected copies, backing and member EOF, and all six logical
families. Retained product singleton views add protected physical roots; they do not alter artifact
meaning unless selected by a semantic binding or its dependencies. Portable completed state format4
uses the same six-family recipe. Logical contribution ownership includes the complete descriptor,
including outcome, output digests and mandatory producer assurance. A producing physical owner is
allocated from its specification before completion; a detached import uses its known completed
identity so distinct completions of one specification cannot collapse.

Compiler storage then executes producer/facts coverage, references, applicable invariants, the
profile/frontier checks, canonical graph derivations and actual manifest inventories. Only its private
constructor combines those executed owners with physical completion into an admitted artifact.
Installation-local persisted evidence binds exact definitions/factories, ordered requested/resolved
roles, complete-empty applicability and the selected physical epoch/incarnation. Native persistence
performs the exact physical CAS; data deserialization cannot construct a compiler admission owner.
The installation assumes trusted writers, including its low-level effect primitives. Artifact format4
carries compact mandatory current producer assurance attribution. Current whole-input admission
can reuse an installation-local premise only for its exact declared selected inputs, current
factory/model/schema, installation validity epoch and protected completion incarnations. A fixed
model driver executes the validator; an independent native observer compares its ordered typed
input through EOF with actual held backing before persisting the premise. Completion owners hold
the receipt, and a receiving pin independently protects it. Missing or stale keys execute current
checks; matching corrupt evidence refuses. Scoped, undeclared, companion, uniform-owner and
unrequested inputs conservatively retain ordinary validation. Portable restoration excludes this
local witness. This mechanism is source-integrated, 2026-10-12; actual fresh-process reuse and
functional acceptance remain open. A frozen warm producer may end product
retention only after independently earned physical completion checks its exact contributor and
inventory; this grants no artifact admission.

**Design-phase cutover target / implementation in progress, 2026-10-12.**
Migrate useful supported views into protected current realizations where practical; otherwise
record regeneration from pinned inputs and its responsible current producer. Retain no legacy
runtime code/data, old view namespace, compatibility reader or opaque historical completed store.
Actual owned process/service quiescence precedes replacing old data. Interrupted outcomes retain
their original uncertainty; joined daemon shutdown establishes executor cessation, not operation
success. The dedicated efficiency campaign does not authorize changes to shared/operator state.
Remove transition-only converters and frozen historical fixtures after cutover. Current contracts
need minimal revealing functional cases, not historical campaigns or performance benchmarks.
The efficiency coordinator owns migration/regeneration dispositions and current acceptance.

Hash hits compare canonical bytes. Nominal anchors contain identity without view existence.
Derived role edges connect source payloads to target anchors; exact completed views resolve the

Durable attempts and effect fences own pending contributions. Contribution completion is local;
private compiler-store admission establishes the exact semantic boundary. Compatible retained admitted
content can attach through checked current ownership without canonical replay. Current provenance,

reconciled through an operation identity, never inferred from local process cleanup.
Attempt closure fences writes before bounded ownership cleanup. Product roots retain their own
prerequisites independently of artifact admission; attempt cleanup nominates outgoing attempt roots
and releases only the attempt's holds. Explicit product release registers exact-incarnation retirement

product as retained even after attempt incidence ends. A named release checks the original terminal
producer and exact product bytes/incarnation, then creates its retirement invocation and root item

collection. Remaining ownership rows provide conservative retry progress. This target integration is
not yet native-Tested; the efficiency coordinator retains the lifecycle acceptance obligation.
Cleanup effects use the exact terminal attempt's original epoch, checking owner/state/epoch at
both durable intent and execution; releasing attempt-owned holds does not allocate a new global
installation epoch per page. A durable hold-cleanup intent spans bounded guarded deletion pages;
only the final empty-scope proof marks it completed. Reconciliation fences further pages of an
incomplete operation, while a fresh intent can resume the remaining ownership rows. Partial
cleanup is not rollback. Ordinary open-attempt and pin authorization remain separate.
Imported memberships retain `attempt→contribution→membership` reachability, including partial
ingress. They need no duplicate direct attempt root once their already-rooted contributor owns
them; canonical, alias and backing-row ownership retain their separate existing protections.
View registration groups descriptor writes and ownership edges in row/byte-bounded windows,
while each exact membership stream still reaches checked EOF and its declared cardinality is
compared with actual rows. A claimed empty descriptor does not establish emptiness. Views enter
the local completed inventory only after their ownership operations succeed.

A short guarded transition publishes an immutable manifest over admitted views and one executable
definition epoch. Handles bind semantic/realization identities, publication, exact view set and
service generation. Captured bindings are validated and ordered by their logical binding keys
before marker serialization, so fresh physical attempt IDs cannot change an equal manifest's bytes.
Definitions are installed under immutable epoch names. Ordinary publication
cannot install DDL, mutate unrelated content or replace another publication's functions. Selection
remains explicit. Later cleanup failure preserves an acknowledged committed publication.

### §6.3 Schema evolution

**Design-phase evolution Implemented / campaign cutover Tested, 2026-10-12 (ADR-0161).**
Current consumers use one current physical format. Prefer practical migration into that format;
otherwise explicitly regenerate named views from pinned inputs under the actual quiesced owner.
The completed format3→4→5 transitions remain dated evidence, not retained runtime readers,
converters or overlays. There is no requirement to reproduce those historical examples before
assessing a future design. Any future migration needs a concrete current consumer and bounded
transition, with obsolete code/data removed when its purpose ends.

Ownership and truthful recovery constraints survive: bind the exact installation and candidate,
fence new work, drain actual executors before replacing state, keep interrupted outcomes unknown,
and establish current definitions and content before opening admission. Neither a marker change nor
local child exit establishes remote completion. The dedicated campaign's main/validation scopes
were explicitly discarded and regenerated, then checked before reopening admission. Its immutable
local disposition preserves the interrupted original outcome as Unknown; the generic receipt consumer
does not depend on the retired one-off producer, old checkout or current executable fingerprints.
Shared/operator state and separately paused qualification remain unchanged. A future actual
retained consumer that cannot regenerate requires its own migration decision rather than silently
retaining an old-format runtime path.

Index application may use execution-only concurrent construction without changing canonical schema
identity. Catalog presence alone does not establish usability: every desired index, including one
present on a retry, must report terminal readiness before installation advances. Unknown/error states
keep admission closed. The known3.3.0 executor timeout-stack defect requires a narrowly patched,
exactly identified server generation; batching alone is not a server correctness fix. Source, locked
build recipe, patch and executable provenance belong to the existing native executable owner; PSE
assets remain external and unchanged. Runtime limits and compiler/test parallelism remain unchanged.

**Implemented physical lowering / focused Tested, 2026-10-09.** Fixed top-level SCHEMAFULL fields, unique indexes and enforced role edges remain database obligations. Flexible semantic object bodies and supplied scope fields are produced by selected declaration-derived adapters, preserving missing/NULL, bytes/text, local sums, originals and aliases. Complete independent expected-row reconstruction rejects extra envelope/body/scope content and coherent corruption. Standalone arbitrary raw-SQL body rejection is deliberately lost; supported ingress and exposure remain fail-closed. Physical definition identity changes together with DDL and lowering; semantic artifact/contribution formats remain unchanged.

Typed declarations and explicit canonical codecs own contracts; Arrow IPC/container bytes and
engine coercions do not define semantic identity. Snapshot changes are explicit migrations;
codebooks remain append-only. Rebuild fresh from pinned inputs without old-format readers, legacy
IDs, dual writes or rollback/runtime archives. Quiesce actual readers before replacing their state.

> Decision: ADR-0161, ADR-0145, ADR-0087, ADR-0048

### §6.5 Services and capability adoption

**Accepted target / implementation in progress, 2026-10-09 (ADR-0145).** One stable local
SurrealDB3.3 RocksDB service serves main and validation. Host state and coordination live outside
checkouts. Install/check/status/maintenance distinguish observation from privileged mutation;
maintenance excludes borrowers and requires actual drainage plus identity revalidation. No fixed
memory, compiler-job or test-thread limits are selected. Embedding and optional portable-product
caches use distinct tables in the same configured database. Exact consumed vector winners remain
canonical content and cannot depend on mutable cache survival.

Native graph/documents/functions/search/bulk operations are selected. Query planning tools are
available for concrete uncertainties, not mandatory per-operation accounting or adoption proofs.
Custom APIs, buckets, reactive enrichment, connectors and external exporters require a named
consumer. Historical runs/operation records are retired rather than reconstructed as another service.
The [operator runbook](../../surrealdb.md) documents configuration, publication and explicit selection.
Operator reconstruction, live vectors and activation belong to separately authorized Q1 work.

> Decision: ADR-0145, ADR-0073, ADR-0150
