## 2. CC01 — exact readiness before concurrent execution

### Construct exact inputs independently of arrival order

gate. Serial execution presently supplies the prefix cutoff. Deleting group edges alone would let
a later owner contaminate an earlier prefix.

view set. Existing `CompletedView` contribution inventories, exact source snapshots and protected
native selection machinery supply the representation. Bind ordered input roles, relation, requested/
resolved boundary, profile/model/configuration and exact dependency closure; names alone do not

Identical rows coalesce under the existing contract; equal-key unequal payloads refuse; all required

of ready execution.

## 3. CC02 — provider cancellation and preparation decisions

### Transaction-local cooperative cancellation

The adapter's cancellation flag and `ProviderDrain` already preserve joining ownership. They do
not currently interrupt Pyrefly's queued work. Prefer the pinned library's existing
`State::cancellable_transaction()` and `CancellableTransaction::run -> Result<(), Cancelled>`
over a fork API patch or ignoring plain `Transaction::run`'s discarded cancellation result.
The exact fork `63cda076956013cd0bd1d0d05c785f747fe6adc0` supplies Exports/None defaults and
AsRef/AsMut access to the same transaction (`state.rs:3455–3481,3630`), matching current setup.
The shared python-analyzers skill is discovery guidance; that exact source is decisive.

Register its handle with the existing provider-run cancellation owner under common synchronization.
Registration after cancellation immediately signals the new handle; cancellation after registration
signals it. A scoped generation guard removes only its own registration. Keep it across initial and
dependency waves, reject a cancelled run before querying/emitting completed facts, and check the
same cancellation around later lazy queries/context operations. Never reset/reuse an interrupted
transaction. Active callbacks may finish; no hard cancellation-latency bound follows. Join all
workers and settle accepted ingress before releasing the run owner.

**Acceptance:** registration-before-cancel and cancel-before-registration; dependency-wave cancel;
cancelled results cannot become complete/empty facts; surviving peer ownership and accepted ingress
remain settled. Independently retain the cooperative limitation for already running opaque queries.
