## 3. Combined design and intentional changes

The workload is a complete pinned release with many fact families, sparse and dense demand,
overlapping closures, highly connected graphs, concurrent attempts and interrupted consumers.
Use normal available parallelism. Choose a credible full-operation route, including preparation,
failure and retirement; refusal alone does not establish fitness for supported input.

Stable scope metadata must not force acquisition of unused providers or full contextual adjacency.
Actual demand selects native frontiers or reusable set preparation under exact dependencies.
Independent ready producer work must progress under joined ownership while one coordinator still
integrates results and publishes in required order. Shared Base inputs retain per-root universes
and once-only mutable production. Summary retains exact finite/partial meaning while its candidate
work is assessed independently of queue admission.

Native windows remain atomic. Their authorization, participant cut, payload, outcome and references
should use the fewest independently necessary stages. Removing split intent is conditional on
the RN00 decision; it is not permission to infer noncommit from absence. Lifecycle writes follow
actual predicate changes, including new holds over equal bytes. Established immutable premises
survive internal preserving reads under actual held ownership. Backup metadata reuse stays inside
one exact snapshot, whose transaction ends before independent local carrier work.

**Approved mutation scope, 2026-10-16:** operation-held immutable views assume controlled writes
through application protocols. Privileged direct edits are maintenance operations requiring
quiescence and rebuilding affected state; detecting arbitrary administrative edits during a live
read is not a supported guarantee. This does not weaken independent incoming-data admission,
malformed-input rejection, stale epoch/incarnation checks, legitimate concurrent changes, cross-owner
protection or physical finality. RN03 must document and enforce the actual controlled-write boundary
before removing checks. No new permission bypass is authorized.

Demand-shaped production intentionally changes when unused input failures become visible.
Independent admission still checks its complete declared domain. Joined execution can change
completion order, but not semantic integration order, dependencies or required failure/drainage
behavior. Root batching can change preparation timing, but never replay already-mutated roots.

Prefer refinements of existing native/Rust/DataFusion owners over another backend, permanent proof
cache or workflow engine. DataFusion handles set joins/order/spill; native indexed frontiers handle
selective persistence; Rust kernels own model semantics. Larger transport batches alone do not
remove repeated server work. Whole-compilation transactions broaden retry and live-state scope and
are not the target. Exact library qualifications and alternatives remain in the runtime review
and its [library evidence](../design_review/evidence/2026-10-16_catalog-runtime-efficiency/library-evidence.md).
