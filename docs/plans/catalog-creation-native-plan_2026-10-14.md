# Catalog creation: native validity, completion and transport

**Proposed target refinements / inherited source foundations, 2026-10-14.** Companion to the
[coordinator](catalog-creation-plan_2026-10-14.md), whose §6 alone owns dispositions and receipts.
Develops creation F03, D02/D10–D12 and the remaining CP00–CP04/CU01–CU03 native obligations. New
same-operation semantic/search reuse is distinct from existing integrated F03 source inventory reuse.

## 1. Authority and physical boundaries to preserve

There are three operations: independently complete/protect a contribution; select an exact internal
view under that live operation; earn an independently retained/frozen boundary when a different
lifetime, admission, publication, backup or cold consumer requires it. Logical views/bindings and
explicit empty outputs remain semantic contracts, not mandatory per-relation physical member copies,
seals or full identities. Independently retained selections still earn complete authority.

Current compound completion v2, schema8, semantic format4/six-family v4, outer transport codec1 and
publication/handle v3 are integrated foundations. They are not new migrations this plan claims to
perform. Preserve actual positive incarnations, full descriptors/bytes, exact selectors, live
client/session/pin/generation/validity/resource-pool ownership, independent admission and complete
terminality. Neither descriptor equality, a digest, cached future, serialized receipt nor a borrowed
reader grants another physical copy's authority.

Private contributions feed exact native membership/indexes; internal providers/checkers borrow earned
selections. Retained products/publications protect exact compound contributor/selector inventories.
Fresh serving/sparse access, candidate/original hydration and backup use their protected reader pins;
data-only/import/cold paths independently earn physical and semantic authority. These ownership classes
must not collapse when improving reuse.

## 2. CN01 — private executed scoped validity

Early normalized `CheckedInputs` retains exact selections/attempt/policy, but its checks currently
run with `earn=false`; final private `CheckedSemanticScope` is built with `earn=true` and reruns
specialized checks. `AdmissionMemo.checked` is a charged set of premise digests, not per-invariant
executed evidence. Merely enabling that memo shortcut for final earning would be unsound.

Let the existing admission owner retain a private successful individual check only after genuine
specialized execution, required ordered input/EOF, failure/refusal handling and terminal completion.
Use the existing ordered selected-role and `CheckedValidationPremise` contracts as a starting point,
without routing scoped kernels through the whole-input replay driver. Final admission assembles
eligible unchanged executed checks plus fresh checks for new/changed applicability. Do not retain
an entire earlier semantic scope as blanket proof: final bindings and applicable checks can grow.

Eligibility consumes the actual operation owner and complete ordered input roles, exact views/source
snapshots, requested/resolved epochs, model/profile, invariant revision/definition, executable factory,
explicit NotRequested premises and any companion/compact/uniform-owner dependencies. Include absence,
removed/added inputs and complete-empty applicability. Identity data is necessary but not sufficient:
the same actual protected operation/source lifetime and valid physical premises must still exist.
Source closure, uncertainty, changed incarnation/context, wrong pool or failed finality defeats reuse.
Charge retained evidence/keys/capacity through actual borrowers; failed/cancelled prefixes publish none.

Reference closure preceding the memo shortcut has its own exact pair/input premise; assess it
separately rather than claiming per-invariant reuse removes all reference work. Final freeze still
compares current native ownership/inventory with handed-off owners. Facts coverage, changed/new
cross-relation constraints, selected vocabulary, frontier, canonical graph derivation, original/manifest
inventory and actual physical completion remain independently established where their premises differ.
Cold/import/foreign/receiving operations start with no same-run authority and execute their necessary
admission. Trusted persisted whole-input reuse keeps its existing separately earned contract.

CC00 fixes exact input/owner policy before CN01 implementation; CC01 can retain a normalized admission
barrier while this is built. Approved RC02 changes the conservative scope exclusion/fresh-earning
policy, not the requirement for real executed production gates or private admission construction.
Amend the architectural owner/ADR rationale before dependent implementation. No durable second proof
store or portable success grant is selected.

**Acceptance:** an unchanged scoped check executes once and contributes genuine final evidence;
changed ordered role/view/model/factory/compact owner/NotRequested or companion premise reexecutes or
refuses. New applicable checks cannot be omitted. Empty applicability requires actual complete-empty
declared roots. Failure, cancellation, late error or closed owner yields no reusable success. Final
actual membership/original/graph corruption still refuses, and detached admission remains independent.
Use independent expected validity cases rather than only comparing two calls to the same validator.

## 3. CN02 — expected search and lexical runs through finalization

The ordinary publication path lowers seven ordered expected-search families, writes/reconciles actual
rows and discards preparation; final staging independently lowers the same expectations again.
Lexical statistics separately prepare four ordered families from selected documents/native analyzer
results, then reconstruct them on final reconciliation. They are not independent semantic oracles
merely because the same lowering ran twice.

Retain both preparations in a private publication-owned prepared-search lifetime from successful
materialization through final seal. Use existing SortedRows/OrderedRows/PreparedRows memory/spill
backing and independent cursors, not a global cache or durable truth store. Reconciliation consumes
cursors: rewind or obtain independent cursors before a second comparison and before expected-child
inventory construction. Avoid a consumed cursor masquerading as complete-empty expectations.

Bind actual publication/Loader/admitted-input/incoming-hold/session ownership, protected source
lifetime, selected views/realization, staging root/incarnation, service generation/validity context
and actual resource pool. Content eligibility includes model/physical schema, native/publication
implementation, executable definition epoch, lexical analyzer policy, vector/encoder/projection/recipe
and lexical scope identity. No metadata tuple independently authorizes the borrow. Native analyzer
observations used in lexical construction must remain under the same immutable definition context.

After ordinary writers drain, compare against fresh actual search and lexical rows to complete EOF:
full serialized content, missing/extra/duplicate/foreign/corrupt rows and native terminal drainage.
Then reconcile complete expected children/inventory roots and final revision/context CAS before
publication visibility. Acknowledged publication identity remains distinct from later cleanup failure.
The write transaction, freeze/finalization and actual reader pin are not replaced by expected spools.

Foreign/cold publication/audit has no same-owner preparation and must derive expectations independently.
Keep those supported entry points explicit; do not select the retained route from a serialized label.
Existing `Publication` already owns the admitted input, Loader, incoming hold and session guard across
`materialize_search`→`seal`; extend that lifetime rather than creating another lifecycle manager.
Reservations/spill runs survive through the last actual comparison and owned cancellation/drainage.

**Acceptance:** mutate a search or lexical row between construction and sealing and observe refusal;
also exercise missing/extra rows, late transport failure, changed definition/analyzer/input/pool,
consumed/rewound cursors, cancellation and final borrower cleanup. A fresh owner must reconstruct.
Independent final actual-state checks remain demonstrably live. No benchmark establishes correctness.

## 4. CN03 — finish inherited native and consumer scope

### Canonical preparation and family dependencies

Preserve the existing prepared logical frame runs and non-consuming ordered union. Normalize native
IDs before sorting; use RecordId::Ord and unchanged v4 JSON payloads/count tagging. Equal key/equal
payload coalesces, equal key/unequal payload refuses. All required input EOFs and final folds precede
complete identity. Fragment digests do not concatenate into the v4 union. Memory/mixed/spill inputs
remain reusable after success or failure; charged multiway/balanced merge follows actual head/buffer
reservations, not a worker cap. Do not decode/re-encode/resort unchanged fragments unnecessarily.

Complete family dependencies remain distinct: full normalized contribution descriptors/outcomes/
assurance; exact selected-copy membership runs; referenced backing/full bytes; complete view/empty
descriptors; exact bindings/roles; selected aliases and composed reachability. Logical contributor
IDs alone do not authorize reuse, and changing a binding need not rebuild unrelated families.
Different selected sets still need their genuine ordered union/fold. Blob byte observation may be
shared only under its protected exact incarnation, while every source/layout/range association remains
checked. Failed shared workers evict only their token; one cancelled waiter does not invalidate an
independently owned peer. Worker/map/tree reservations follow their actual retained owner.

### Actual protected source and independent receiving

Integrated native F03 already borrows observations from the actual live source audit under exact
client/pin/generation/validity/pool correspondence. Missing observations use registered first-miss
workers; cached mechanical selections retain their small real guard, not a descriptor authority or
scope cycle. Source close prevents delayed broad/field/key/empty/sparse queries. Borrowed close owns
its operations/cache, not shared source-pin/session release. Independent receiving readers retain
their own earned pins and may survive source abandonment.

The admitted hold may share the exact opaque physical owner's charged inventory under fresh original
parent full-byte/incarnation/frozen-owner/admission checks. Every selector retains complete domain,
mapping, membership and composed alias proof. Fresh new-parent acquisition, independent retained pin,
complete child/incidence inventory EOF and final parent revision/context CAS remain mandatory.
Receiving guarded child fetches occur once; ordered actual parent holds compare directly to expected
cursors. Data-only/foreign/cold factories start fresh. This is an existing correction, not CN01's new
semantic-check capability or CN02's new search preparation.

**Outstanding acceptance:** real opaque-source positive reuse; foreign-owner/pool and closed/fenced/
changed-incarnation refusal; first-miss failures/overlapping flights; source-close during actual read;
guarded receiving pointer/parent-hold completeness and late finality; current-source independent cold
restore and actual Catalog composition. Earlier pure5 and cold1586b7 do not replace these controls.
If a control exposes a real migration gap, repair it in this package; do not expand into unrelated
older campaigns or weaken the asserted meaning.

### Bounded windows, aliases and mutation

Record/guard/hold assurance uses actual bounded indexed identity-correlated set queries. Optional
absence stays None; missing required record or invalid/missing guard refuses. Heterogeneous hold IDs
share the production derivation and verify exact owner/object/incidence, not counts or Cartesian
owner/object queries. A read window never authorizes an unchecked later CAS. Per-key flights retain
unjoined workers across cancelled close; a retry cannot release the audit pin ahead of accepted work.

Directed alias adjacency/frontier operates over the exact selected contributor closure, including
cross-contributor paths. Independent audit rejects unreachable owned source aliases. Preserve cycles,
multiplicity, target identity and per-selector scope; aliases in the enclosing union do not grant a
wider selector. Retain compact adjacency for fitting inputs and existing sorted/indexed windows for
larger inputs with charged frontier/visited/spill. No whole-heap graph refusal replaces a supported
ordinary route. Empty alias EOF may avoid unnecessary seed/index preparation after local integrity.

Keep conservative typed full-content recapture (IF04). Generic expected-object revisions and incidence
touch predicates protect different races; deleting a touch is not an equivalent replay specialization.
Real creation, retirement/recreation, inactive/changed incarnation and maintenance invalidate the
appropriate premise. Cleanup root nomination consumes exact object/incarnation and incoming hold,
with current guarded atomic nomination/release; benign unrelated guard churn is not a different
nomination identity. No unapproved fencing rewrite follows these narrower existing predicates.

### Exact transport, restore and physical consumers

Preserve semantic format4/v4 independently of codec1 root-qualified transport. Codec1 binds full
root/dependency descriptors, ordered dense copy labels, complete per-copy member/local-alias inventory
and explicit zeros. Distinct equal-descriptor copies survive. Eligibility separately ignores incidental
physical labels/sharing but preserves complete root/view/contribution/alias meaning; equal-v4/different-
eligibility publications can coexist. Actual incoming and winning boundaries are checked.

Checksum-only callers use the direct six-family fold, not portable encoding. Export requires frozen
or independently retained read-only authority; read admission, AuditCapture or wait_scans is not a
freeze. Prepare the portable stream once, independently fold actual emitted logical content and compare
it with the boundary. `CompletedTransportReceipt`, artifact and backup receipts are expected data,
not admission authority; return them only after checked EOF/delivery/fsync/finalizers. CLI import and
restore require independently supplied `--expect-receipt`, never trust incoming headers/sidecars.

Restore retains dump-owned demanded source/blob metadata and collision-checked ordered indexes rather
than repeated per-ID table-spool scans. Complete required validation still covers unretained duplicate/
foreign rows. Fresh destinations allocate actual copy-discriminated native contributions, endpoints,
alias/dependency holds and independently earn incoming/installed physical and semantic authority.
Selected backup remains a coherent transaction over exact pinned input/binding/original closure and
marker/inventory/incarnations; its bounded data-only SQL carrier is parsed, never executed. No source
attempt/pin/guard/selection is imported authority, no first-logical-copy or global-alias fallback remains.

Preserve corrected units: protobuf complete request/intent bytes versus wire limit; native row width
versus declared64MiB physical-row bound; unchanged32×+64KiB workspace reservation versus actual pool.
The maximum control's256MiB source/8MiB prepared consumer does not promise cold8MiB or whole-process
memory. Actual owned decode arenas transfer into sorters without double reserving; retained spill/input/
output reservations remain live. Current enclosing64MiB/native results retain their dated limits.

All actual provider/normalization/checker, frozen/admitted/published, retained product/recovery, sparse
reader/original/alias, selected backup and cold/import consumers must retain these contracts. Replaced
per-view member copies, old codecs/readers, stale fields and compatibility-only helpers stay removed.
Current source already migrated most paths; do not reinstate them as intermediate substitutes.
Workspace/artifact shared execution ownership retains native calls, spills/provider joins/cache and
the original completion signal through last operation; a borrowed seal/export does not implicitly
finish the enclosing owner. Unknown remains protected until actual reconciliation/drain/disposal.

## 6. Focused acceptance and completion

Keep independent literal canonical roots/streams, reordered physical IDs, explicit empties, unequal
duplicates, byte/null distinctions, late-error/cancellation and spill/reservation cases. Retain shuffled
set correlation, missing/foreign/extra guard/hold, before-CAS incarnation change and cross-contributor
alias/cycle/disconnected cases. Exact root-port consumer tests remain independent of topology output
selection. Failed preparation/transport publishes no reusable capability.

Current cold acceptance must retain strict physical source absence, two genuinely independent fresh
receiving/admission owners, exact receipts/eligibility/original bytes and no operator selection. Round
trip agreement through only the same producer normalizer is insufficient as the sole oracle. Earlier
maximum/v4/receiver tests rerun only where changed contracts or unresolved current coverage require;
the optional full16-compilation cache matrix is not imported as a gate.

CN01/CN02/CN03 deliver working migrated consumers and focused evidence, not just interfaces or pure
models. CO01 adapts actually changed generated definitions/diagnostics with the same slices. CX01
tests complete fixture composition; CX02 tests pinned FastMCP; CX03 regenerates useful owned current
state. Neither native source acceptance nor successful host cleanup closes those exits by association.
