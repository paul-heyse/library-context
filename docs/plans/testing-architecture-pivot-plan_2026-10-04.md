no adapters or database; provider/compiler controls prepare the native APIs they actually use;
native effects use owned authenticated persistent RocksDB fixtures. Reuse a complete immutable
read-only fixture only for compatible cases with fresh request/guard/resource state. Mutation,
corruption, lifecycle and concurrency controls own isolated state and cleanup. Nextest process
isolation does not share a static fixture between separate test processes. No global fixture
server or persistent assertion cache is required.

Prepare the union of selected Python/native prerequisites once before workers start. Retain
content/membership readiness, stable Cargo paths and cached release builds; use `--no-sync` during
controls and never synchronize beneath live native workers. Cancellation retains owned resources
until actual work drains. Independent authored expectations challenge semantics; same-provider
CLI parity challenges driver agreement; generated schema checks challenge lowering. Observation-only
or mocked results never qualify actual producer/served fidelity.
