## 3. Complete admission and completion contracts

### 3.1 One complete operation outcome — F01

`lctx-model` owns a library-neutral completion outcome/composition operation; effect owners still execute their own cleanup. The operation consumes the primary result and explicit outcomes for all owned finalization steps. It retains the original structured cause, secondary drain/cleanup errors, whether local work is terminal, whether remote effects are known, and whether private storage was removed or remains an unselected orphan. A failed completed join is not a still-running task; local quiescence is not confirmation of an ambiguous remote write; session invalidation is not writer drainage.

On primary-only failure, retain that failure category. Cleanup-only failure cannot produce success. Simultaneous failures preserve the primary cause and all relevant secondary failures without replacing them through `?` order or concatenating strings as the semantic representation. Formatting and existing CLI/serving error projections derive from this outcome; preserve sanitized public failures and keep private resource identification in operator diagnostics. Successful completion returns the ordinary value only when the operation's required finality holds. Record already committed effects separately: a sealed fresh database followed by staging-cleanup failure remains sealed and unselected; a persisted backup followed by parent-sync failure remains published with uncertain durability. Neither error implies rollback. CLI exits unsuccessfully and retains the owned handle/path and cause chain in diagnostics without automatically retrying. Public serving projections recurse to a primary typed failure when present, retaining ResourceRefused/Incompatible/Corrupt distinctions; completion-only failures map to the existing sanitized Unavailable outcome. No new public wire fields or secret-bearing errors are required.

Use ordinary data/functions within the existing dependency direction, not a generic retry service or cleanup runner. Awaiting effects stays with the workspace, native attempt, publisher and CLI. Drain handles remain owned across cancellation and a subsequent drain; resources and scratch cannot be released while acknowledged work is outstanding. A drain report must distinguish local terminality from stored native uncertainty. Unknown acknowledgement fails the disposable attempt even after local tasks finish; it never authorizes publication.

Migrate construction and finalization siblings together: compiler setup and CLI compile; facts inspection; artifact import CLI; publication begin/publish/abandon; backup finalization; restore import/copy/cleanup; and native attempt initialization. Include failures before a Workspace exists. Preserve cleanup's underlying failure as well as orphan identity. Remove locally competing outcome composition, without moving workflow-specific cleanup effects into the model.

### 3.2 Captured suppliers bind a declared semantic contract — F02

Reading the declarations does not construct executable providers, acquire inputs or use sentinel configurations.

Each supplier role declares its recognized tool/analyzer revision, an adapter/fact semantic revision starting at1, coverage meaning and configuration binding. Revision1 describes the current pinned producer semantics; a semantic change deliberately advances it at that declaration. The supported contract is explicit metadata checked by admission, not a claim that arbitrary executable bytes have been proved equivalent. An executable binding adds current implementation/build provenance, effective settings and concrete provider identities. A captured binding persists the exact producer contract identity/revision, role-to-provider mapping and configuration/source bindings with its contribution. Coverage roles are not necessarily one-to-one with stages: the Pyrefly stage's independent Ruff observations retain their distinct supplier. Configuration semantics distinguish producer settings, captured analysis-context configuration and fixed contract settings at their declaration owner; no central stage-name exception list interprets them.

Missing, extra, ambiguous or contradictory suppliers and outcomes reject. Keep the profile plus all nine exact completed view premises; changed attribution/context/membership invalidates reuse even when payloads appear equal. ## 5. Whole import units in bounded requests — F06

The pinned parser continues to own statement boundaries, initial import-option admission and whole transactions. Separate `next_unit` from request aggregation: each unit supplies serialized SQL plus its actual statement count, including transaction control statements. Preserve rejection of nested/incomplete transactions and duplicate/noninitial request modes.

Use existing limits: target 8MiB (`TRANSFER_BYTES`) per request and at most4096 payload statements (`TRANSFER_ROWS`); preserve the4096-statement transaction bound. Include prefix and separators in byte accounting. A single indivisible unit above8MiB travels alone only if the complete serialized request fits the existing64MiB (`MAX_ROW_BYTES`) hard bound. Otherwise refuse before submitting it. Do not split transactions or increase query/transaction deadlines. These are physical bounds, not a guarantee every request finishes within a deadline.

Aggregate contiguous units in order, retaining at most one whole lookahead unit. Avoid retaining a complete AST batch plus a duplicate serialized batch. Reuse one tempfile, prefix each request exactly once with `OPTION IMPORT;`, and await checked HTTP import completion before the next request. Keep HTTP import semantics; `/sql` is not an interchangeable transport. The SDK waits for the response and rejects returned statement errors but reports the first returned error, not an aggregate of all statement failures.

Accepted RC02 permits later independent units in the failed request to have executed. Submit no later request. Preserve the first observed import failure and all relevant session/drain/staging cleanup outcomes through PC1. Never publish failed staging. Reconnect/cold validation and independent reconciliation still follow successful import; import mode bypasses field processing, so request success does not prove valid stored derived values. Whole restore also needs PC2's new captured bindings and PC3's rebuilt definitions.
