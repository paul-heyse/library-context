## 1. Native role, baseline and preserved capabilities

At baseline`9c457a0c`, ordinary completed artifacts are actual NativeCompilerStore/view owners.
The [review](../design_review/reviews/design_review_catalog-execution-speed-comparative-target_2026-10-18.md)
shows both real improvements—nongraph packing, operation-root pages, indexed set readers—and
remaining physical/control amplification. It corrects the external claim that every current page
has a generic apply/settlement transaction. Build on current capabilities rather than implement them again.

Native storage remains canonical durable content for all explicitly requested frontiers, complete
originals/graph/evidence, useful cross-attempt products and pinned publication/serving consumers.
The private compiler source is not a native view, lease, receipt or admitted artifact. Native
materialization creates authentic target ownership and independently establishes physical content,
selection and finality. A private metadata/property demand need not persist every intermediate
payload that happened to help compute it; required final artifact closure decides durable content.

Use actual locked SDK/core/protocol patches and library capability skills. Set access, existing
operation pages, bulk mutation and indexes are useful only if full equality, atomicity, snapshot
isolation hazards, stream EOF and remote terminality fit. No database replacement, universal
transaction framework, permanent duplicate store or benchmark harness is selected.

## 2. SN00 — Separate semantic validity from actual native/incoming assurance

## 3. SN01 — Coarse bounded packets and exact native hazard coverage

**Consumes:** SP00 RC03/physical scope, actual native effect/lifetime owners. **Delivers:** validated
whole-operation packets and set observations that reduce per-kind crossings without losing protection.
It can improve current native boundaries before the full private compiler migration.

Prepare compatible graph payloads, endpoints, aliases, memberships/locators, original references and
required holds/incidence together. Preserve genuine dependency ordering inside the operation rather
than separate network calls for every physical category. Group small tails and metadata-only empty
domains where meaningful; keep declared zero-row semantic contributors and exact identities.

columnar backing cannot silently replace their identity, multiplicity or evidence.

Size by actual transfer bytes and admitted expanded working set, with necessary row/protocol bounds.
Do not replace a conservative reservation multiplier with an unmeasured memory claim. Prepare exact
record→guard/incidence correspondence once; preserve full typed record identity and first-match/
duplicate behavior. `array::find` inside every target map, other repeated membership tests and scalar

Current `OperationWriter` records an exact root, page identity, payload/prefix and terminal outcome.
Preserve it for real accepted effects. Successful pages already avoid per-page generic host settlement.
Trace remaining generic effects by actual owner and only coarsen their journal/settlement unit when
that covers their recovery duty. Bounded native staging may need multiple transactions; a final
manifest commit does not imply one giant data transaction. Producer prefix ordering may remain
necessary even when independent preparation or contributions run concurrently.

### Contention and protection decision (I02)

Inventory actual shared write keys/predicates for retained native work: attempt stripes, guards,
completed parents, holds, membership and collector/definition hazards. Use actual key/class and
query/operation observations if source does not settle the exposure. Retained trace retries identify
contention, not exact mutual conflicts or removable time. Keep exclusion where its protected predicate
can change, including equal-row admission, first creation, new hold versus retirement and late writes.
Reader pins and immutable payloads do not by themselves cover every hazard.

Choose narrower incidence/striping or shared prepared protection only with a complete replacement
argument. Native snapshot engine behavior, unique collisions and write-skew need exact version/target
qualification where uncertain. No extra cap or arbitrary larger deadline resolves the design.
A bounded retry policy must distinguish confirmed no-op/refusal, committed and Unknown, retain the
original idempotent request and await actual issued-query terminal/reconciliation before returning.
Do not cancel an in-flight transaction to force a supposedly clean timeout.

### Additional existing set-read opportunity

`complete_block_original_holds` currently gathers32 IDs but reads each block separately
(`compiler.rs:6400–6423`). `control/held.rs:480–495,540–589` already reads row/guard point sets.
Use byte/resource-admitted batches, preserving every block validation, incarnation/guard observation
and exact `(block,original-layout)` association. Thirty-two deep blocks can exceed reasonable live
workspace because each observed row has its own expansion charge. Split an effect-free local batch
only after its readers are drained; never replay a partially accepted native effect as preparation.
Set observations are not a coherent snapshot or unchecked attachment authority.

**Focused closure:** equal/unequal payloads; native graph/locator identity; mixed existing/new predicates;
empty outputs; missing endpoint; guard collision; new foreign holds/collector race; concurrent disjoint
and conflicting packets; original-block association; partial accepted prefix, refusal, cancellation,
