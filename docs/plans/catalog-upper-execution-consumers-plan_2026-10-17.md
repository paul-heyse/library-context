# Catalog upper execution: sufficient inputs and indexed consumer windows

_Date: 2026-10-17. Target maturity: Proposed. Execution state: Open; no implementation or functional verification is claimed by this document._

## 1. Responsibility and basis

This companion implements the consumer preparation corrections F05–F09 and investigates I03 and the window-representation portion of I06 in the [upper-execution review](../design_review/reviews/design_review_catalog-upper-execution-performance-target_2026-10-17.md). The [coordinator](catalog-upper-execution-plan_2026-10-17.md) owns the combined target, shared contracts, prerequisites, rule decisions and sole §6 disposition ledger. This document defines UC01–UC05; it does not create a second findings status register or supersede existing plans.

The intended result is that consumers acquire sufficient immutable properties once where they share exact dependencies, and hydrate rich selected inputs through exact bounded windows. Sharing preparation never grants another owner's domain, result, admission or publication authority. Completion means migrated functionality and focused revealing controls, followed by the coordinator's UE90/UE99 integration and handoff. Full Catalog campaigns, assembled qualification and quantitative benefit measurement are outside this plan set's endpoint.

Baseline inspected: `d37a14add3e18d6a101aa4710dcd279b5445e896`, 2026-10-17. Governing owners are [semantic model §15.1](../design/sections/semantic-model.md#section-15-1), its native/independent-admission contracts and [storage and publication](../design/sections/storage-and-publication.md). Core 3.3, efficient-architecture heuristics 1.0 and code-intelligence profile 1.5 apply. FP-07/A4, DP-10 and H7/H9/H12/H15/H16 favor removing repeated decoding, scalar queries and whole-window filtering while preserving model authority, exactness and actual ownership.

## 2. Existing foundations and target interaction

The following mechanisms already exist and should be extended rather than duplicated:

- `cpg-core/src/consumed_rows.rs::stream_artifact_admission` obtains the model-owned artifact properties used by expected-domain admission. SourceArtifact contains identity/path/hash/length metadata, not source text. F05 does not diagnose repeated source-text scans.
- `AnalysisUniformInputs` distinguishes common expected-domain preparation from owner-specific roots, definitions and ordered source snapshots. Today `compilation/uniform.rs::produce` rebuilds and fully decodes that preparation per invocation, with view deduplication and exact EOF checks local to that invocation. Seven Catalog behavioral owners use it; conditional unrequested Embedding/Analytic paths also use the same dispatcher.
- C0 `catalog_core.rs::load_metadata` declares all `CatalogData::validation_inputs`, streams rich catalog inputs and retains only expected-domain properties plus definitions, method parameters and provider runs. Its later public-root windows already hydrate the actual rich premises. Removing discarded reads is useful without first building shared metadata.
- `analysis_prepare.rs` and model `analysis/native.rs` collect a charged native inventory before writing. The finite inventory declares 75 assertion/support pairs; profile filtering and assertion-family presence determine actual reads. Catalog excludes Flow families. Native assertion, support and qualification validators remain their semantic owners.
- `lctx-compiler-store/src/scoped_positions.rs::IndexedRootColumns` already binds exact root membership to charged Arrow backing and gathers physical row positions while preserving duplicates and source order. SourceCall, Enriched and Models use it. PreparedEdges terminates cyclic discovery over compact adjacency and retains exact root partitions.
- Retrieval already discovers a bounded root window and hydrates each relation's selected union once. Its remaining costs are scalar root/subject header queries, partition-by-relation membership queries and a repeated scan/filter of every union row per root. Its allowed-type, artifact, text-range and brief predicates are stricter than graph closure.

The chosen composition has three separate products: protected exact input eligibility supplied by native/admission owners; immutable model-owned sufficient preparation; fresh consumer-specific domains or selected rich partitions. Conceptual product names do not mandate a new crate, framework or persisted type. Use existing typed declarations, property routes, charged preparation and indexed positions. Native batching, ordering and query semantics are not redefined here.

### Shared validity and resource boundaries

Consume the coordinator's shared contracts before changing their interpretation. A reusable preparation is eligible only for the same complete profile, selected immutable views and epochs, typed port/prefix/namespace, relevant context, model/vocabulary and definition dependencies, and actual operation/resource owner. Include any additional dependency discovered by authoritative predicates; nominal IDs alone are insufficient. Different source ordering remains available separately to each consumer. Cross-owner sharing requires exact compatibility; it must not create a union of unrelated domains merely to raise cache hits.

Build on demand and publish only after complete checked traversal, exact row/EOF accounting and all required predicates succeed. Failed or cancelled preparation is not a successful cached prefix. Immutable backing, indexes and borrower outputs retain their reservations and source protection until actual last use and joined cleanup. Shared ownership must not charge only the first borrower and then release while others still read. Reserve transient projection/query/gather allocations as well as retained state. Do not add a global rich cache, whole-library rich union, nested pool, arbitrary thread cap or deadline increase.

Property reuse preserves independent receiving: exported/detached or otherwise independently received content must earn its own checks under that receiving owner. A property valid in one checked immutable view is not a persisted universal proof. The [native plan](catalog-upper-execution-native-plan_2026-10-17.md) owns protected acquisition, lazy logical preparation, retries, originals, grouped agreement and acknowledged blocking execution; these consumers must not implement parallel versions of those responsibilities.

<a id="uc01"></a>
### UC01 — Shared sufficient metadata, fresh compact domains

**Result.** The model declares sufficient input properties for expected-domain preparation and the authored metadata required by uniform owners. Compiler execution acquires compatible exact inputs once into charged immutable preparation, then each owner constructs its own domain, ordered source declarations, empty outputs and total NotRequested outcome. Preparation may share finite common subsets; owner-specific roots, context/policy dependencies and fresh result construction remain explicit. No other owner's result or admission is reused.

**Implementation scope.** Extend existing expected-domain/property operations and AnalysisUniformInputs rather than introduce a second artifact classifier. Migrate the seven Catalog paths Local, Base, Completion, SourceCalls, Enriched, Models and Summary. Inspect and adapt conditional Embedding and Analytic unrequested uses of the same uniform dispatcher: share only matching dependencies, preserving their own domain selection. This neither enables embedding inference nor expands requested analysis domains. Keep provider/definition/method/model/retrieval metadata according to actual model demand. Preserve input declaration reachability, multiplicity/conflict detection, source identities and exact per-view count/EOF checks. The finite common index must not silently collapse prefixed or epoch-distinct ports.

Replace repeated full SourceArtifact reconstruction with the existing model-owned property route, and remove repeated per-owner common preparation once all relevant callers migrate. Do not retain a rich fallback for metadata whose sufficiency is established merely for old callers; retain full acquisition only for a still-required authoritative predicate. Reopen the property contract if a new owner requires a property not captured by the shared product; do not let consumers independently infer it from IDs.

**Focused closure.** Hand-author distinct expected domains for at least two owners over the same exact inputs, including one genuine empty domain and one with model roots. Check fresh owner outputs and ordered source references while common preparation is acquired once. Change context, profile, definition, prefix or view/epoch and verify incompatible preparation is not reused. Include duplicate/conflicting metadata, early/extra EOF and cancellation before complete preparation; no successful result or reusable prefix may escape. Exact domains and qualifications matter, not just counts.

<a id="uc02"></a>
### UC02 — C0 metadata expresses physical intent

**Result.** C0 metadata preparation reads only expected-domain properties and the AnalysisDefinition, MethodParameters and ProviderRun data it actually consumes. Public selected windows own rich catalog premise acquisition. Global completeness/negative-universe admission remains independent of selected positive output.

**Implementation scope.** Separate metadata-demand declarations from rich C0 kernel validation inputs. Preserve typed loader reachability through the declaration/dispatch contract; a loader's existence must not require physically reading a discarded payload. Continue to validate expected metadata and authored definition/parameter identities before C0 production. UC01 may supply compatible preparation after it exists, but UC02 must deliver the discarded-read removal even without shared metadata. Migrate `load_metadata` and its dispatch/finish logic together, removing the catalog-wide metadata read loop and declarations used solely to justify it. Do not narrow the complete public universe, native qualification obligations or negative premises to a selected grain.

**Focused closure.** Use a rich relation irrelevant to metadata whose acquisition is observable and would refuse if requested: metadata preparation must not acquire it. A selected C0 grain that genuinely needs that relation must still acquire and validate its rich rows, rejecting a malformed premise. Independently specify expected public/negative-domain membership and malformed metadata refusal. Verify a sparse selected root does not erase global completeness premises and no extra rich read is hidden in a new metadata wrapper.

### UC03 — Sufficient native inventory properties (I03)

**Investigation decision.** Trace every predicate in NativeInventory, its generated assertion/support adapters and independent semantic admission. For each family establish which properties are already earned on the exact immutable premises, which compact fields the inventory still must consume, and which predicates require rich rows. Settle this before changing `stage_inputs(...).validated_by(...)` or the corresponding reads. Source inspection may settle sufficiency; use a minimal focused native/property control if lifetime or actual read behavior remains material. Stored identity by itself never discharges validation, reidentification, attribution or support integrity.

**Result.** Eligible inventory inputs use model-owned projections of assertion/support identity, assertion qualification, native attribution/fidelity and any additional authoritative property required by the traced predicate. Full acquisition remains for a predicate whose sufficient properties cannot be established. This is a settled safe outcome of I03, not permission to mark F07 closed while avoiding the investigation. Record exact family/predicate coverage and any remaining rich necessity in the coordinator; a discovered contract obstacle becomes a dependent implementation package or explicit finding obligation there.

**Implementation scope.** Keep one finite model-owned assertion/support inventory and its append-only codes. Extend its generated adapters and compiler read path together. Preserve profile/presence filtering, qualification-first dependencies, empty-assumption basis, missing/foreign qualification rejection, assertion/support pairing, native attribution, qualified alternatives and original failure semantics. Collect and validate the complete inventory before declaring or emitting output, retaining no successful prefix after a late support failure. Do not replace original native support validators with consumer-local approximations or manufacture a grant from another operation's evidence.

Retire rich decode/reidentification only where the carried-property contract genuinely replaces that work. Keep deterministic integration; parallel family reads belong to US02 after simultaneous input/work/output reservations and failure ordering are settled. A fresh receiving owner still checks actual received content independently.

**Focused closure.** Compare independently specified exact NativeAssertionPremise and NativeQualification records, including fidelity and original assertion/support correspondence, for Catalog and Behavioral selections. Exercise absent families, multiple qualification alternatives, foreign/missing qualifications, nonempty assumptions, a support targeting the wrong assertion, malformed native attribution and a late invalid support. Corrupt an otherwise plausible stored ID/payload pair and prove the appropriate admission or full-read predicate refuses it. Change the checked view/context and prove properties cannot cross it. Both direct fresh receiving and eligible property consumption must reject their respective malformed inputs before output.

<a id="uc04"></a>
### UC04 — Retrieval's exact filtered positions (I06)

**Result.** Retrieval batches EvidenceRoot headers and then the required RootSubject headers for a window. Compatible partition/relation membership acquisition carries partition identity; rich hydration remains one selected union per relation. Build each partition's physical row positions once from the actual retrieval-filtered membership and gather directly, removing repeated full-union membership masks.

**Implementation scope.** Extend IndexedRootColumns or its narrow internal position builder for already-filtered partitions. Its existing PreparedRootBatch membership is not sufficient when retrieval's allowed types, artifact restrictions, text ranges or brief projection exclude reachable rows. Preserve table/port/prefix/namespace mappings, snapshot epochs, source order and every physical duplicate admitted by the selected relation. Duplicate root requests retain distinct partition outcomes. Batched lookup must retain missing and conflicting header refusal, without inner scalar header or membership queries disguised inside a batch API. Share only query-compatible predicates; carry remaining predicate families explicitly rather than widen them.

Keep context text as context and completion/applicability as their own meanings. Do not let supporting metadata become a root. Retain original bytes and same-snapshot evidence under the native original owner; UC04 cannot replace UN03's range/owner contracts. Remove per-root scalar header acquisition, compatible repeated membership-query dispatch and per-root union-mask scans once replacement tests cover them. Position preparation, retained Arrow backing and transient gathers remain charged; a borrower cannot outlive the exact backing.

**I06 decision criteria.** Inspect overlap, one sparse root and a skewed large root using hand-defined memberships. Choose bounded windows that reuse actual input while respecting complete working-set reservations; retain the existing window policy unless these cases reveal a semantic/resource mismatch. Use a direct single-root form only as the same indexed operation at cardinality one, not a retained legacy loader. No arbitrary concurrency cap or new window-size tuner. Record the selected representation and changed policy, if any, before consumer integration; useful independent computation overlaps through US02.

**Focused closure.** Specify exact expected ordered row positions independently for overlapping roots, duplicate requests, duplicate physical rows, same nominal IDs on distinct prefixed/epoch ports, absent roots and missing subjects. Verify allowed-type/artifact/text-range/brief exclusions and that context-only material cannot become applicability. A disconnected cyclic branch must terminate without entering another partition. Observe one union hydration and absence of per-root whole-union scans for compatible relations; a late failure/cancellation retains no published window and releases only after actual borrowers finish.

<a id="uc05"></a>
### UC05 — Remaining body and frame window migrations (I06)

**Result.** Completion, Structural, Analytic and Summary use compatible bounded union discovery/hydration plus exact indexed partitions. Each existing kernel receives the same complete input and retains its own invocation, source receipts, supported universe and failure meaning. SourceCall, Enriched and Models remain examples and preservation controls, not newly invented mechanisms.

**Actual migrations.** Change Completion's statement/body adapters in `semantic_execution.rs` and `execution_scope.rs`; Structural and Analytic frame acquisition in their producers and `analytical_scopes.rs`; and Summary frame acquisition in `semantic_summaries.rs` and its scoped adapter. Migrate their input-loading operations and all affected call sites together. Preserve separate private body/root namespaces: an actual callable body includes its complete ordered direct suite and required declaration metadata, while a referenced callable cannot acquire root status. A statement window must not divide an ordered body into independently transferable statements. Structural/Analytic parents remain fixed metadata; foreign provider dependencies cannot widen the invocation domain.

Summary retains its current callee-first SCC schedule, semantic worklist/proof frontier and actual-owner adoption. This package changes acquisition grain, not recursive semantics or settled-component ownership. Coordinate with UA04 if its investigation changes which frame/component state may be released; UC05 can use the current sound Summary kernel without awaiting a speculative replacement. Preserve complete model-specific negative universes, even when a bounded rich window is sparse or empty.

Reuse compact prepared topology and reserve only useful rich bounded unions. Keep exact per-partition selected membership, qualification/support association and ordered output integration. Remove single-root rich query loops and redundant per-root position preparation after each consumer migrates. No whole-library rich retention, compatibility loader or unrelated graph-algorithm rewrite is included.

**Focused closure.** Independently specify overlapping statement, body and frame inputs and expected ordered kernel outcomes, including cyclic relations, missing premises and genuinely empty domains. Include a second callable reachable only as supporting metadata and prove its body stays excluded; include required immediate declaration metadata and prove it remains. Change namespace/context/epoch and check no leakage. Compare complete qualified outcomes, source receipts, negative domains and Summary proofs rather than row counts. Cancellation/late invalid input must preserve failure ownership, drop unfinished private work and retain backing until actual last use. A single sparse frame must remain a supported case without forcing whole-library hydration.

## 4. Decisions, migration and verification boundary

The operator explicitly approved all RC01–RC08 directions on 2026-10-17, subject to preservation and equivalence prerequisites. This companion consumes **RC03** for sufficient native inventory properties, **RC04** for shared sufficient metadata with fresh domains, and **RC07** for exact indexed remaining consumers. The coordinator UE00 owns their ADR/architecture routes before dependent implementation. Approval establishes direction; it does not establish implemented foundations or functional acceptance. A new algorithm, changed supported universe, weakened receiving trust or changed observable failure semantics is outside that approval and must be surfaced before adoption.

Internal input/property/preparation contracts change; no public CLI or wire-format change is assumed. Do not persist another canonical authority merely to share temporary metadata. If implementing the approved contracts genuinely changes a stored model/schema, schedule snapshots, coherent reader quiescence and regeneration from pinned inputs through the existing owners. Do not introduce old-format readers or preserve compatibility-only runtime copies. Existing protected Unknowns remain protected; fixture read readiness is not authority to clear them.

Verification during implementation is compile checks for touched crates plus the package's smallest independently revealing controls. Pure model/position kernels need no database; actual persistence/property/admission claims require genuine completed inputs on existing stable-service logical fixture scopes after authenticated readiness. Use `just verify --print --select ...` to resolve current family/boundary/filter commands, then `just verify --select ...` or `just fixture -- cargo nextest run --release -p <affected-crate> <focused-filter>`. Use the pinned toolchain, `INSTA_UPDATE=no`, normal available parallelism and unchanged deadlines. No readiness repair, maintenance or service regeneration is implicit.

UE90 owns cross-package focused integration and applicable hygiene; package results feed its ledger with exact command, date, source and passed/failed/blocked/not_run boundary. Keep the original full-frontier preparation journeys and assertions for later integration validation under R01. A new pure or focused persisted control cannot close the old upper timeouts or assembled finality. Structural reduction in repeated work is inspectable; numerical execution gains remain unmeasured until separately authorized representative evidence exists.

**Authoring evidence, 2026-10-17:** current source, model owners and review inspected. Production changes, builds, product tests, services and probes: **not_run** for this documentation-only creation task. Root owns publication checks, STATUS handoff and turn-end maintenance.
