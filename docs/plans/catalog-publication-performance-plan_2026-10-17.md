publication preparation. Actual code intelligence, independent receiving, coherent visibility,

## 2. Foundation assessment and combined target

Authoring inspected the actual semantic dispatch, completed-input stream, output/work ownership,
retention ordering, scoped assurance, guarded installer, reader/session and prepared-search
contracts. Focused independent design advice checked Summary semantics and native realization/
recovery alternatives against the source. The completed review remains the design basis; this
assessment is not a new formal review or broader qualification claim.

Useful foundations already exist: model-owned facts/coverage/questions, exact immutable completed
inputs, pure finite kernels, callee-first SCCs and distinct semantic/proof progress; private
selected assurance and authentic lower-owner tokens; indexed native access, actual store-executor
joins, explicit Unknown, immutable equality, pins and incarnation guards; direct ordinary
publication, protected search expectations and independent cold/portable receiving.

The selected target composes these owners rather than introducing a universal execution engine:

1. Acquire the smallest sufficient admitted metadata and actual selected payload. Prepare shared
   root membership, syntax, correspondence and vocabulary properties at their real validity lifetime.
2. Make Summary questions/coverage authoritative independently of attempted-pair trace detail.
   Keep required finite witness/refusal evidence and deterministic logical budget behavior.
3. Move canonical output backing into existing bounded writers and integrate ready canonical
   prefixes, keeping private persistence distinct from completed visibility.
4. Prepare one exact native installation packet. Prefer compact nongraph blocks with indexed
   locators and extent protection, pending PN00's complete access/lifecycle decision. Commit
   bounded pages beneath a durable operation root with exact outcomes and native progress.
5. Reuse protected deterministic definition/role/search preparation within public publication,
   freshly reconcile actual content, and publish only through the guarded final marker.

### Choices, limits and library fit

Question/coverage plus finite evidence is the preferred model target; permanent lossless pair
trace is a fallback only for a named legitimate consumer. Compact nongraph blocks with indexed
locators are preferred over preserving every physical row's current lifecycle, but exact layout
is a blocking bounded decision. Packet and operation-root recovery contracts are selected;
their implementation must prove the concrete gap left by native transactions/transport.

The [pinned capability inquiry](../design_review/evidence/2026-10-17_catalog-publication-performance/library/README.md)
qualifies SurrealDB3.3.0's patched runtime SDK, bulk writes, exact-ID set reads, locks, equality,
UDF execution and transport; DataFusion55.1.0/Arrow59.3.0 support existing columnar preparation.
Surrealkit1.0.0-beta.1 is development schema tooling, not the production transport SDK. Recheck
actual resolution before transferring a changed-version claim. No dependency move is assumed.

Use typed Rust indexes for small exact packets and existing Arrow/DataFusion for suitable
already-columnar reduction/spill. SQL NULL/duplicate behavior is not automatically native full
Value equality; array-valued FOR UPDATE is unavailable; stored UDFs do not eliminate replanning;
mutating work cannot be made concurrently independent inside one transaction by caller intent.
The existing SDK multiplexes channels; accidental session cloning calls for correct ownership,
not a pool. Keep petgraph and BDD transfer semantics instead of replacing analysis with reachability.

Prioritize removal of work, then access/preparation, then useful overlap. No worker caps, changed
deadlines, weaker assertions, generic cache, runtime cost model or compulsory benchmark stage.
Numerical speed/capacity remains unmeasured until a suitable later comparison exists.
