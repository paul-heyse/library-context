# Catalog runtime efficiency: Base preparation and Summary expansion

**Proposed, 2026-10-16.** Companion to the
[coordinator](catalog-runtime-efficiency-plan_2026-10-16.md), which alone owns disposition,
rule decisions and shared dependencies. This document develops runtime F08/F09 and preserves the
previous Base/Summary/analytics delivery and its remaining functional acceptance.

## 1. Semantic owners and suitable foundations

The model owns root/frame identity, requestedness, negative universes, proof/evaluation order,
summary states, work allowances, residuals and partial results. `cpg-core` supplies exact inputs
and adapts execution; pure model and graph kernels determine meaning. Read
[Behavioral analysis](../design/sections/behavioral-analysis.md),
[semantic projections](../design/sections/semantic-model.md#section-15-10) and
[analytics](../design/sections/analytics.md).

Retain attempt-owned captured inputs, full literal hydration for physical read roots, expression
virtual/opaque distinctions, typed union/partition views and charged singleton feasibility. Earlier
Base capture deliberately discovered/assembled roots singly to avoid uncontrolled disjoint rich
unions. RC05 now permits a better compatible union route; it does not invalidate resource admission.
Retain borrowed ordered Summary invocation inventories, lazy immutable signatures, caller-bound
ports, exact SCC schedules, indexed endpoints, delta enqueueing and Pareto representatives. No
historical timeout establishes that these algorithms are wrong.

Analytics continues to publish exact PairContribution/LayerPair/CombinedPair/evidence and FCA
concept/lattice products. Retain dual FixedBitSet FCA, PageRank isolates, community touched universe,
Leiden policy, deterministic ordering and exhausted-layer semantics. A queue problem or timing lead
does not authorize pair elision, another graph backend or changing a governed analytic result.

## 2. RA00 — Compatible Base discovery and typed support

### Required operation

Consume exact selected roots, their completed dependency views and model-defined scope program.
Use existing root-batch discovery to share compatible native frontiers/adjacency while retaining
each root's independent membership, coverage and missing-reference result. Capture unique immutable
payload once where overlap permits, then prepare a charged typed union with exact root-specific
row views. Each mutable read production still executes exactly once in deterministic root order.

This extends both singleton closure discovery in `base_scope/capture.rs` and width-one typed
reconstruction in `base_scope.rs`. Sharing only bytes while reconstructing every rich input again
does not close the finding. Share dynamic-class support across field keys where its exact negative
universe is unchanged; class/name-specific conclusions remain per-field. Full physical literals,
physical-root checks, begin/seal transitions and expression/read distinctions remain explicit.

Bound shared preparation by actual resource ownership, not a fixed new root count or parallelism
cap. A high-degree root may require the existing singleton route. Disjoint roots may benefit less
than overlapping roots; a larger union is not mandatory when its retained working set buys no
useful reuse. Prefer existing spillable capture and partition views over another materialization
or global cache. Captured source and all charges remain held through the last root consumer.

### Failure and resource behavior

Shrink or retry only local preparation/unconsumed computation that has not performed mutable
production, using the existing classified pure Resource-refusal route. A failed or Unknown native
acquisition is not permission to catch and requery it. Retain partial native ownership and original
errors. After mutable production starts, do not replay emitted/adopted roots or restart a partially
executed root under a smaller cohort. Result adoption remains failure-atomic before native emission.

Selection of a larger preparation group can expose a selected later root's acquisition failure
earlier; describe that timing explicitly. Never hydrate unrelated companions to obtain a union.
Malformed demanded payload, missing required physical roots, incomplete EOF and schema failures
remain terminal rather than resource fallback. Complete-empty membership permits its existing
namespace skips and never means unavailable input.

### Dependencies, migration and closure

Agree the common discovery interface with CX00 before overlapping source integration. RA00 can
reason against existing batch/partition contracts while CX00 changes acquisition. RN03 is a
prerequisite only where new retained premises are consumed. Apply the RC05 ADR-0176/owner route,
then migrate expression/read capture and compatible field-support consumers without adding a
parallel legacy path. Keep genuinely different field universes separate.

Controls cover overlapping and disjoint roots, reconvergence/cycles, mixed physical/virtual meaning,
literal preservation, missing demanded payload, class/name negatives, small-budget singleton-fit
fallback, cancellation before/during acquisition and after mutation, and stateful root-order
equivalence. Preserve witnesses, negative claims, independent root budgets/errors and once-only
effects. Pure known answers challenge the semantic projection; native controls establish actual
shared acquisition and finality. Existing focused capture passes remain narrower historical evidence.

## 3. RA01 — Decide Summary candidate and residual factoring

The existing queue allowance counts admitted/popped work. It does not claim to bound every
candidate scan or residual construction. Runtime F09 is an unresolved high-degree execution-fit
question, not a queue bug or established cause of a timeout.

Inspect opposite-owner proof buckets, endpoint eligibility, candidate enumeration after queue
exhaustion, residual qualification and obligation identity. Construct two minimal service-free
adversarial shapes: many candidates yielding exactly equivalent residual tuples, and candidates
whose proof/evidence/residual products are genuinely distinct. Include cycles and multiple admitted
proof representatives. Count the work relevant to this distinction in the revealing control;
do not build a permanent accounting framework or equate output size with examined work.

Compare existing enumeration with exact semantic endpoint indexes and factoring before repeated
equivalent residual construction. A legal equivalence key includes every model-owned field needed
to preserve obligations, witnesses, proof identity, source context and deterministic partial meaning.
Coalescing representatives cannot delete admitted proofs or merge genuinely distinct outcomes.

The decision must choose one of these supported routes:

- Remove demonstrated duplicate candidate/residual work through exact existing-model factorization.
- Retain necessary distinct expansion with a credible charged/streamed route and explicit partial
  behavior for the declared workload; explain why an index cannot remove the necessary output.
- Propose a deliberate model/support change if no credible existing-contract route exists. Obtain
  a separate operator rule decision before dependent delivery; leave F09 and affected acceptance
  open meanwhile. Do not silently broaden queue charging or truncate witnesses/pairs.

Record the choice, evidence and dependent implementation at the coordinator/owning contract.
No new graph engine, incremental framework or blanket pair cutoff is selected by this investigation.
If the selected route changes model/support semantics or a substantial ownership boundary, apply
the binding's bounded design/target review before RA02, alongside the required operator decision.
The present plan review cannot certify a future changed semantic contract.

## 4. RA02 — Deliver the selected Summary route

Implement RA01's selected route in the existing model-owned production/worklist boundary and migrate
its actual callers, admission/evidence and publication consumers where affected. If exact factoring
is selected, avoid materializing duplicate candidate/residual products before the equivalence test.
If necessary expansion is retained, deliver any required feasible streaming/retention correction,
or substantiate the existing route; a written retain choice does not excuse a demonstrated defect.

Preserve canonical states, proof identity/cost, finite witnesses, residual qualification, deterministic
work/partial outcomes, SCC order and exact admitted-proof inventory. Resource refusal, semantic
exhaustion and unavailable input remain different observations. No unsupported quantitative
speedup or claim that Summary caused the historical timeouts follows from this work.

Controls compare same-residual and distinct-residual cases, exhaustion before/after candidate
generation, cycles, competing proofs, cancellation and deterministic repeat results against
independent finite expectations. Verify evidence closure and partial outcomes, not just row counts.
RE90 then runs actual ordinary/recursive Summary and Base/SourceCall consumers on the final target;
those controls must reach their named assertions before establishing their integrated behavior.

## 5. Integration and completion

RA01 is independent of native protocol redesign and can start early. RA00 shares scope/capture
surfaces with CX00 and prior cohorts; coordinate editing without imposing runtime serialization.
Only meaningful contract changes require new ADRs; routine organization remains implementation
judgment. RE80 handles affected derived-state replacement, and RE90 owns inherited analysis,
finite model, analytics and actual persistence acceptance. Behavioral changes never become a
mandatory ordinary Catalog stage merely to make a combined control easier to run.
