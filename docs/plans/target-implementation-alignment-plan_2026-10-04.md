## 3. Selected shared decisions and extension scenarios

**Proposed target, supported by source inspection 2026-10-04:**

- Preserve native Bound even when no declared definition can be attached. An unmapped candidate does not become an Unbound reaching row. Native condition/source evidence must survive independently of mapped-target availability; incomplete inventory still refuses behavioral proof.
- Resolve a requested library against generation-bound first-party release/corpus captures before member filtering; same-name captures form a finite union, never an implicit latest release. Unknown input is a typed refusal, while admitted-empty results retain their actual coverage. Canonical enumeration completeness and provider coverage remain separate; member count cannot certify input admission.
- Render resources from the generation-bearing Rust response. Keep process-relative capability URIs, explicitly labelled as such, with generation metadata in the returned resource; do not introduce a second process selection authority.
- Use finite typed expansions/ordinary functions first. Preserve decoder reachability, actual read membership, exact validation requirements and sufficient grants as distinct contracts.
- Preserve differing nonempty validator-list incompatibility at the closure owner; no current consumer establishes conjunction. A new conjunction policy needs a named composition and explicit owner change, not generator union.
- Keep conservative model artifact fingerprints over source/manifests/lockfile. Replace incidental declaration/consumer `Debug` encodings with explicit domain encodings; do not promise identity across formatting, refactoring or revisions.
- Preserve the specified ordered, whitespace-free embedding-spec JSON contract unless a concrete equivalence requirement warrants migration. JCS is an alternative, not a prerequisite.
- Separate human display, original source and executable expression. Ranking/display cannot promote uncertainty or heuristics to evidence.
- Keep charged typed kernels and model-owned relational lowerings both eligible. Correct current compute claims; no blanket DataFusion ban or wholesale conversion is selected.

Extension controls explain locality: adding a publication relation changes its owner and mechanically expands adapters; adding a profile-specific input retains exact epochs; changing a physical column convention changes one lowering owner; adding a packet reuses domain admission and generation provenance. Independent controls must still catch a common declaration/lowering error.
