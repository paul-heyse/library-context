# Code facts: analytic inputs, discovery and qualified outputs

**Proposed, 2026-10-03.** The [coordinator](code-facts-expansion-plan_2026-10-03.md) owns status,
finding disposition and Q0 acceptance. This plan develops C11/C12 and the output cascade for
C1–C10. It consumes [normalized roles/identities](code-facts-normalization-plan_2026-10-03.md)
and [qualified behavioral decisions](code-facts-behavioral-analysis-plan_2026-10-03.md), not raw
analyzer internals. Enduring owners are analytics §9, catalog/selection §14/§15 and synthesis/
serving §10–§11. Algorithms/store/transport boundaries from the completed alignment remain.

## 1. Existing outputs and intended changes

Current communities/PageRank, sparse type/mention layers and bounded FCA/RCA already have
declared projections and policies. Boolean FCA incidence deduplicates membership correctly.
The parameter parent/formal mismatch removes real inputs before those algorithms; repair the
join rather than change the algorithm to compensate. Current declared ParameterType selection
uses formal identity correctly. FacetMembership currently returns unknown for every value;
unsupported forms must be honestly refused before effects, then selected supported forms gain
typed meaning. New facts must not silently change graph universes or default type policy.

Target outputs answer three distinct questions: how to invoke a decorated/generated API; which
public path/field/option is characterized; and what finite behavior follows under a stated basis.
Grouping and diagnostics aid discovery/explanation. They are not proofs of safety or runtime
success. No generative interpretation layer, new retrieval engine or live embedding campaign.

## 2. P0: repair current parameter analytics

Consume N0's model-owned source/formal/slot correspondence in
`domain::analytics::attributes`, receiver exclusion, Parameter/ParameterType/Returns attributes
and type-layer contribution. Preserve declared source policy as default, receiver policy and
the current type-layer universe: **release-defined classes**, not builtin/dependency classes.
Do not add local parent-name reconstruction to FCA/type layers or mutate type subjects.

Expected incidences include ordinary parameters with and without defaults, positional-only,
keyword-only, varargs/kwargs and correct bound-receiver exclusion. Type-layer controls use two
entities sharing a release-defined class; an `int` control alone cannot demonstrate an edge in
this universe. Assert exact memberships/weights and independent formal mapping expectations.
Repeated provider support remains multiple provenance rows, one Boolean membership and the
declared class/entity weight. Existing correct bitset dedup stays unchanged.

P0 can land with N0 before migration, immediately improving current outputs. It does not require
new analyzer facts or a real-library campaign. Closure includes an actual analytic result,
not a corrected helper that no analytic call site uses.

## 3. P1: declared richer attributes and separate projections

Normalize attribute meaning before FCA/RCA or similarity construction. Each new attribute has
an explicit entity/role universe, qualification/support, missing-evidence policy and consumer.
Adopt this finite set from the selected scope:

| Attribute/input | Governing evidence and policy | First output consumer |
|---|---|---|
| Source/effective/synthesized signature role; declared/effective parameter and return type | N1/N2 variant/slot identity and structural terms, separate attribute kinds | Role-labelled type grouping, query discovery and invocation brief |
| Resolved decorator | Contextual normalized qualified identity, no spelling equivalence | Explainable decorator groups/facets and original evidence |
| Class/record/protocol/abstract/final/enum traits and typed fields | N3 field-specific declared/computed basis; no runtime closure | Characterization facets, constructor/field discovery |
| Deprecation | N3 exact origin/message and availability | Brief warning/evidence and filterable characterization |
| Capture dependence | B2 declaring place/timing/mutability characterization | Located dependence explanation/group, not stable value claim |
| Import/public aliases and member/protocol relationships | N4/N5/B3 typed origins, candidate/exact and action phase | Declared RCA relations and structural dependency/navigation |

Represent role selection and receiver inclusion in typed analytic policy and policy digest;
declared/source remains default. Adding effective types or new projections is explicit, never
a hidden change beneath an old digest. Names/rendered labels do not merge declared and inferred
types. Grouping conditional behavior carries basis; structural attributes remain characterization
and do not inherit arbitrary runtime premises just because they came from a type provider.

Call, import, containment and type projections remain separate declared graphs. Candidate
implicit arcs retain action/phase; unresolved/possible targets are not exact runtime dependencies.
Aliases do not multiply entity votes. Communities/PageRank consume their specified graph/settings,
not an unreviewed union of everything. Preserve isolates, direction, parallel-edge policy and
normalization. RCA additions declare relation universe and bounded propagation explicitly.

FCA implication is exact only for the recorded finite incidence frame and coverage; incomplete
facts outside the frame cannot establish global absence or API safety. Support/citation retain
multiple sources without changing Boolean incidence. Concept/partition identity is deterministic
under shuffled input; community labels alone are not comparable semantic identities. Sparse
type/mention construction remains bounded; no dense all-pairs algorithm or default weight change.

## 4. P2: catalog roles and honest typed selection

P2a is an early independent repair: model/native request preparation recognizes unsupported
predicate forms and refuses them before creating a grant, lease/query effect or service execution.
Unknown is reserved for a supported question with insufficient evidence; it is not a fallback
for an unimplemented operator. Migrate wire/native/Python request validation through the existing
model admission boundary. Reserved facet codes keep their append-only identity.

P2b replaces FacetMembership's opaque String value with a typed value sum, hard-migrating wire
and persisted request definitions. Initial supported structural values are ParameterName,
role-explicit ParameterType/ReturnType patterns, resolved DecoratorQualifiedName, Async(bool),
ModulePath, MemberKind and RaisedClass characterization. Metadata/deprecation values use typed
N3 definitions. Each operator validates facet/value compatibility and its evaluation domain.
Do not parse query text or display labels to discover semantics.

Behavioral delegates/forwards/hands-off/takes-from/settings/raise queries use the existing typed
relationship/behavior predicates and proof/basis. If a corresponding FacetMembership form has
no implementation, refuse it before effects; preserving an old enum code does not require
inventing a permissive membership semantics. FCA concept membership is a separate typed query
when exposed, not a community ID masquerading as an exact facet value.

Catalog preserves source, effective, synthesized, documented and observed roles when evidence
exists. Invocation form, descriptor adjustment, overload family/candidates/chosen trace, generic
specialization, slot/return types, class/field traits, aliases and source/default uncertainty
are explicit. Missing effective typing does not substitute source undecorated invocation. A
generated constructor can have complete typed slots and Unknown runtime default stability.

Current ParameterType remains declared-source matching. Add explicit variant/type-role predicates
for effective/synthesized/specialized queries; structural matching is not runtime assignability.
Receiver/member queries consume N5 candidates versus exact identity; properties are not storage
reads. RaisedClass typing characterization and finite behavior Raises verdict are distinct.
Use model-owned normalized predicate evaluation, not a second interpretation in SQL or templates.

Controls: source/effective queries deliberately differ for a wrapper; generated slots survive
without source formals; overload candidate versus chosen is correct; unresolved/partial exports
do not erase known public paths; absent fields under incomplete metadata yield unknown. Supported
facet true/false/unknown controls and unsupported pre-effect refusal run through actual service
preparation, including malformed facet/value pairing and wrong-generation referents.

## 5. P3: original evidence, diagnostics and framework roles

Use existing source/example/test association, exact aliases/targets and native call/argument/
overload evidence to link original usage to APIs. Retain source span, variant/receiver/applicability
and unresolved association rather than attributing an example by a matching name alone. Pyrefly
higher-order parameter roles can explain forwarded arguments under existing finite binding;
they do not prove runtime callback effects.

Select Ruff F821/F401/F841 corroboration (unresolved/unused lexical context), Pyrefly call/type/
return/handler diagnostic categories and deprecation evidence relevant to those associations.
Record exact diagnostic code/category, severity, configuration, suppression/source and provider
environment. Native typing diagnostics belong with Types; Ruff lexical diagnostics use the
syntax/lexical provider surface. The capability is bounded evidence attachment, not a new
lint service or universal diagnostic relation for every upstream rule. Map actual Pyrefly enum
categories at the pin; do not infer them from formatted CLI text.

Pyrefly pytest fixture understanding characterizes injected parameter origin/role and API-example
association. Persist its native role/support where available. Fixture availability/type is not
execution, successful injection or a passed test. Preserve ordinary unresolved parameters when
no fixture answer exists; test-name heuristics cannot upgrade them. Lint-free/type-correct source
and absence of a diagnostic never certify feature success or exhaustive absence of problems.

Selected examples retain original text/provenance; synthesis does not invent runnable code from
a signature. Ty inference/IDE reports and python-oracles remain competing/cross-check surfaces
for bounded uncertain claims. They are not another production type authority or mandatory CLI
installation. Add an oracle only when it resolves a material case; no oracle-every-field gate.

Controls include aliased/rebound API names, pytest fixture versus ordinary same-name parameter,
re-exported API usage, chosen versus merely closest overload, suppressed versus emitted diagnostic
and mismatching provider context. Evidence serving resolves exact same-generation source; no
"test passed" wording follows from a source test record.

## 6. P4: synthesis and packet preservation

Extend existing typed S0 bindings and generated Rust/wire/native/Python schemas with role/basis
and normalized evidence closure. B0 and P4 agree the required basis contract early; P4's complete
journey follows richer P1–P3/B1–B4 outputs. No legacy missing-field adapter. Text generation is
mechanical from canonical records, never analyzer API interpretation or inferred certainty.

Render distinct answer meanings: declared signature, inferred effective signature, synthesized
constructor, grouped-by attribute, exact modeled behavior, or behavior conditional on stated
typing/closed-world premises. An unconditional and conditional alternative stay separately
qualified in summaries and packet bytes. Selection cannot rank away a required premise or cite
a source from a different generation. Unknown/default/partial-export/capture/async boundaries
are understandable product limitations, not internal implementation jargon.

Reuse original evidence grants, one pinned generation lease, support/prerequisite closure and
exact source-default fallback behavior from the existing serving contract. Integrate the
concurrent source-default repair by its actual scope; do not revert it or assert its independent
qualification already passed this series. Generated adapters must match current model membership
and fingerprints; refresh readiness before Q0's tests.

Catalog texts/retrieval inputs rebuild from changed canonical identities. Existing rank and
embedding specs remain explicit; ranking/similarity cannot establish truth or eligibility.
No old embeddings are silently reused after content/schema dependency changes. Live dependent
embeddings, operator generation replacement and registrations belong to the separate activation
follow-up. Fixture kNN/embeddings are off/NotRequested, consistent with the selected boundary.
