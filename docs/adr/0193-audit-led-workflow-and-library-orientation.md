## Context

The operator selected the audit-led workflow already adopted in corpus-intelligence, with
repository-agnostic library overviews and documentation research replacing active library
capability skills. This repository retains core 3.3, code-intelligence profile 1.5, the separate test-review pair, native
preparation commands, operator-selected model inheritance and independently owned workstreams.

## Options

1. Keep mixed diagnostic/solution reviews and library-skill synchronization. This avoids
   migration but repeats exploration and leaves completion claims insufficiently challenged.
2. Add mandatory audits to every implementation slice and maintain separate completion reports.
   Reject the recurring overhead and duplicated progress ownership.
3. **Separate deliberate assessments and their owners.** Persist broad diagnosis, develop
   solutions within operator-selected focus, independently challenge recommendations when
   requested, and correct claimed completion in its existing owning plan.

## Decision

The binding owns freshness, review focus and artifact routes. `design-principle-audit` refreshes
one living diagnostic collection before a new design-review engagement, without choosing fixes.
The operator selects holistic, library-targeted, principle-focused or combined solution review.
`design-review-audit` accounts for every recommendation plus omissions in a net-change companion
and integrates a newly attributed review at the original path after preserving its input in Git.
`plan-completion-audit` reconstructs accepted obligations and updates the same plan's current
completion state, distinguishing implementation, qualification and benefit evidence.
Ordinary implementation/handoff does not start these assessments. Audits authorize their
artifacts, not production repairs or changed accepted scope. Plans retain scheduled disposition.

Optional library overviews are repository-agnostic orientation, followed by Context7 and primary
sources at applicable versions. Retire selection, synchronization and local discovery links for
central library skills; retain sources and explicitly inactive historical identities. Existing
plans and reviews are not rewritten. Worker library research cannot edit central sources.
Unrelated readiness, native preparation, profile criteria and product/provider behavior remain.
The separate FastMCP gold evaluation consumer resolves existing central data directly, without
agent discovery or synchronization; missing inputs remain not_run and nothing fetches or rebuilds them.

## Consequences

Diagnosis, solution reasoning, editorial revision and execution progress have separate useful
owners without new roles, gates, registries or automatic test campaigns. Initial scaffolds make
no alignment claim; substantive audits remain separate work. This decision accepts the process;
implementation and focused verification are reported independently at handoff. Revisit if a
concrete consumer needs different artifact ownership or research access.
