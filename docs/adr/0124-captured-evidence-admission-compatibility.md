## Context

The [target review](../design_review/reviews/design_review_target-implementation-alignment_2026-10-04.md)
finds three concrete gaps: a native Bound candidate can be relabelled Unbound when attachment fails;
a requested library can be filtered without establishing input admission; and capability resources
discard the generation carried by their response. Declaration and consumer signatures also contain
incidental Debug encodings. Existing source attribution, immutable process pins and conservative
artifact compatibility remain valid. These corrections affect extraction, pure model interpretation,
PostgreSQL hydration and Rust wire presentation, with Python retaining transport effects.

## Options

1. Preserve current shortcuts and document their limitations. This leaves nominal raw evidence
   changed by target availability and permits unknown input to look like an admitted empty domain.
2. Add fallback definitions, a persistent library registry or generation-qualified resource routing.
   Each introduces another authority and migration surface without a selected consumer.
3. Carry native evidence independently of attachment, resolve captured domains in the pure model,
   render resources from their complete response and encode owned contracts explicitly. This
   retains the current producer/effect boundaries and supports isolated independent controls.

## Decision

Select option 3. Native kind, qualified condition evidence and mapping availability are independent;
Bound/unattached publishes no fabricated Unbound reaching row and does not authorize Entry proof.
A requested name resolves the finite union of admitted first-party release/corpus captures before
filtering. Unknown/unadmitted names have a dedicated semantic refusal; admitted-empty enumeration
and provider coverage remain separate, with no implicit latest release.

GetCapabilityResponse owns resource rendering. Preserve authored bytes first, append generation
and capability metadata and then attributed assertions. Capability URIs remain process-relative
to the immutable serving pin. Admit the complete resource and final SDK envelope.

Model declarations and consumer/preparation signatures use framed, versioned owner-defined
encodings. Preserve field declaration order, canonical relation/sum order and exact meanings.
Retain the raw-source/manifests/lockfile artifact fingerprint and ordered whitespace-free embedding
specification JSON. This does not promise identity across formatting or revision changes.

## Consequences

These are deliberate schema, identity and presentation migrations, with no legacy readers or dual
authorities. Rebuild affected fixture projections and invalidate derived text/vector artifacts;
real-library activation remains separately stopped. Shared library skills retain pinned capabilities
only; repository wiring belongs to existing repository owners.

Acceptance establishes the decision, not completed implementation or qualification. The
[target coordinator §7](../plans/target-implementation-alignment-plan_2026-10-04.md#7-current-disposition--sole-owner-for-transferred-review-obligations)
owns remaining production work and Q0. Native evidence, admitted-domain cases, independent identity
vectors, actual PostgreSQL/MCP provenance and same-tree full gates remain required there. The
revisit trigger requires a concrete consumer and a newly specified ownership/acceptance contract.
