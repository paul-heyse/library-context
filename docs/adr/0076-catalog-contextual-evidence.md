## Context

PR3 extends the public catalog beyond brief-seed snippets. Agents need attributable enclosing
examples and deployment information for any public API. Existing Markdown code is materialized
into synthetic Python files; its AST coordinates do not index the original document. Installed
RECORD verification previously excluded metadata. Large original contexts require explicit expansion.
The forward plan owns AP/F03 and the PR3 composition obligation of CLF/F02.

## Options

1. Enlarge the existing brief snippet builder and its packets. This conflates selected stitched
   snippets with original context, keeps non-seed APIs dependent on synthesis and hydrates too much.
2. Add an independent authored recipe store or general execution/analysis engine. This introduces
   another authority and lifecycle without a selected consumer.
3. Compose pure scenario/deployment derivations with the existing catalog, retaining verified
   original artifacts and bounded exact-ID expansion. This is selected.

## Decision

Acquisition owns integrity, membership and original bytes. Dedicated pure evidence inputs compose
with immutable catalog facts. Schema owns distinct artifact/span/scenario/deployment/association
identities and independent context, intent and check observations. Integrity is separate from
release alignment. Original Markdown fences/passages retain an explicit synthetic-analysis link;
no fabricated source map or rewritten recipe is published. Expected failure is site-scoped.

Metadata parsing uses pep508_rs with Requirement<url::Url>, raw mailparse headers and case-sensitive
rust-ini. Original bytes and diagnostics survive failed interpretations. Markers are evaluated only
against explicit environment inputs; no parser expands the operator environment or resolves packages.
Declared requirements, installed environment and observed task sufficiency remain separate.

Delta remains canonical. API/scenario/deployment roots seed closure independently of assertions.
Release-wide package metadata has one release subject, not a copy per API. Serving includes those
explicit release associations alongside member-specific references; it does not relabel package
requirements as operation requirements. The first live compile exposed the duplicate expansion
(504,595 associations), so the normalized subject is part of this decision.
PG contains rebuildable typed projections and original body bytes with generation-scoped access.
Rust owns evidence wire types, selection and budgets. get_operation pages evidence references and
admits at most two demonstrations; get_evidence expands a typed exact-ID reference, with bounded
original-byte pages. Oversized metadata is explicitly omitted while preserving access to its
primary original span; the canonical typed record remains intact. Transport pagination never changes extraction completeness. General search,
comparison and retrieval/classification changes remain PR4–PR5.

Execution is an explicit operator-invoked task check, never compile or query behavior. Receipts
record source, runner, command, environment, inputs, outcomes and limits, and are checked as explicit
inputs before publication. A successful observed configuration does not prove minimal installation.

## Consequences

Original-byte fidelity, isolated derivation tests and bounded serving improve local reasoning.
Acquisition, codecs, closure and recovery require a versioned migration. Existing brief behavior
and additive semantic tools are retained. No incremental engine or generic shell evaluator is added.
Acceptance chooses the architecture; implementation and qualification remain tracked in the
[forward plan](../plans/behavioral-model-forward-plan_2026-09-24.md#30-consolidated-execution).
