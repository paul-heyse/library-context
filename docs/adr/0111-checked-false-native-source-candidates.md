## Context

The Phase 4 finite Summary and S0 contracts admit a checked, exact false alternative only with
an actual source proof and complete native Flow coverage. The recursive acceptance fixture
instead yielded Conditional proofs and explicit ConditionTransferUnsupported residuals: distinct
evaluation atoms cannot be equated to manufacture a contradiction. The provider's pruning also
removed actual direct-name value candidates and their native reaching evidence when the existing
runtime view decided their selection false. This left no explicit finite question for refutation.

The owners are `cpg-flow` for native mapping, `cpg-extract::ty_flow` for attributed attachment,
model Entry/Local for unchanged-formal admission, and Summary/S0 for their qualified consequences.
This supplements ADR-0045's runtime view and evaluation identity; it changes neither.

## Options

1. **Keep all false candidates pruned.** Simple, but cannot supply the explicit checked-false
   source question required by the existing finite negative contract. Silence remains Unknown.
2. **Retain every inactive reaching row alongside live candidates.** Rejected: Entry's exact-one
   inventory would acquire inactive competitors and invalidate otherwise sound positive proofs.
3. **Retain only a preferred false Defined formal.** Rejected: dropping another Defined or
   Unbound alternative would fabricate uniqueness and an origin witness.
4. **Derive a false transfer from a complete-no-read assessment.** Rejected for this scope:
   no-read and a qualified finite transfer are different questions; this would require a new
   origin/sink universe and negative proof contract.
5. **Retain a complete, bounded native checked-false candidate inventory.** Chosen: existing
   attributed observations, conditions, Entry proofs and finite consequence validators compose.

## Decision

- Retain a direct bare-name identity value source under its original checked-false expression
  condition only when it has an actual native use. Computed values and call crossings retain
  the previous refusal boundary; no source use or formal origin is reconstructed from spelling.
- Lower the entire native binding set once. A false-only inventory is admitted only when it is
  nonempty, every condition is exact false, and no candidate is a loop header. Preserve every
  actual Defined/Undefined/Deleted state through the existing mapper, including Unbound.
- Any live or approximate candidate keeps the prior reaching-pruning policy. Empty sets and
  loop-header expansions remain outside the false-only lane. Missing, multiple, unbound or
  unsupported formal origins remain unresolved under the shared Entry validator.
- Retained candidates are not discarded skip counts. Provider mapping source participates in
  build identity. Original evaluation identity, attribution, fidelity and coverage are preserved.
- A Refutation states impossibility of the exact qualified finite alternative. It is not proof
  that a parameter never reaches any return. Complete same-input/context/scope Flow membership,
  exact false qualification and nonheuristic structural proof remain mandatory through S0.

## Consequences

No new semantic relation, compatibility path, solver, store or serving interpreter is introduced.
The native inventory is slightly larger; unsupported alternatives still refuse rather than
becoming negatives. Positive Entry inventories retain their prior active candidates. Extending
this policy to loops, computed values or a complete transfer-absence question requires a new
contract decision and independent controls.

Independent focused design advice accepted the bounded policy statically. The actual native
suite passed 33 controls; native/PostgreSQL publication passed the Summary proof, kind18 finding,
Limits assertion and selected brief, with missing-proof, erased-membership and Partial-coverage
refusals (2026-10-01). The initial recursive and source-pruning failures remain in the
[qualification receipt](../design_review/evidence/2026-10-01_phase4-qualification/README.md).
These are composite focused results, not Phase 4 exit. Its remaining acceptance is owned by
[the detailed plan §13.3](../plans/semantic-model-phase4-detailed-plan_2026-09-30.md#133-restart-checkpoint-and-remaining-work).
