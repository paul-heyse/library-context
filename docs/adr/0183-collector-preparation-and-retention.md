## Context

The Python collection review's P:I01–I05 identifies preparation, construction and retention
choices after the indexed/admitted collection foundation. Modules combine source syntax, two
suppression-sensitive diagnostic computations, native definitions/calls/types, selected external
definitions and runtime flow. Their useful lifetimes differ. Identical final IDs neither establish
safe native reuse nor justify retaining every intermediate until the last stage.

The [collection coordinator §6](../plans/catalog-collection-efficiency-plan_2026-10-17.md#6-sole-disposition-and-current-checkpoint)
owns implementation, subdecision disposition and actual evidence. ADR-0182's admitted complete
synchronous groups, typed operational errors and existing cancellation owner remain in force.

## Options

1. Retain all current preparation and buffers. This avoids new interfaces, but repeats immutable
   Ruff token work, copies emitted-only syntax, formats the same opaque type twice and retains
   flow-owned originals and import-spelling scratch after their consumers finish.
2. Fuse or cache rich work indiscriminately. A single diagnostic run cannot reproduce both Noqa
   channels; observer stopping currently determines contextual statistics and completion. Recursive
   type construction has encounter/first-registration/native-resolution effects. Solver callbacks
   can precede AST eviction and final analysis epochs. Speculative top-level flow queries violate
   callback-before-next-query stopping. These are not interchangeable pure computations.
3. Share stable preparation, select expensive payload before expansion and end physical ownership
   at the actual last consumer. Retain the native mechanisms whose richer context/finality is still
   needed. This removes demonstrated work with small native seams and existing attempt ownership,
   without a scheduler, global cache, persisted token relation or shadow traversal.

## Decision

Use option3. Ruff's source-derived Locator/Stylist/Indexer are shared by the existing separate
empty-rule contextual observer and both actual diagnostic computations. Canonical syntax-only
consumers do not construct this preparation. One admitted prepared view spans diagnostics and
contextual collection and ends immediately afterward. Observer validation, refusal/statistics,
requested diagnostic completion and operational cancellation retain their existing meanings.

Move declarations, parameters, formal links and calls into one charged retained syntax inventory.
Calls and types borrow the same call backing; emitted-only syntax ends with its writer. Preserve
support/emission order rather than moving typed output ahead of its canonical premises. Use one
exhaustive latest-family Ruff-kind mapping in the existing cpg-flow dependency direction; role
selection and Pyrefly's nominally distinct embedded Ruff remain independent.

Reuse a current Other/Truncated term's exact display for its presentation. Retain encounter-driven
recursive/structural construction and cross-encounter formatting: their complete context, depth,
remaining-work and first-registration effects are not captured by final-row identity. No depth32,
cumulative100000, native generic/candidate or fidelity contract changes.

Select untapped dependency function payloads from the complete borrowed native base inventory and
class definitions before signatures/decorators/capture payload copies are constructed. Retain exact
qualified-name and enclosing selection, complete classes/globals/MRO and full base capture eligibility,
including already referenced symbols outside selected heavy payloads. Root extraction and diagnostic
PysaTap still request full reports. Native definitions-only dependencies do not acquire call graphs.
Rich native extraction remains post-wave at Everything where AST/answers/traces are actually needed.
A pre-eviction callback without final-epoch ownership does not replace that route. Progressive waves
retain actual discovered closure rather than eagerly promoting all imported dependencies.

Keep one complete declared-input read domain for flow; foreign bindings, targets and owners remain
available. Partition reference rows directly into ordered source buckets. End source import/name
preparation after building compact cross-source classifications. Compact classifications remain until
runtime maps finish; avoiding that small lifetime does not warrant another preparation/cache protocol.

Transfer flow-owned original text/runtime backing with per-source StateCharge into an owning runner.
Reserve before source reads, copies, runtime insertions and input-container growth. Read exactly the
captured geometry and reject length/hash drift without an unbounded buffer. Prepare the full
transformed virtual universe before queries, then consume inputs in callback order. Each original
copy ends after its synchronous module callbacks. Captured-source authority, native VFS contents,
Program/settings and required lazy dependency queries retain their independent owners. This is not
an RSS or complete opaque-heap guarantee.

Retain parser-mediated original-token renaming: canonical tokens currently end in an earlier
provider phase. Extending canonical AST lifetime or adding a cross-provider token protocol merely
to avoid a transient parse adds a larger lifetime. Source-kind/version option differences alone
are not proof of token inequality. Retain native AST caching when late wildcard/import queries
would reconstruct a cleared parse. Retain serial top-level collection because a callback refusal
must prevent later top-level queries; ordered output buffering does not repair speculative work.

## Consequences

New fact consumers borrow narrow prepared inputs and retain independent admission. Native forks
add small observational/preselection seams at their existing pinned versions, with aggregate patch,
immutable revision and provider identity updated together. Neither a native fork change nor matching
content earns semantic admission. Replaced duplicate copies/debug-kind scans are removed; no old
format readers, optional production fallback, schema/codebook change or source interpretation is added.

Expected efficiency follows removed preparation, formatting, unselected payload construction and
unnecessary overlapping ownership. Quantitative latency, capacity and RSS remain unmeasured. The
coordinator distinguishes focused native-analyzer controls from persistence integration and deferred
whole Catalog qualification; prior unresolved native finality remains separately protected.
