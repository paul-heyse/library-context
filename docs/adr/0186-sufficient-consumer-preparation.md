## Context

The [upper execution coordinator](../plans/catalog-upper-execution-plan_2026-10-17.md#6-sole-disposition-and-current-checkpoint) owns UC01–UC05, F05–F09 and I03/I06. The operator approved RC03/RC04/RC07 and implementation with focused functional validation on 2026-10-17. Current uniform owners repeat common metadata acquisition, C0 reads discarded rich payloads, native inventory reconstructs already-admitted assertions/supports, and remaining retrieval/body/frame adapters repeat scalar acquisition or full-union filtering.

Existing model declarations, private checked semantic inputs, exact immutable completed bindings, protected native acquisition and owning indexed Arrow windows supply the needed foundations. Native inventory already executes after normalized semantic admission. That authority, rather than nominal completed metadata, establishes canonical row/custom validation, identity and support integrity. Independent receiving still earns these checks itself.

## Options

1. Retain broad rich input lists, per-owner reconstruction and scalar/masked windows. This keeps existing local adapters but amplifies physical acquisition and decoding for the supported overlapping-root and multi-owner workloads.
2. Share global rich caches, persisted proof flags or raw graph-closure keys. This adds invalidation/retention machinery or loses owner, schema and actual filtered-membership distinctions.
3. Carry sufficient immutable preparation under exact existing owners and gather model-selected windows through charged indexes. Selected. This adds narrow typed production-demand/property interfaces while removing repeated work without another canonical store, executor or semantic authority.

## Decision

`lctx-model` declares production metadata demand separately from independent receiving and semantic dependency declarations. C0 metadata consumes complete expected-domain properties and authored definition/parameter/provider metadata; selected C0 windows own rich premises. Shared uniform preparation retains compact common inputs and compatible authored fragments. Each invocation constructs fresh owner domains, ordered source records, declarations and total outcomes. SourceArtifact metadata uses the existing classifier property operation; uniform equal-copy coalescing does not change strict admission duplicate checks.

`cpg-core` owns an operation-local preparation registry. Compatibility follows model/program/profile, actual operation/resource ownership, typed ports, selected source identity and requested/resolved epochs; ordered invocation sources remain fresh. Entries retain exact input protection, immutable backing and charges. Only complete successful preparation is reusable, and retention ends with actual final demand/borrowers. There is no global cache or result/admission reuse.

Native inventory projects qualification identity/assumptions, assertion identity/qualification, and support identity/assertion/fidelity only after projecting the actual private checked semantic authority onto its complete model-declared dependency closure and matching exact current inputs. Missing or mismatched authority refuses before compact reads. Model-owned inventory logic still checks presence, qualification basis, alternatives, conflicts and output mapping before output starts. Full semantic dependency declarations and rich independent receiving validation remain unchanged; stored IDs alone grant no property.

`lctx-compiler-store` extends its owning indexed window with explicitly declared full/property schemas and model-selected partition memberships. Membership binds to exact window/port/backing rather than requiring raw closure membership: retrieval artifact selection can intentionally include artifacts outside that closure. Positions are prepared once, preserving duplicate requests/physical rows, source order and exact prefixes/epochs. Ordinary full-schema callers retain their checks.

Retrieval batches root/subject headers and compatible partition-tagged membership acquisition, hydrates each selected rich port once and gathers actual filtered positions. Completion uses separate statement and whole-body windows; Structural, Analytic and Summary use bounded frame windows. Typed visitors, complete negative universes, invocation domains, source receipts and semantic output integration remain. Summary keeps its existing SCC schedule, worklist, proofs and actual-owner adoption. The existing 32-root window policy and cardinality-one operation remain; general worker overlap and Summary component release belong to US02/UA04.

## Consequences

Physical work follows useful metadata and selected rich demand. Shared immutable representations and carried checked properties remove repeated acquisition/validation while preserving trust boundaries, model ownership and exact output meaning. Resource admission includes preparation, indexes, temporary gathers and retained backing through actual cleanup. No new dependency, persisted schema, wire contract, worker cap, deadline increase or compatibility reader is selected.

The expected work reduction is source-grounded; latency and memory benefits are unmeasured. Acceptance records the decision, not implementation or verification closure. The coordinator owns actual delivery and evidence; historical native Unknowns and unobserved cleanup remain protected. Full Catalog and assembled qualification are separately pending.
