## Context

The reconciled efficiency campaign's actual analysis integration timed out with confirmed command
cleanup and32 started native owner receipts. The dedicated service runs the reviewed registered-query
drain server, but its installed warning filter omits the informational post-join message. Current
fixture recovery correctly refuses to treat process disappearance as native completion, and ordinary
maintenance correctly refuses an unresolved borrower. The bounded synthetic PD02 recovery route
requires exact wire manifests and positive shutdown logging; ordinary compiler tests have neither.
The shared service, other sessions and operator state are outside this decision. The first actual
single-attachment recovery refused before effects because the new observation policy also protected
an earlier, historically released source-producer command. This replacement makes the finite joint
scope explicit; it does not infer that the earlier command ran no queries from its Cargo-lock log.

[Coordinator §4](../plans/efficiency-alignment-plan_2026-10-11.md#4-package-sequence-and-sole-execution-checkpoint)
owns actual evidence and S09/D10 closure. This accepts an explicit campaign recovery contract;
implementation and actual recovery qualification remain incomplete.

## Options

1. Preserve the attachment indefinitely and use a separate installation for subsequent work.
   This keeps ambiguity protected but leaves an unresolved execution lifetime and duplicates
   service state without repairing its actual owner.
2. Release after command exit, daemon disappearance, a healthy follow-up query, or an empty LIVE
   inventory. None establishes the original accepted queries' joined execution, so these fail
   the recovery contract.
3. Bind an exact deliberate shutdown to the reviewed binary's successful-return control flow,
   then independently reconcile persisted native ownership under exclusive installation authority.
   This uses existing execution and maintenance owners. It requires a narrow versioned source
   premise and durable original evidence, but no new query scheduler or general recovery framework.

FP-07/A4 and H13/H18 favor composing the real owners' finality while preserving distinct execution,
request outcome and content-retention meanings. Quantitative performance claims are not made.

## Decision

The service owner may explicitly recover a finite named set of attachments on one dedicated
campaign installation. At least one primary attachment has declared started native compiler-store/
workspace owners with exact generation/process correspondence. Additional eligible peers are either
the same class or historically released, uninstrumented attachments: released=true, exact dead
command/owner, confirmed cleanup with no survivors, no native binding and no native receipt files.
The latter class retains its original not_observed status; neither a historical release nor absent
log output establishes native completion. A live, unknown, changed or unlisted peer refuses recovery.

The owner acquires exclusive admission, every named dead attachment owner's lock and the borrower
lock, confirms every command cleanup, and refuses every other live or unresolved borrower. One
immutable recovery plan snapshots every original attachment/native receipt and descriptor byte
stream. Each peer consumes the same authenticated host receipt; no implicit all-borrower sweep is
permitted. Historical local release remains a local fact, never retrospective transport qualification.

For an already-serving invocation of the exact reviewed patched server, a source-correlated join
proof binds installed binary/provenance, actual executable and argv, unit, InvocationID, PID and
process start identity. Deliberate SIGTERM targets that same main process without a stop job,
abort timeout or forced kill. Clean exited/0 is eligible only because the pinned server's normal
successful return awaits the query/session shutdown owner and propagates its failure through the
CLI exit status. The full exact-invocation journal rejects cleanup warnings/errors that the upstream
session/LIVE helpers log without propagating. This proof never claims an informational message was
observed. Changed or unavailable source/executable/identity/journal premises refuse recovery.

Restart uses the same checked generation with admission closed. The existing immutable installer
performs installation-wide native reconciliation: exact persisted effect requests retain their
committed dispositions; open attempts are fenced and their existing terminal cleanup runs. Live
pins or backup holds refuse completion. No guessed reader reconciliation, era cut, history collection
or inferred content deletion is added. Existing cleanup can release unadmitted product/attempt holds;
it does not authorize unrelated storage collection.

A separate immutable host receipt records joined execution and installation-wide persisted-owner
recovery. Original per-request outcomes remain unknown where their identities were not retained;
missing intent records do not mean uncommitted effects. For an uninstrumented historical peer, the
current invocation's registered-query join is not proof of its earlier RPC finality. Its host receipt
separately records installation-wide persisted-owner recovery and retains the earlier transport
outcome/finality as unqualified. This recovery releases the named local attachment obligation after
real persisted-state reconciliation; it does not close the transport finding or turn its test into a pass. Fixture borrowers and storage retention
consume the authenticated host receipt alongside the unchanged original Unknown, then release only
the explicitly named attachments' local obligations. Interrupted recovery remains journaled and resumes the same
original scope before admission reopens.

The synthetic PD02 route retains its stronger exact table/session/effect manifests and positive
post-join log prerequisite. Neither route changes shared service policy or original test outcomes.

## Consequences

The campaign can recover an actual lost execution owner without inventing a successful test or a
request-specific outcome. The source premise must be reassessed whenever the server patch, shutdown
control flow or CLI exit mapping changes. Isolated host controls and actual campaign recovery are
required before claiming Tested. Actual native transport, migration and integrated acceptance remain
separate obligations in the coordinator; this decision closes no finding.
