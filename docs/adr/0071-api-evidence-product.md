## Context

The operator now defines value as an agent discovering, configuring, implementing and deploying
library features with specificity and customizable selection that improves actual outcomes over
Context7. The existing infrastructure and behavioral analyses are substantial, but general Python
semantic completion is not the shortest path to that product. The supplied pathway and R01–R08
reviews identify missing API contracts, options, examples and connected evidence.

Source inspection at `739f9df` also finds mandatory public/catalog construction coupled to optional
analysis, duplicated invocation classification, assertion-rooted evidence export, missing field
expressions/package requirements and retrieval without winning-unit identity. Context7's current
public API already supplies versioned documentation, source links and dynamic source snippets.
Adding snippets alone does not establish differentiation.

[§14](../design/sections/api-and-evidence-product.md) is the detailed replacement target. Its
[review](../design_review/reviews/design_review_api-evidence-product_2026-09-28.md) distinguishes
source observations, interface checks and proposed outcomes. No head-to-head evaluation has run.

## Options

1. **Finish all Stage 3–5 semantics before product delivery.** Retains the old trajectory but ties
   useful signatures/examples to work not needed for those answers. Deferred as research, while
   any false claim still exposed by the product must be fixed or withheld.
2. **Documentation/source search with nicer formatting only.** Simplest useful baseline and a
   required comparison condition. It lacks explicit public-member, requirement, configuration and
   joint-applicability contracts and may not improve on Context7.
3. **Mandatory API/evidence catalog with selected bounded analysis (chosen).** Reuse facts,
   canonical publication and PG serving; add the missing contracts, associations and witnesses.
   Scope new inference to surface transformations and field/direct relationships required by tasks.
4. **New analyzer, graph store, solver, generative recipe service or retrieval engine.** No present
   task evidence justifies the additional owner, lifecycle or compatibility burden.

## Decision

The first product is a **version-pinned API and evidence catalog for feature discovery and correct
use**, with behavioral conclusions as optional, strictly admitted enrichment. Public members,
source declarations, signatures, configuration options, original scenarios, deployment material,
evidence associations and retrieval units have explicit contracts. Uncertainty is local to the
field/claim. A source signature can remain useful while an exported wrapper's signature is unresolved.

Public-root/catalog construction is mandatory independently of optional analyses and briefs. A
valid no-brief/no-semantic-capability generation is distinct from corrupt advertised output. Existing
validators remain strict; arbitrary compiler exceptions never become successful partial publication.
The catalog reuses Arrow/Delta authority, DataFusion derivation and existing PostgreSQL publication,
role, pinning, recovery and physical-index admission. No second editable catalog or semantic interpreter.

One Rust selection contract defines strict versus discovery, per-requirement support/conflict/open
states and separate joint applicability. Original evidence can explain a match without proving a
behavior. Bounded implementation packets and browsing expose the contracts through the existing MCP
boundary; independent evidence search also returns conceptual/deployment pages without guessed APIs.

Retain Qwen3/1024, exact vectors and BM25. New families preserve winning evidence-unit identity and
normalize contributions per family. Changes use versioned projections/specs/policies, new migrations
and current publication; no deployed migration checksum changes and no automatic ANN activation.

The forward plan's active queue becomes product PR0–PR6. Prior Stage 3–5 sequences remain an
explicitly deferred research backlog, with stable findings and unchanged unmet tests. Broad summary,
heap/decorator/lifecycle completion, ontology expansion and engine comparisons cease to be first-
release gates. A selected task failure can reactivate the smallest bounded missing capability.

Product evaluation adds paired agent **task execution**, independently checked by task tests and
source-backed review, against Context7 and an internal unstructured evidence baseline. This replaces
ADR-0021's blanket no-API-agent evaluation restriction for the new product suite only. Agents do not
judge their own answers as the sole oracle. Existing semantic evaluation remains separate and its
operator-reviewed truth rubric is unchanged. A usable pilot and demonstrated differentiation are
separate milestones; parity does not meet the operator's stated objective.

## Preserved decisions and explicit replacements

From ADR-0021, retain the public-root universe, all-public catalog reach beyond brief seeds, exact
attribution and local unknowns, programmatic synthesis without a generative model in pipeline or
query path, immutable generations, one pinned generation per server process, evaluation-only gold,
FastMCP 4.0.5 pilot and pinned acquisition. Existing enabled analyses keep their stated per-callable
scope; optional pass selection does not silently narrow an advertised completeness claim.

Retain the original non-goals: analyzing callers' repositories, cross-version comparisons, arbitrary
composition planning, general requirement solving, unbounded query traversal, native body analysis,
general ontology/RDF and general points-to analysis. Typed declaration/domain predicates and bounded
original deployment evidence do not assert those excluded capabilities. Selected opt-in runtime
surface observations are a separate effectful observation lane, never a request-time analysis.

ADR-0040 owns current review cadence. The old increment numbering and Stage 3–5 completion deadline
no longer determine release. Replace scheduled deletion at increment 5 with an explicit consumer-
triggered retention decision: no new analytics default without a named product consumer, independent
benefit and no incorrect/misleading claim or displacement regression. Existing defaults and frozen
parameters do not change in this design revision.

**Freeze ownership transfers intact.** This ADR owns all freezes inherited by ADR-0021 from ADR-0004:
analytics config, community/PageRank/FCA/kNN parameters, selection parameters and variant policies.
The ADR-0058 typed-RCA implementation-record correction and prior exposure disclosures remain in
`eval/gold/analytics-freeze.json`. Only the owning ADR/transfer note changes now; no digest, target,
threshold, behavior item, heldout data or score changes. Future parameter edits need a new decision
with disclosure of evaluation exposure, following ADR-0042's immutable-record rule.

Exposure for this design: supplied external reviews, existing design/plan diagnostics and freeze
metadata were read; no new gold scoring or sealed-heldout inspection was performed. Prior exposure
recorded in the freeze remains attributed to its original sessions. The new product confirmation
set must be separately curated and sealed before tuning; it does not repurpose old gold as unseen data.

## Consequences

The next implementation can deliver useful contracts and evidence without pretending deeper behavior
is complete. Additional work is real: public-member normalization, capability-aware publication,
original evidence closure, package metadata, typed selection and retrieval witness migration.
The accepted direction is not an implementation or superiority claim. §14's response budgets and
comparative thresholds are proposed protocol choices to freeze before execution; no outcomes have
been manufactured. The forward plan owns PR0–PR6 and finding status; runtime and deployed PG state
are unchanged by this documentation decision.
