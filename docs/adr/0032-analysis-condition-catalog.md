## Context

The flow provider persists `conditions` and `condition_nodes`, but Stage 2/3's
flow analysis conjoins reaching and sink conditions after reading those rows.
Its recomposed condition id can be absent from the provider table. The new
predecessor and direct-model candidate relations cite those recompositions;
L3 cannot check compatibility or serve a proof by parsing their bounded DNF
display. This is the condition-authority gap in DESIGN §3.9 and §9.9 (DP-08,
CI-04, CI-06).

## Options

1. **Keep the diagrams compile-local.** Simplest and sufficient for the current
   source pass, but a published summary cannot reconstruct the condition.
2. **Reparse display DNF or append recompositions to provider `conditions`.**
   Reparse loses capped structure; extending the provider table with analysis
   rows conflates fact provenance and analysis authority.
3. **Persist a separate analysis condition catalog.** Chosen. Reuse the exact
   structural node format and shared hydration validator, with condition IDs
   and nodes deduplicated in two analysis tables. Provider and recomposed roots
   stay distinct, and references name the correct catalog.

## Decision

`analysis_conditions` holds each recomposed condition id and structural root
or a named kernel boundary; `analysis_condition_nodes` holds the reachable
content-addressed node closure. The compiler writes both from the existing
`BoundedCondition` objects, not from display text. Publication reconstructs
all rows from the same raw inputs and calls `hydrate_catalog`, the same
structural validator used for provider conditions and native loading. The
catalog may contain terminal roots without node rows. Approximation remains
row-local on source/path facts because it is not part of Boolean identity.
Missing or over-budget diagrams remain unknown, not false. L3 reads this
catalog before composing any derived condition.

## Consequences

The direct transfer and predecessor candidates can now cite reconstructible
conditions. This adds two analysis tables, a schema migration, a catalog-size
budget and publication work. A measured Stage 3 pilot must check row/node
counts, hydration cost and any limit hit before serving. A condition created by
a later summary pass needs a separately validated extension rather than an
unproved reference to this flow-analysis catalog.
